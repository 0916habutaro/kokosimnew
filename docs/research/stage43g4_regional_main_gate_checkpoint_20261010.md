# Stage 43G-4：春季関東地区大会17校の開始ゲート・本戦保存／再開

作成日：2026-10-10  
前提：Stage43G-3 PR #144 main反映済み。  
**重要：今回、8都県すべての2027県大会を実ゲーム進行させたわけではありません。** 2027年の関東地区大会を安全に開始する「条件を満たした場合のみ起動するアダプタ」と「保存・再開機構」を先行実装した工程です。

## 1. 対象と進出ルール

2026年度の実資料に基づくゲーム用大会方式マスター`regional_feeder_rules.csv`には、春季関東地区大会 `CMP000006` の次の8県17出場枠があります。

| 県大会 | 春季関東への代表 | 今のゲーム内2027テスト実行 |
|---|---:|---|
| 茨城 CMP000084 | 2 | Stage43G-3で完了・試合履歴で照合可能 |
| 栃木 CMP000086 | 2 | まだこの年度sandboxに未登録 |
| 群馬 CMP000088 | 2 | まだこの年度sandboxに未登録 |
| 埼玉 CMP000090 | 2 | Stage43G-3で完了・試合履歴で照合可能 |
| 千葉 CMP000092 | 3 | 年度sandbox未登録、3位境界の独立検証が必要 |
| 東京 CMP000094 | 2 | 年度sandbox未登録 |
| 神奈川 CMP000095 | 2 | 年度sandbox未登録 |
| 山梨 CMP000105 | 2 | 年度sandbox未登録 |
| **合計** | **17** | **4校が実試合から資格検証可能、13校は保留** |

`region=REG03`の2026方式を**2027年ゲーム内仮ルールとして利用する**のであり、2027年の実際の参加校や開催日を公認したものではありません。

## 2. 千葉の3位決定権を別証拠で扱う

`phase2_engine/same_year_regional_feeder_gate.py`の`project_same_year_regional_feeders`に、任意の`placement_decider_match_ids`を追加した。

- 指定がなければ千葉の上位3校枠は従来どおり`ranking_cutoff_requires_tiebreak_rule`。準決勝敗退2校の見かけ上の配列順で3位を割り当てない。
- `CMP000092`に限り、**実際にゲーム内で実施して保存済みの順位決定試合のID**を明示して解決できる。
- この記録には、同年の歴史SQLiteに残る`PLACEMENT/THIRD_PLACE`の実試合であり、`score_source=ability_model_v1`であること、対戦校が本戦準決勝の敗退2校と一致すること、決定戦が県大会最終試合後・関東地区大会開始前であること、SHA-256指紋・勝敗が変更されていないことを要求する。
- 条件が揃わなければ3位枠を勝手に埋めない。**2027年に実際の3位決定戦が開催されると断定したものではない**。今後、当該枠の別選考方式が判明した場合は方式そのものを専用契約に追加する。
- 2027年の3位決定戦を生成する正式なスケジューラは今回未実装。外部から適当な順位文字列を指定して解決する機能ではない。

## 3. 本戦開始・保存／再開機構

新モジュール `phase2_engine/career_regional_main_checkpoint.py`

`CareerRegionalMainCheckpointService(multi_service)`：

- `start(slot_id,year,placement_decider_match_ids=...)`：
  - 既存Stage43G-2`CareerMultiPreviewCheckpointService.load`から同一年度の大会・セーブ・選手をロード。
  - 当年登録済みのすべての県大会が完了し、Stage43G-3の`project_same_year_regional_feeders`が8件の全ルールと17校を実試合と履歴SQLiteから認証している場合のみ、地区大会を作成。
  - 学校IDはその認証結果からのみ取得。参加校リストの任意差し替えを受け付けない。
  - Stage43Fの`build_future_season_blueprint`の2027仮日程と`prepare_future_direct_main_preview`を使用。学校ごとに進級済みの`CareerRosterArchive`があることを要求し、既存能力シミュレータとMAINトーナメントを使用。
  - 前大会順位を第1シードなどの抽選上の権利に自動変換しない。
- `play_next_date(session)`：春季関東17校による本戦を仮日程で1日進め、同じ2027年度`historical_matches.sqlite3`へ試合ごとの打者・投手・得点履歴を記録。
- `save(session)`：上流複数大会のJSONチェックサム・同年度plan identity・進出証明・本戦初期組み合わせ、処理日・全試合fingerprintをチェックサム付きファイルへ原子的に保存。過去の2026セーブ・歴史台帳を触らない。
- `load(slot_id,year)`：上流セーブ・出場資格17校・全ロスターを再検証し、保存した日付まで同じ試合を再実行して途中状態を復元。結果が食い違えば拒否、JSON先行保存でSQLiteが欠けた場合だけ正常な試合を追記する。

保存場所：

```text
<save_root>/<slot_id>/
  manual.json / autosave.json            ← 既存2026本編セーブ不変
  historical_matches.sqlite3            ← 2026 sealed、2027 active
  career_rosters.sqlite3               ← 選手ID永続
  career_multi_previews/2027.json        ← 県大会の年次セーブ
  career_regional_previews/2027_CMP000006.json
                                       ← 今回の地区大会チェックポイント
```

地区大会から保存される試合は`HistoricalMatchArchive.sync`の**同年度・同plan identity**であり、Stage43G-2の年度セーブと混在可能。地区大会のみで2027年度を`sealed`にしない。

## 4. 追加テストと検証範囲の区別

`tests/test_stage43g2_multi_competition_checkpoint.py`にStage43G-4専用5テストを追加した。

1. 2027県大会がまだ終わっていない場合、地区大会を開始せずJSONも作らない。
2. 茨城・埼玉の2大会が完了しても**4/17校だけ**なら17校本戦を開始しない。
3. **地区大会側のみの独立単体テスト**では、検証済みゲートの返却値を模した試験専用17校を注入し、実際の関東17校MAINトーナメントの仮日程試合を能力シミュレータで実行。同じSQLiteへの保存・ロード・再開・旧年度sealed保持を検証。
4. 同じ試験専用17校による地区大会セーブのSHA-256改変を検出・拒否。
5. 千葉以外の大会IDを順位決定証拠として指定する誤入力を拒否。

**第3・4テストは「8県の全試合から自動で17校が認定できた」ことを示すE2Eテストではない。** あくまで地区大会エンジンと永続化の動作を、条件が揃った状況を模した入力で独立検証した。実データ側の安全な起動ブロックは第1・2・5テストで検証する。

## 5. 次の工程

- **Stage43G-5**：2027県大会の残る6都県の年度sandbox入力、前年秋免除・直接MAIN・予選方式の差を個別に扱う。全県の完了結果を共通年次セーブへ確定保存。
- **千葉の3位確定方式**：実際の春季関東進出校の選定方式を整理し、ゲーム用の順位決定方式（試合か選考か）を年度ルールとして明文化。必要な場合は順位決定試合を大会スケジューラで生成・実行・保存し、本契約の履歴IDへ接続。
- **全8県17校の正式E2Eテスト**：試合・順位・出場資格・関東本戦17校・日付・校別の試合成績・年度セーブ／再開まで一続きに検証。
- 2027年の大会開催日・出場資格はゲーム内仮定。公式2027データとして表示しない。
- 長期の本編正式年度切替、全国162大会の自動進行、選抜大会の選考、東京秋2026マスター未登録、広島の未確認予選は依然として保留。

**到達点：関東地区大会の参加校全17校が検証されるまで安全にブロックし、揃った場合の本戦実行・セーブ・再開を実装。全17校のゲーム内資格が実際に揃ったことは未検証。**
