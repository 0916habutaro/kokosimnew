# ココシミュNew ゲーム定義と実装計画

作成日: 2026-10-20 / 基準: main `6c13b74`（PR #302 マージ後）

この文書がゲームの目的・範囲・進め方の正本である。作業ルールは リポジトリ直下の `AGENTS.md` を参照。

## 1. ゲーム定義（ユーザー決定事項）

| 項目 | 内容 |
|---|---|
| 対象 | Windows専用、本人が遊ぶ個人用。配布・展開は考慮しない |
| 完成の基準 | ゲームとして遊べる状態 |
| 遊び方 | 日程を進めると、その日の全国の試合が処理される。結果・記録を眺める。監督としての指示や試合操作はない |
| 年度 | 4月開始。夏の予選 → 夏の甲子園 → 秋の予選（県・地区） → 神宮大会 → 選抜 → 春の予選 の循環 |
| 組み合わせ | 大会規則の範囲内で毎回ランダム |
| 選手の循環 | 新入生の入学と3年生の卒業を毎年行う |
| 成績 | 現在定めている範囲（個人成績・大会成績・学校戦績）を残す |
| 成長・怪我 | あり。練習の指示はないため、成長は仕組みで決める。強豪・常連だけが伸びすぎないようにする |
| 試合 | 実際の高校野球になるべく近づける |
| 初期状態 | 校名・能力・勢力図を実在に近づける |
| 履歴 | 大会結果・ベスト8一覧などを後から追える |
| 監督 | データを持つ。異動・退任があり、有名監督の学校は新入生の質がよくなる |
| 選手名 | 苗字は都道府県ごとのデータから選手の出身地に応じて選ぶ。名前はランダムだが、よくある名前ほど出やすい |

個人用・配布なしのため、**旧セーブとの互換性や旧形式の維持は不要**（§5で決定）。

## 3. 新しい仕組みの方針案

### 3.1 成長

練習の指示がないため、選手ごとに次の要素を持たせて自動で成長させる。

- **潜在能力（上限）**：入学時に決まる。分布は全校共通にし、無名校にも一定の確率で高い潜在の選手が現れる。
- **成長の型**：早熟・普通・晩成など。学年による伸び方の違い。
- **成長の時期**：毎月処理する。夏休みと冬（試合のない期間）を大きめにする。
- **試合経験**：公式戦の出場に応じて少し伸びる。

**強豪だけが伸びすぎない仕組み**：

1. 入部時の能力（入部品質）と、その後の成長量を分ける。強豪は入部時点の能力が高いが、成長量の学校差は小さくする。
2. 上限に近いほど伸びにくくする。差が開き続けない。
3. 出場機会を成長に反映する。強豪は控えが多く出場が少ない。弱い学校は1年生から出場して経験を積む。
4. 監督の育成力は小さめの補正にとどめる。

実装（2026-10-26、段階4）：`game_core/player_growth.py`、値は `config/players/player_growth_v1.json`。

- 選手ごとに成長の型（早熟・普通・晩成。25%・50%・25%）と潜在能力（伸びの倍率）を入学のときに決め、名簿（`roster_book.py`）に入れてセーブする
- 潜在能力：全校共通の分布（平均1.0・広がり0.3）に、まれに大化け（4%で +0.8）。学校による差は小さい（学校成分の z 1あたり +0.02）
- 球速の伸びしろ：潜在能力とは別に引く（平均1.0・広がり0.5、0.1〜2.6）。3年間で数km/hしか伸びない投手から、20km/h近く伸びる投手までいる
- 伸び悩み：学校によらず12%の選手は、潜在能力と球速の伸びしろが0.35倍（強豪校にも伸びない選手がいる）
- 毎月の初めに前の月の分を伸ばす：3年間の伸び（潜在能力1.0で打撃などは14、球速は13km/h）× 潜在能力（球速は球速の伸びしろ）× 月の重み（8月と12〜2月は1.6、7月は0.7）× 型の学年の重み（早熟 1.6・1.0・0.4、晩成 0.5・1.0・1.5）× 上限に近いほど小さくなる係数（打撃などは50で1・100で0、球速は130km/hで1・165km/hで0）
- 公式戦に出た試合ごとに少し足す（打者 0.12、投手 0.15。月の成長のときにまとめて）
- 出場はPA>0・BF>0・`team_participation.fielding_player_ids`の和集合で判定し、選手IDごとに1試合1回だけ記録する。守備のみの出場や交代で退場した選手も含み、未出場の控え・開始前に外れて実出場のない選手は含めない。月次成長用`games`と練習中の怪我用`season_games`をともに加算し、既存の月次・年度リセットを維持する。成長量・上限・成長タイプは変えず、投手向け成長の区分も従来どおり本職による
- 試合と画面はその日の能力を使う（成長すると次の試合から変わる）

段階6-3Bでは練習分だけに育成力の倍率を掛ける（§3.4）。公式戦経験と乱数の丸めはそのままで、潜在能力・成長タイプは変更しない。処理済み月は名簿へ保存する。

**入学時の能力と選手の素質**（2026-10-31。`game_core/school_intake.py`、値は `config/abilities/school_intake_v1.json`（revision 5）・`player_generation_v1.json`（revision 2））

前は学校・年度の入部品質（z）を、その学校のその年の新入生全員に同じだけ足していた。評判Sの学校は控えまでミート・長打がA〜Sになり、投手もそろって強かった。今は選手ごとの素質を通して効かせる。

- 素質 = 入部品質 z（学校成分・年度の当たり外れ・監督。§10）× 1.0 ＋ 選手ごとの乱数（広がり0.7）＋ 有望な新入生なら上乗せ（平均1.4）。どの学校にも上下の差が出る
- 有望な新入生は学校・年度ごとの人数で決める：Poisson（平均 0.3 × exp(1.15 × z)、4人まで）で人数を引き、その年の新入生のうち選手ごとの乱数の順に割り当てる。強豪校で学年に数人、中位校で数年に1人、弱小校はまれ。1人あたりの確率にしないので、部員が多い学校ほど主力が増えることはない
- 能力 = 入学時の平均（素質0の1年4月。打撃などは44前後、球速117km/h）＋ 素質 × 能力ごとの重み × 型の倍率 ＋ 型の長所・短所 ＋ 能力ごとの乱数。上の方は緩やかに頭打ち（打撃などは72から96へ、球速は138から160へ）
- 1年生の能力の上の方（2026-11-12）：入学時（1年の4月）だけ、上の頭打ちのあとの能力をさらに61から83へ緩やかに抑える（`school_intake_v1` の `entry_soft_cap`）。抑えた点は能力ごとに名簿に残し、毎月の成長で戻す。1年の4月の分から数えて26か月目（3年の5月の分。6月1日）までに全部戻し、潜在能力・上限の近さ・怪我によらない（`player_growth_v1` の `entry_deferral`）。上限の近さによる伸びにくさは、戻していない点も足した値で見る（抑えた選手が速く伸びないように）。球速・変化球には使わない。前は1年生の7月にAを持つ選手が3年生の0.44倍いて、夏の甲子園のベンチ入りの1年生が多すぎた。抑えたあとは0.07倍で、Aは「スーパー1年生」だけになった。2・3年生の能力の分布は変わらない

### 3.2 怪我

- 投球数・連投・年間の出場量から発生確率を決める。投手を重めにする。
- 程度（数日〜数か月）と、復帰までの能力低下を持たせる。重い怪我はまれにする。
- 球数制限（1週間500球以内）を大会規定として実装し、継投の判断にも使う。

実装（2026-10-27、段階4）：`game_core/injuries.py`、値は `config/players/injuries_v1.json`。

- 頻度はセーブごとの設定（なし・少なめ・標準・多め。倍率 0・0.5・1・2）。新しく始めるときに選び、セーブの管理画面で途中でも変えられる。セーブにだけ持つ
- 練習の怪我：毎月の初めに次の月の分を決める（その月のどこかの日から休む）。1人1か月 0.35%、投手は1.5倍、その年度の公式戦の出場1試合ごとに4%ずつ増える
- 試合の怪我：出た試合のあとに決める（翌日から休む）。野手 0.12%、投手 0.3%。1試合100球を超えた分・7日間300球を超えた分で増え、前の日も投げていたら1.6倍（2日続けば2回掛ける）
- 守備のみの出場も試合直後の怪我の対象にする（投球数0なので既存の野手確率）。両校の従来対象（PA>0またはBF>0）を従来順に抽選した後、守備のみの選手を両校の名簿順で抽選する。試合別の独立乱数を使うため、同じ試合直前状態なら従来対象の抽選結果は変わらない。年間出場回数の補正は既存式どおり練習中の確率も増やし、月・学校内の共有乱数を介して他選手の結果にも影響し得る。新たな怪我や成長により将来の試合結果は変わり得る
- 重さ：数日（3〜7日）70%・数週間（10〜42日）29%・数か月（60〜180日）1%。投げすぎの怪我は数か月の割合を3倍
- 怪我の間は試合に出ない（元気な選手が9人に満たないときだけ出る）。成長は休んだ日の割合だけ減る
- 復帰直後は能力が少し下がり（数日 3%・数週間 6%・数か月 10%、球速 1〜4km/h）、1〜4週間で1週ずつ戻る。後に残る怪我はない
- メンバー一覧と選手の画面に怪我の印と復帰の見込み日、選手の画面に怪我の履歴を出す

### 3.3 勢力図の維持と変動

- 学校ごとに**評判**を持たせる。初期値は実績データから作り、毎年の成績で更新する（直近ほど重く）。
- 新入生の質 ＝ 学校の評判 ＋ 監督の評判 ＋ 年度ごとの当たり外れ。
- 評判が上がった学校には良い新入生が集まり、成績が落ちれば評判も下がる。これで「新しい強豪の誕生」と「名門の低迷」が起こる。
- 公立と私立で、県外からの入部の割合を変える。

実装（2026-10-27、段階5-1）：`game_core/annual_reputation.py`。設定は `config/abilities/annual_reputation_v1.json`。監督の補正は段階6。

- 新規開始の評判・入部品質・ランクは `school_reputation.py` の従来値を維持する。学校ごとの評判は初期の入部品質の z で保持する
- 確定した大会全体の到達点（出場のみ0、ベスト8 0.25、ベスト4 0.4、準優勝0.6、優勝1）に大会別の重みを掛け、学校ごとに合計する。県・夏の地方1、地区2、選抜4、夏の甲子園5、神宮3。予選の勝数や試合別の点を重ねて加算しない
- 毎年4月1日、前日までに完了した大会を使う。年度・大会IDで一度だけ集計し、未完了の大会は終了してから次の4月へ回す。4月1日当日の結果も次回に回す
- 目標の点は直近3年の年間の点の重み付き合計（今年1.0・前の年0.6・2年前0.3。`recent_year_weights`）。点のある学校だけ年ごとに `CareerState.reputation` に残し、重みの数より古い年は消す
- 目標の点の全国順位を正規分布の z に変換し、`新しい評判 = 前の評判 + (目標の z − 前の評判) × (1 − carry)` とする。`carry = 0.8`（過去の影響は約3.1年で半分）、1年の変化は z ±0.35 まで
- 同点（全国の約9割は点が0）は**前の評判の順**に並べる。結果のない学校は順位がほとんど動かず、乱数の種でも変わらない。2026-11-11 までは同点を学校ごとの固定乱数で並べていたため、結果のない強豪が乱数の位置へ引かれ、勝てない学校が毎年上がり続けていた
- 初出場率などの目標に合わせる補正は入れない。carry と ±0.35 は変えていない（複数年にしたことで目標が安定し、変える必要が見えなかった）
- 更新後の評判の全国順位から、従来と同じ分布の入部品質の学校成分を作る。年度ごとの当たり外れは変更しない。各入学年度の学校成分を保存し、遅れて名簿が作られても入学時の値を使う。在籍選手の能力と過去の試合結果は評判更新では変更しない
- 最新の評判・更新済み年度・集計済み大会ID・確定済み未反映の大会・入学年度別の学校成分は `CareerState.reputation` に保存する。名簿も同じ評判を参照し、読込で初期値から作り直さない。学校詳細の評判ランクは保存された最新の評判の全国順位を使う

### 3.4 監督

- 持つデータ：氏名、年齢、在任校と在任年数、評判（実績から更新）、育成力、継投や起用の傾向、作戦の傾向（小技・機動力。段階F1）。
- 異動：公立は数年ごとに県内で異動。私立は長期在任が中心。
- 退任：年齢や在任年数に応じて退任し、後任が就く。
- 有名監督：評判が高いほど新入生の質が上がる。異動するとその効果も移る。
- 初期データ：実在の監督名簿を使わずランダムに生成する（§5）。

実装（段階6-1）：`game_core/coaches.py`。2026年の新規開始時に学校マスターの全校へ架空監督を1人ずつ配置する。

- `Coach` は永久監督ID、氏名、生年、所属校ID、就任年、監督評判、育成力、継投・起用傾向を持つ。監督IDは専用乱数で生成した128ビットの値（`COACH-` 接頭辞）で、学校ID・校名を含めない。人物IDを主キーに保持し、将来所属が変わっても同じ人物を追える
- 氏名は既存の `player_names` の生成用データと重みを再利用する。苗字は所属校の所在県から選び、名前は既存の人気名の重みを使う。監督の年代別名簿や実在監督の名簿は使わない。架空の組み合わせなので実在の人物との同名はあり得る
- 生成範囲・分布は `config/coaches/coach_generation_v1.json`。年齢は25〜70歳（最頻47歳）、在任は1〜30年目（最頻4年目）の三角分布。就任時23歳以上になるよう在任期間を制限する。年齢・在任年数は年度基準（4月1日に各1増加）で、生年・就任年から算出する
- 評判・育成力は1〜100、平均50・標準偏差15の正規分布を範囲内に収める。采配傾向は同じ範囲、平均50・標準偏差18。値が大きいほど早めの継投／若手の起用を好む。全校共通の分布で、学校の評判とは結び付けない。実データへの推定ではなくゲーム用の初期分布
- 乱数は `coaches:initial:*` の名前空間に分離する。IDの乱数も氏名・能力とは別。同じシードで同じ監督になる。選手・学校評判・試合の乱数と設定は変更しない
- `CareerState.coaches` に全人物を保持し、既存の本番セーブのスナップショットへ統合。ロード時は保存した値をそのまま戻し、再生成しない。学校詳細は現在の監督の氏名・年齢・在任年数を表示し、校名変更後も所属校IDで参照する
- 6-1は生成と保存・最小表示まで。退任・異動・後任就任は6-2、新入生・成長・試合への効果は6-3。詳細画面、異動履歴、長期バランス検証は後続工程。旧セーブ互換は設けない

実装（段階6-2）：同じ `CoachBook` と `CareerState.coaches` を拡張し、年度人事と所属変更イベントを保存する。初期配置の乱数・名前・能力は6-1のまま。

- 2027年以降の4月1日に1回だけ更新する。処理済み年度をセーブに持ち、ロード後・同日再処理でも二重に更新しない。年度は連続して処理し、飛ばして更新しようとしたらエラーとする
- `CareerState.next_day()` は3月31日の試合処理 → 日付更新 → 監督人事 → 学校評判の年度更新 → 前月の選手成長・翌月の怪我予定／新入生生成 → 名簿の日付更新の順に行う。監督の能力による補正は6-2では接続しない
- 調整値は `config/coaches/coach_personnel_v1.json`。退任は40歳未満0、40・50・60・65・70・75歳から段階的に年率0.3・1・4.5・12・30・60%、80歳で必ず退任。在任による加算は公立15年超から年0.3ポイント（最大8ポイント）、私立等25年超から年0.2ポイント（最大6ポイント）。実在の人事統計ではなくゲーム用の初期設定
- 異動抽選は退任しなかった監督だけ。3月末までに満了した在任年数で、公立は3・5・8・12年以上から年率12・25・40・55%、私立は10・20・30年以上から1・2.5・4%。学校の設置者はセーブの編集も反映した現在値を使う
- 最小限の保守的な異動範囲として、全員を**同一都道府県かつ同じ設置者区分**内に限定する。県立・市立・国立・公立大学法人はそれぞれ別枠、私立も県内私立だけ。公私間・都道府県間の異動はしない。設置者不明校は異動させず退任・後任就任だけ行う
- 退任者・異動候補・空席を全国で先に確定する。県・設置者ごとに候補と空席を正規化して専用乱数で並べ、本人の元の学校を除いた二部マッチングで異動先を一括決定する。有効な異動先がない単独候補は留任し、架空の異動履歴を付けない。更新後の全校配置を検証してから人物・イベント・処理済み年度を一括反映する
- 異動では永久ID・氏名・生年・能力を引き継ぎ、新任校の就任年を当該年度、在任を1年目とする。退任者は `retired_on` を持って現役配置から外れ、人物と能力を保持する。空席には既存生成処理・名前データで後任を作る（25〜55歳、最頻36歳。能力分布は6-1と同じ）。全ての過去・現在IDとの重複を避け、新規IDを付ける
- 乱数は人事抽選・配置・後任生成・後任IDごとに `coaches:*` の専用名前空間へ分離する。年度と人物ID／学校IDで抽選を固定し、学校や辞書の処理順序・保存再開で結果が変わらない。学校評判・選手・試合の乱数や設定には触れない
- 人物はIDごとに1件、履歴は初期就任と所属変更の `CoachEvent`（日付・種類・人物ID・前任校・異動先・前任校への就任日）で保存する。退任・異動イベントから前任校での在任期間を算出できる。年度ごとの全人物コピーは保存しない
- 現役の学校ID→監督ID索引で現在の検索を定数時間にし、学校別の所属変更索引で `for_school(school_id, on=日付)` を検索できる。索引はイベント・人物からロード時に復元する。異動後も3月31日までの監督と4月1日からの監督を区別し、3月開始で4月に続く大会でも試合日の監督を参照できる。学校詳細は現在の監督を表示し、校名変更でも所属は学校IDで保持する
- 6-2の検証は監督人事のみ30年間・複数シードと、本番の複数年進行・保存再開。詳細画面・履歴閲覧と、監督効果を加えた試合の長期バランス検証は後続工程。旧セーブ互換は設けない

実装（段階6-3A）：監督評判を、2027年度以降の新入生の入部品質へ独立した成分として加える。

- `config/coaches/coach_intake_v1.json`：評判50を0とし、`監督成分z = clamp((評判 − 50) × 0.004, −0.20, +0.20)`。評判80は+0.12、20は−0.12。2026年開始時の在校生（2024〜2026年度入学）と開始前の選手には適用しない
- `SchoolIntakeModel` は従来の学校成分×重み＋年度成分×重みに監督成分を加えてから、従来と同じ±3.5の範囲に収める。学校成分・年度成分の生成値と重み、能力の上限・ソフトキャップは変えない。監督の評判を学校の評判へ足したり、学校成分を置き換えたりしない
- 4月1日は、6-5以降の監督評判更新 → 人事更新 → 入学時の監督評判・補正値の確定 → 学校評判更新 → 前月の成長・新入生生成の順とする。`CoachBook.intake_year` で二重確定を防ぎ、まだ確定していない未来の入学年度の生成は拒否する
- 入学年4月1日の所属は既存の `CoachEvent` から参照する。人物IDごとの `CoachIntakeRating` に適用開始年度・その時点の評判・実際の補正値を保存し、同じ人物の評判と補正値が変わらなければ翌年度に複製しない。学校ID・入学年度 → 所属履歴の人物ID → 当該年度の確定値という参照で、監督の異動・退任後、名簿の遅延生成・ロード後も入学時点の値を使える。現在の監督や現在の評判から過去分を再計算しない
- `CareerState.coaches` と `RosterBook.coaches` は同じ保存済みの監督帳を共有し、名簿ごと・選手ごとの監督データの複製はしない。監督補正の設定も監督帳に保存する。すでに入学した選手の能力は従来どおり名簿に保持し、監督の交代では変更しない
- `RosterBook._new_state()` の潜在能力の抽選には、従来どおり `program_quality_z`（学校成分だけ）を渡す。監督成分や合成した入部品質を潜在能力へ加えず、毎月の成長・能力編集・怪我・復帰にも監督補正を再加算しない。3月から4月に続く大会は従来の旧年度の部員・能力を使う
- 人事とその乱数は6-2のまま。補正のための新たな乱数消費はない。6-3Aでは監督の実績による評判値の年度更新・育成力・采配・監督画面は扱わない。旧セーブ互換は設けない

実装（段階6-3B）：監督の育成力は、対象月の練習による成長量だけへ倍率として適用する。

- 設定は `config/coaches/coach_growth_v1.json`。2027年4月の練習分（2027年5月1日に計算）から、`練習倍率 = 1 + clamp((育成力 − 50) × 0.003, −0.10, +0.10)`。50は1.0、80は1.09、20は0.91。開始前は1.0で、2026年の能力・試合結果を維持する
- 対象月の**1日**に在任していた監督を `CoachBook.for_school(on=月初)` の所属履歴から取得する。4月1日に人事が行われた後の3月分成長でも、3月1日の旧監督を参照する（2027年3月は適用前なので1.0）。4月分は4月1日の新監督で、5月1日に計算する。将来月途中の交代を追加しても当月は月初の監督とし、翌月から交代を反映する。翌月の計算日や現在の所属で過去の月を置き換えない

- データは出典付きで集める（苗字ランキング、名前ランキングの公開資料）。

実装（2026-10-26、段階4の最初）：`game_core/player_names.py`、重みは `config/players/player_names_v1.json`。

- 材料は架空の選手名をつくるための生成用データとして `data/generation/player_names/` に置く（実在の記録ではないので `historical_data/` に入れない。出典は `data/master/sources.csv` の SRC000390・SRC000391）。苗字は電話帳の掲載件数（件数3以上の行だけ。行数で49%、件数で98%）。名前は9,999件で頻度がないため、先頭の人気の名前（53件）を重くし、残りは同じ重み
- 出身：公立などは県外1%。私立は評判のランク（ゲーム開始時の値）でS 45%・A 30%・B 15%・C 6%・D 3%・E 2%。県外の出身地は苗字の件数の合計（人口の目安）で重み付け。設置者は学校マスターの値（セーブの中で編集しても今いる選手の名前は変わらない）
- 表示は「苗字 名前」（半角スペース）。同じ学校の中で同姓同名にならないように選び直す（同じ苗字は許す）
- 名前は投打とは別の乱数で選ぶ。乱数の種が同じなら同じ名前になる。名簿（名前・出身・能力）はセーブに入る（§6、2026-10-26）

### 3.6 試合の現実らしさ

1. 高校野球の規定を入れる：タイブレーク（10回から）、地方大会のコールド、球数制限。
2. 実際の試合結果（#302で収集）と比べる：得点の分布、点差、番狂わせの頻度、延長の頻度、甲子園と地方大会の違い。
3. 調整値は従来どおりJSONで管理し、経緯を `docs/tuning/` に残す。

投手別失点は走者の責任投手へ帰属させる。自責点は無失策のイニングを投手別に
再構成し、救援投手は登板前の失策によるアウト機会を引き継がない（規則9.16(g/i)）。
チームの自責点と投手個人の自責点合計は一致しないことがある。試合展開・投手起用は
変えず、過去の保存結果も再計算しない。現在のイベントで扱える範囲と再構成の限界は
[`match_simulator_v1.md`](match_simulator_v1.md#pitcher-earned-runs) を参照。

出場状態は `game_core/match_state.py` の `TeamMatchState` を本番試合の正本とする。
DHなしの打順枠・実際の守備配置・登録者・当日の起用可能者・控え・退場者を一括検証する。
球数制限後の先発に開始配置をそろえ、試合中の継投で打順・P配置・成績行・守備値を更新する。
開始前に先発から外れた選手は未出場の控えへ戻し、出場中の野手が登板する場合は位置を交換する。
確定した開始配置・交代時点付きの変更履歴・守備出場IDを試合結果とA方式履歴へ保存する。
最終配置は差分から復元し、現在の能力・名簿を参照しない。正式な試合詳細画面では、
先発打順・守備配置、時点付きの交代履歴、個人成績をタブで表示する。打撃成績の守備欄も
当時の実配置の履歴を使い、配置記録がない試合は本職から推測せず「配置記録なし」とする。
過年度の選手リンクは試合年度の名簿を参照し、選手画面から元の試合・タブへ戻れる。

### 3.6.1 DHの状態モデルと直接試合計算（2026-10-30）

[日本高野連の公認野球規則5.11解説](https://www.jhbf.or.jp/memberschool/regulation/dh/)
（2026年2月訂正後）に従い、既存の `StartingLineup` と `TeamMatchState` を拡張する。
打順9枠と守備9位置を独立して保持し、開始時のDH宣言を記録する。DHなしは9人、
通常DHは投手を打順から外した10人、先発投手兼DHは同じIDで9人の出場となる。
先発投手兼DHの投手役・打撃役を退いた履歴は、選手の完全退場と別に保持する。
打撃役を退いた投手が、DH消滅後に別の打順へ入ることも認めない（公式ケース④）。

同時交代は `transition()` へ打順変更と守備変更をまとめて渡し、DH消滅後の投手等の
打順を呼出側が明示する。候補全体を検証してから一括反映し、不正な交代は状態・控え・
退場者・履歴を変えない。先発DHの第1打席完了義務には、打撃完了・相手先発交代・
球審が認めた負傷/病気を明示入力する。自チームの投手降板だけでは義務を解除しない。
DHが消滅した後は再導入できない。

状態モデルの記録・復元は開始宣言と成功した規則入力を再生し、役割復帰禁止と打撃義務も
復元する。守備出場IDには実際の守備9人だけを加え、DHだけの出場は含めない。
直接試合計算では `dh_mode`（`none`・`normal`・`pitcher`）を明示して先発選考できる。
省略時は従来のDHなし。通常DHは守備9人以外で打撃合成が最も高い選手を加え、
投手兼DHの明示選考では本職投手の既存の打撃・投手合成値を使い、両者の低い側が
高い選手を優先する。同点なら投手合成・打撃合成・ID順で決め、片方だけの適性へ偏らせない。
強制した方式の使用率・戦略バランスはここで決めない。球数制限後に先発が変わるときは、
確定した投手を使って同じ申告方式の合法な開始配置を作り直し、開始後は方式を導入し直さない。

`MatchSimulator.simulate()` は独立した打順・守備を参照する。継投では状態操作を再利用し、
通常DH・投手兼DHを継続する。緊急の野手登板ではDHが空いた守備へ入りDHを消滅させる。
明示的な同時交代は `LineupAdjustment` で打席開始前に指定できるが、全国進行や監督AIは生成しない。
初回打席完了は `CompletedPlateAppearanceMoment` で結果確定後の実打席へ記録し、
相手先発交代の通知は変更したチームの相手側だけへ送る。DH試合の打席前変更はチームをまたぐ
実行順も記録する。結果検証は両校の履歴をこの順で再生し、通知の根拠・打者・投手・守備出場を
実イベントと照合する。最終打席の通知に架空の次打席を使わない。

DH試合も既存A方式で保存・大会圧縮・読込・年度封印後の閲覧に対応する。
保存前は全イベントで厳密検証し、検証対象の照合値を付けてからイベントを破棄する。
読込では保存された半イニング別打席数と履歴を同じ状態操作で再生し、役割・退場・通知・
PA/BF・守備出場・成績合計を照合する。イベントのない打球・走者責任等を独立に再証明したとはしない。
保存前/後の境界と最小証跡は [`historical_match_retention_option_a.md`](historical_match_retention_option_a.md#9-dh試合の現行保存契約2026-10-30) を参照。

既存の試合詳細タブで、通常DHの打順外投手、兼任者の「投・DH」、片役終了・完全退場・
DH消滅後の打順を当時の記録から表示する。内部規則通知を実交代として表示しない。
全国自動進行でも、各正式試合の開始前に3方式を独立して比較する。球数制限後の実先発を
既存の投手起用順から確定し、その投手を固定して通常DH・兼任DHの配置を作る。通常DHは
当日の起用可能者が10人以上必要。兼任DHは実先発の打撃合成が自校の先発野手8人の平均以上
の場合に候補とし、投球だけ・控えとの僅差だけで兼任へしない。

DHなしで継投後に打順を継ぐ打者も含め、9枠合計の予想打撃合成値が1を超えて改善する
方式を選ぶ。通常DHは、救援登板による消滅と、その後の継投で失う打撃価値を評価し、
最高打撃力以外の野手・投手も候補にする。兼任は降板後の打撃継続と、より打てる後続投手へ
打順を引き継げない制約を比べる。DH消滅自体に一律の罰点は付けない。

継投区間は既存BF基準・スタミナ・監督采配・球数残量から、打撃機会は相手9打者と自校守備の
既存打席モデルによる規定回打者数分布から概算する。配置は本番と同じ状態遷移で再生する。
失点による早期降板・コールド・延長を予知しない。改善なし・閾値以下・同点はDHなし、
通常DHと兼任の同点は通常DHとする。大会や評判から使用率を直接与えず、選択用乱数も使わない。
健康な9人が揃わず負傷者を使う既存の救済経路では追加のDHを使わない。共有キャッシュには
DHなしの入力を保持し、選択結果は試合限りのコピーへ反映する。設定は既存
`config/match/game_rules_v1.json` の `dh_selection`（最小改善量1は9枠平均では1/9ポイント）。
比較用の `dh_enabled=False` は従来の入力・試合結果を維持し、保存形式や確率式を変えない。
代打・代走・試合中の戦術的DH解除のAI、投手再登板への拡張、採用率に合わせた確率調整は行わない。

**A 凡退時の走者**（`game_core/match_simulator.py`、値は `config/match/match_simulation_v1.json` の `outs_in_play`）
- 打席の結果は今までどおり「凡退」（`field_out`）として引き、そのあとでゴロ・フライに分ける。ゴロの割合は投手のゴロと打者の長打（大きいほどフライ）・ミート（大きいほどゴロ）で決める
- ゴロ：一塁に走者・2死未満なら併殺（`double_play`）になりうる。起こりやすさは打者の走力（速いほど起きにくい）と守る側の守備力で決める。併殺でなければ打者がアウトで、押し出される走者は進み、二塁の走者の三塁への進塁・三塁の走者の生還（進塁打）は走者の走塁・走力と守備力で決める（`ground_out`）。内野ゴロの間の得点は打点、併殺の間の得点は打点にしない。2死からのゴロ・1死からの併殺は3アウト目なので、走者は進まず得点もない
- フライ：三塁に走者・2死未満なら犠飛になりうる（今までの犠飛をここに含めた）。二塁の走者の三塁へのタッチアップも足した（`fly_out`）
- 記録：打者の成績に併殺打（`grounded_into_double_plays`）を足した。責任投手は今までどおり走者ごとに引き継ぎ、自責点の再構成（失策がなかった場合）では、凡退の間の進塁・得点は同じ塁にいる同じ走者の実際の動きだけを写す（疑わしいときは投手の有利に）
- 画面：試合の詳細の個人成績と選手の画面の成績に「併殺打」、試合の要点に併殺を出す

### 3.7 部員の人数（2026-11-07）

全校20人（学年5・7・8、守備位置の枠も固定）をやめ、学校ごと・年度ごとに入部人数が変わるようにした。実装は `game_core/roster_size.py`、値は `config/players/roster_size_v1.json`。実在の人数には合わせず、傾向だけを `docs/research/school_roster_2026/` の資料から目安にした（全国の1年は1校10〜11人ほど、小さな公立は学年0〜5人、県の常連は学年20〜30人、甲子園の常連の強豪は部員60〜100人。千葉の分析では、規模と常連度を除くと私立・公立の差は小さく、学校ごとの過去の入部人数がいちばん効く）。

- 新入部員の期待人数 = exp(学校ごとの集まりやすさ) × exp(0.5 × 監督の z) × 都道府県の傾向。監督の z は入部品質の監督の補正
- 集まりやすさ（対数）= 目安 ＋ 学校ごとのずれ。目安は、評判の全国の順位（入部品質の学校成分の z を順位の割合に直したもの。#428 と同じ）と私立・公立で決まる1学年の人数（`by_share`）の対数。私立は上位ほど大きく伸び（評判Sで1学年30人前後）、公立は強豪でも20人前後に寄せる。中位以下では私立・公立の差は小さい
- 目安は新規開始の評判から始め、毎年その年の評判の目安へ25%ずつ近づく（評判が変わっても部員はすぐには増減しない）。ずれは新規開始の年に引き、毎年 前の値×0.95＋小さな乱数 で少しだけ変わる。ずれの大きさは強豪・私立ほど小さい（標準偏差 私立の上位0.1〜中位以下0.38）。`RosterBook.appeal` に入れてセーブする。都道府県の傾向は乱数の種と都道府県から決める弱い値（標準偏差0.08。実在の県の差は入れていない）
- 実際の人数は期待人数から負の二項（ガンマ・ポアソン）で引き、強豪・私立ほど期待人数に寄せる（評判Sの私立はばらつきを4割に。推薦・寮で安定して集める）。中位以下は寄せない。上限は1学年 私立42人・公立26人。乱数は学校・年度（・部員番号）ごとに分ける
- 新規開始の2・3年生も同じ決め方で、入学した年の順に人数を引き、進級のたびに退部を引く
- 退部：毎年4月1日、進級する1・2年生が3.5%前後でやめる。評判の低い学校ほど少し多い（最大12%）
- 部の規模（2026-11-13）：集まりやすさが評判（野球の強さ）だけで決まると、野球の実績がない進学校などが連合チームになりやすかったので、2021〜2025年の夏の地方大会の出方（`historical_results/summer_local.py` の `participation`）から学校ごとの部の規模を決める（`program_size`）。年の重みは2021年0.4〜2025年1.0（直近ほど重い）
  - 2025年に単独で出た学校：単独の年の重みの割合（score）が0.6を超えると、新入部員の期待人数に下限を置く（5年続けて単独なら1学年3.5人）。ばらつきも最大0.3小さくする
  - 2025年に連合だった学校：下限は置かず、期待人数を連合の年の割合に応じて1学年4.0〜2.2人までにとどめ、ばらつきを最大0.4小さくする（下限だけでは前の年の連合が続けて連合になる割合が実際の77%に届かず53%だった）
  - 2021〜2025年に試合のない学校・新設校は今までどおり。下限・上限は評判の目安（`follow`）とは別に毎年同じ値を使い、セーブに入れない。評判と能力は変えない

  - 係数＝15歳人口の比 × 参加率の比。15歳人口は国立社会保障・人口問題研究所『日本の将来推計人口（令和5年推計）』の男子15歳（出生中位・死亡中位。2026年に対する比、2030年0.954・2040年0.739・2070年0.542）。表は2070年まで、その先は2070年の値で止める
  - 参加率：日本高野連の硬式部員数（2019年14万3867人、2022年13万1259人、2023年12万8357人）は、15歳人口（2020〜2023年ほぼ横ばい）より年に約2%速く減っている。この差を2026〜2030年だけ年2.1%ずつ入れ、2030年の値（0.918）で止める（ゲームの決まり。差が続くかは資料からは分からないので、先へは伸ばさない）
  - 効き方：係数を「その学校のもとの期待人数による度合い（1学年3人以下1.6、8人1.0、15人0.6、30人0.3）× 評判の順位による度合い（私立は上位ほど小さく、評判Sの私立は0.1。公立は1）」乗する。部員の少ない学校ほど強く効き、推薦・寮で集める強豪私立にはほとんど効かない
  - 学校の数（統合・閉校）、評判と能力は変えない
  - 確認（新規開始から30年、乱数の種 20261022・20261026。夏の連合チーム／出場チームのうち連合の割合。前は減少なし）：2026年 151・169（4.4・4.9%）、2031年 205・214（6.2・6.5%。前 152・166）、2036年 267・270（8.5・8.6%）、2041年 293・309（9.6・10.2%）、2046年 299・309（9.8・10.2%）、2051年 303・326（10.0・10.9%）、2056年 332・343（11.1・11.7%。前 161・164）。最初の5年は年に約10チームずつ増え（実際の2022〜2025年とほぼ同じ）、30年後も出場チームの25〜30%には届かない。連合でも出られない学校は2056年に34校。評判Sの私立の部員（3学年）は92〜103人で変わらない
  - 効き方の度合い：参加率の表を入れたうえで、部員の少ない学校で1.6・2.0・2.5・4.0を最初の5年で比べ、年に約10チームずつ増える1.6にした（15歳人口と参加率の表は変えていない）
- 最低人数：新入部員のかさ上げはしない（2026-11-08。`minimum.players` を0）。人数の足りない学校は大会ごとに連合チームを組む（§3.8）。投手2人・捕手1人は、新入部員の守備位置の振り替えでそろえる（人数は増やさない）
- 守備位置：新入部員ごとに確率で決める（投手27%・捕手11%など）。部員番号は空いている番号を小さい順に使う
- ベンチ入り：大会ごとに20人。その学校の最初の試合の日の能力で、投手4人・捕手2人を先に入れ、残りを評価の高い順に入れる（学年1つにつき3.0点上乗せ。`roster_size_v1` の `bench.grade_bonus`）。選んだ選手は進行中の状態（`bench_members`）に入れ、大会の途中で入れ替えない。ベンチ外の選手は試合に出ず、試合の経験も付かない。部員が20人以下なら全員で、そのことも大会ごとに記録する（画面が前の大会のベンチ入りを出さない）。画面の◎は、いちばん最近始まった大会の出場メンバー（大会開始日の部員から決めたもの）から付け、今日の部員からは付けない（3月に始まった大会のあとの新入生には付かない）
  - 学年の上乗せ（2026-11-12）：1年生の能力を抑えたうえで1.5→3.0点にした。夏の甲子園のベンチ入りの1年生（49校×20人、乱数の種 20261022・20261026）：2026年 83・70人→45・48人、2027年 83・102人→54・51人（実際は40〜51人、4〜5%）。3.25点では45・28人／47・39人と少なすぎる年が出た
- 有望な新入生（§3.1）は今どおり学校・年度ごとの人数で決める。部員が多くても主力の数は増えない。学校の強さに直接足す補正はない（強さは選手から）
- 画面：学校の一覧に部員数（引退した3年生を除く）、部員の表に学年ごとの人数・学年とベンチ入りの絞り込み・ベンチ入りの印
- 確認（`balance_report`、種 20261022・20261026、2026年4月〜2029年3月）：4月1日の1校あたり 1年10.0〜10.3・2年9.7〜10.3・3年9.3〜10.0人（3年周期の入れ替わりはない）。最低人数で補ったのは毎年440〜640校、退部3.4%。20人固定からの導入時（#442）は §11 の得点 5.05→5.19、コールド 37.0→40.0%、1年を進める時間 約8%増、セーブ（JSON）約4割増
- 強豪の調整（2026-11-08）：2年目の秋に強豪私立の部員が少なすぎた（1・2年で15〜24人）。評判の効きを順位にし、私立×評判を強め、集まりやすさを評判に寄せ、強豪のばらつきを小さくした。4月1日の部員数（3学年、平均。前→後）：評判Sの私立 63〜66→95〜99人（50人未満は毎年5校前後→0校）、Aの私立 55〜57→72〜76人、Bの私立 51→49〜50人、公立の評判A 42〜47→43〜49人、公立D 30〜31人・E 23人（変わらず）。§11 の指標は地方大会の得点 5.20→5.23、コールド 40.4→40.2%、完封 30.4→30.8%、夏の甲子園の初出場 12.2→11.2%、2年続けて出た学校 13.5→14.0校、直前10年に3回以上出た学校 38→44%（実際42%）

### 3.8 連合チーム（2026-11-08）

部員の足りない学校は、大会ごとに同じ都道府県の学校と連合チームを組む。実装は `game_core/joint_teams.py`（組み方）と `game_core/live_members.py`（大会・名簿への組み込み）、値は `config/players/joint_teams_v1.json`。実在の連合チームの組み合わせは data/ に入れず、ゲームの中で毎年組む。

実在の規則（日本高野連が2012年5月24日の理事会で決めた「部員数不足の高等学校間の連合チームによる大会参加」。作業環境から高野連の原文を開けず、報道と都道府県高野連の通達の検索結果の要約で確かめた）
- 部員8人以下の学校2校以上で組める。同じ都道府県の加盟校どうし。学校の間の距離は問わない
- 地方大会・都道府県大会に出られ、地区大会・全国大会にも進める（通達に「地区大会および全国大会を含む」）
- 2026年夏の地方大会は3,662校・3,363チーム。部員不足の連合は142チーム・421校（ほかに統廃合の特別措置の連合15チーム・35校）（日本高野連の発表。デイリースポーツ・熊本日日新聞 2026年6月28日）

ゲームの仮の決まり（資料が見つからない点）
- 数える部員は、その大会の開始日に出られる部員（秋季・春季は1・2年生）。8人以下なら連合を組む
- 相手は同じ大会の出場校から、同じ支部・地区（data/areas の federation_branch）、同じ市町村、部員の多い学校の順に選ぶ。13人（交代のできる人数）に届くまで、4校まで加える。9人に届かなかった学校は、まだ入れる近い連合に加わる。入れなければ、その大会に出ない（部員0人の学校も出ない）
- 連合の代表校は、シード・予選免除のある学校、なければ部員のいちばん多い学校。組み合わせ・日程・勝敗は代表校の枠で持ち、名前は「代表校・ほかの学校」とつなぐ
- 連合は夏の地方大会・春季と秋季の都道府県大会（北海道は春季・秋季の全道大会）ごとに組み、勝ち進んだ地区大会・甲子園・神宮・選抜は同じ連合で出る（`chains`）。選抜の選考は単独の学校と同じ
- 大会の組み合わせは前の年度の秋につくるので、まだ名簿のない新しい年度の大会は、連合を組まずにつくっておき、4月1日に名簿ができたら組み直す（`union_pending`）
- 学校ごとの試合の日と甲子園の予定（秋季大会に入れない日）は、連合の構成校それぞれで確かめて記録する（夏と秋で連合の組み合わせが変わっても、同じ選手が同じ日に2試合しない）。甲子園に出ている連合のほかの構成校も、秋季大会の予選免除・日程の組み直しの対象
- 勝ち進んだ大会で新しく組んだ連合・出ない学校があっても、進んできた連合はそのまま使う
- 出場校が減って3〜4校の組に分けきれない予選（神奈川の支部予選）は、組の試合をせずに進む学校をできるだけ少なく出す
- 春季・秋季の県大会は、連合・不参加を決めたあと、チームを出せる学校がすべて出る（2026-11-14。それまでは2026年の実際のチーム数に合わせて乱数で出場校を減らしていた）。予選はその年のチーム数から組み、本大会の校数・シード・地区大会への進出は変えない。2026年の実際の方式から外れる点：
  - 東京の秋の一次予選：62の代表の組（31ブロック×A・B）に、予選に出るチームをできるだけ同じ数ずつ分ける。2026年は230チームで3・4チームの組だったが、チームが248を超える年は4・5チームの組になる。連合・不参加を外したあとに組み直す（`StructuralAnnualInputFactory.arrange_groups`）
  - 神奈川の支部予選（FMT006）：地区のチーム数から3〜4校のリーグを組む。組の1位は代表、残りの枠は2位から決め、2位どうしの補充代表決定戦（3校の組の2位を先に、足りなければ4校の組の2位）で枠の数に合わせる。2026年のチーム数（枠の2倍）では実際と同じ「4校の組の1・2位と3校の組の1位が代表、3校の組の2位どうしが決定戦」になる
  - 岐阜の秋の1次トーナメント：2次トーナメントへ進む21校（`gate_winner_slots`）を固定し、非シード校が42校より多ければ1回戦から、少なければ不戦勝で合わせる（2026年は42校が1試合ずつ）
  - 千葉の秋（一次予選＋敗者復活）：代表28＋敗者復活19の数は変えず、ブロックの大きさで合わせる
  - 鹿児島の秋：地区のシード決定戦のない熊毛地区の学校も、県大会から出る

試合と記録
- 試合は構成校の部員をまとめた名簿で行う（ベンチ入りは§3.7のまま。監督は代表校の監督）。試合では代表校のチームとして出るが、選手の学校は変えないので、個人成績・試合の経験・成長は選手それぞれの学校に付く
- 評判：連合の到達点（出場・ベスト8など）を構成校それぞれに付ける（初期の評判の `union_start` と同じ考え方）
- 学校の強さは選手から計算する（連合の強さも構成校の選手から）。直接の補正はない
- 画面（2本目）：大会の組み合わせ・出場校一覧・試合の詳細・その日の試合・優勝校・記録の一覧に「代表校・ほかの学校」の名前を出す（閉じた年度も、保存した年度の状態の連合から）。学校の画面は、連合で出た大会に「連合（相手の学校）」の印を付け、勝敗・最高成績・試合一覧・部員の個人成績を構成校それぞれに出す。甲子園の出場回数も構成校それぞれに数える。記録の一覧では連合を1チームとして数える
- 新入部員の目安（§3.7 の `by_share`）は、順位の下の方を小さくした（夏に8人以下の学校が実際の連合の校数に近づくように）

確認（`balance_report`、種 20261022・20261026、2026年4月〜2029年3月。前は main（#443））
- 夏の地方大会の連合：毎年148〜158チーム・440〜454校（実際は部員不足142チーム・421校＋統廃合15チーム・35校）。出ない学校は8〜10校。秋季の都道府県大会は213〜225チーム・650〜680校
- 部員数（4月1日、3学年）：公立の評判Eは23人→17人（10%点5人・90%点33人）、かさ上げした学校は毎年440〜640校→0校。1校あたりの学年の人数は1年9.7・2年9.4〜9.6・3年9.1〜9.3人（前は10.0〜10.3・9.7〜10.3・9.3〜10.0）。評判S・Aの私立は変わらない
- §11（3年の平均、前→後）：地方大会の試合 3,697→3,395（実際3,363）、1チームの得点 5.23→5.11、コールド 40.2→39.7%、完封 30.8→31.4%、夏の甲子園の初出場 11.2→9.9%、2年続けて出た学校 14.0→11.8校、直前10年に3回以上出た学校 44→39%

## 6. 保存の現状（2026-10-20 時点）

ゲーム本体が実際に使っている保存は次の組み合わせ。

- セーブスロット（`save_slots.py` / `live_season_save.py`）：進行中の状態をそのまま書き出したJSON。読込で計算し直さない（ADR-043。2026-10-21 に ADR-026 の再計算方式から変更）
- 試合履歴（`historical_match_archive.py`、旧A方式）。終わった大会の試合の記録は大会ごとにまとめて圧縮する（`packed_competitions`。2026-10-26）
- 名簿（`game_core/roster_book.py`、2026-10-26）：年度・学校ごとの部員（名前・出身）と、選手ごとの能力・成長の状態を持ち、セーブ（`CareerState.rosters`）に入る。乱数の種から作るのは新規開始の部員と新入生だけで、進級した選手は前の年度から引き継ぐ。年度を閉じるとき（4月1日）に、その年度の名簿を年度末の能力・成長の状態と一緒に試合履歴の `closed_rosters` に詰めて圧縮して書き出す。セーブから手放すのは、その年度に始まった大会（3月に始まる春季県大会）が終わってから（ADR-043 追記）
- 監督（`game_core/coaches.py`、6-2）：全国の現役・退任監督の人物データ、所属変更イベント、処理済み人事年度と人事設定を `CareerState.coaches` に保存する。氏名・生年・所属校ID・就任年・能力はロード時に再抽選しない。学校別の現役・履歴索引は保存された人物・イベントから復元する（§3.4）
- 選手名簿の履歴（`career_roster_archive.py`）
- 閲覧用SQLite（`browse_repository.py`）

v2（`career_v2_*`）と履歴閲覧の試作画面、Tk の閲覧画面、閲覧用SQLiteを作る `season_cli` は、正式な画面に置き換えて段階2で削除した。v3（架空大会用）は段階0で削除済み。

読込時に毎回最初から再計算する方式は、段階1で状態をそのまま書き出す方式に変えた（ADR-043）。

## 8. 段階1（年度循環）の方針（2026-10-21 決定）

### 年度の区切り

ゲームの1年度は **4月1日〜翌年3月31日**。新規ゲームは **2026年4月1日** に始まる。

新規開始前に処理する2026年3月の春季大会は、勝敗・進出、試合記録・個人成績、
先発・交代履歴、7日間の球数ログ、発生した怪我と復帰予定日を保持する。
新規開始の大会状態を作り終えた直後、開始日が2026年4月1日の場合だけ、月次成長用の
`games` と年度内の練習怪我補正用の `season_games` を0にする。開始前の経験を
4月以降へ持ち越さず、セーブの読込では再実行しない。通常の月次成長と
2027年度以降の年度リセット、開始日を変更するテスト経路の処理は従来どおり。

| 時期 | 大会 |
|---|---|
| 4〜6月 | 春季県大会・地区大会 |
| 7〜8月 | 夏の地方大会・夏の甲子園 |
| 9〜11月 | 秋季県大会・地区大会・明治神宮大会 |
| 翌年3月 | 選抜（その年度の秋の結果から選考） |

**大会の所属年度**（2026-10-21 決定）：

- 3月の選抜は **前の年度** の大会（2027年3月の第99回選抜＝2026年度）
- 3月に始まる春季県大会は **新しい年度** の大会（2027年3月開始の春季県大会＝2027年度）
- 翌年度の大会表は、**その年度の秋の大会が終わった時点で作る**。3月は、前の年度の選抜と新しい年度の春季県大会が並んで進む

コードでは `phase2_engine/school_year.py` の `competition_school_year` で判定する。

実装（`phase2_engine/career_state.py`）：ゲームの日付は1つで、進行中の年度を同じ日付で進める。その年度の秋の大会の日程の最後の日が過ぎたら翌年度の大会表をつくって開き、3月31日を進めたら前の年度を閉じる（履歴を封印する）。3月に始まる大会は新チーム（夏が終わった3年生は出ない）。

**同じ学校が同じ日に2試合しない**（2026-10-21）：学校ごとの試合の日を全大会・全年度で共有し、両校とも空いている最初の日程の日に入れる。日程の日がふさがっていれば、次の日程の日より前の空き日（予備日）を使う。日程が地区ごとの日をまとめたものしかない大会（2026年データの青森春季の地区予選）は日が足りず、わずかに同じ日の2試合が残る。

### 選手の循環

- 4月1日に新入生が入部する
- 3年生は、自分の学校の夏の大会（地方大会または甲子園）が終わった時点で引退する。秋からは1・2年生の新チーム
- 3年生は3月に卒業する

**卒業・入学の日と大会の出場メンバー**（2026-10-21 決定）：

- 卒業は **3月31日**、入学は **4月1日**
- 各大会の出場メンバーは、**その大会が始まった時点の部員** から選ぶ。大会の途中で部員が変わっても入れ替えない
- 3月に始まる春季県大会は、秋と同じ新チーム（1・2年生）で戦う。4月1日に入学した新入生は、その大会の途中からは加えない
- 秋の大会は新チーム（1・2年生）で戦う。甲子園の途中で秋の県大会が始まる県でも、甲子園に出ている学校の3年生は秋の大会に出ない
- 同じ選手が同じ日に2試合出ないようにする（例：甲子園に出ている学校の秋の初戦は甲子園の後に回す）。年度の重なりか全国の試合を選手で行う作業で入れる

実装：`game_core/membership.py`（部員と出場メンバー）、少人数のときの先発・投手陣は `config/abilities/team_strength_v1.json` の `small_roster`。

### 前の年度の結果を翌春に使う

2年目からは、前の年度のゲーム内の結果（選抜の出場校、秋季県大会の順位、秋季地区大会の出場校）を翌年度の春季大会の予選免除・推薦に使う（`phase2_engine/prior_season.py`）。東京・北海道のように秋季地区大会が1都道府県だけの大会は、その順位を県大会の順位として使う。翌年度の大会表は秋の大会が終わった時点でつくるので、そのときにはすべて決まっている。前の年度を閉じた後も同じ大会表をつくり直せるよう、この結果はセーブ（`prior_results`）に書く。

### 進め方（PRの分け方）

1. 年度の区切りを4月〜3月にし、新規ゲームを2026年4月1日から始める（済）
2. 2027年以降の大会表を自動生成する（回数、曜日合わせ、抽選）（済）
3. 全国で入学・引退・卒業を回す。全国の試合を選手で行う前提なので、次の順に分ける（2026-10-21 決定）（済）
   1. 名簿の作りを直す：部員を日付で決める（4/1入学、自分の学校の夏の大会が終わったら3年生引退、3/31卒業）。大会開始時点の部員で出場メンバーを固定する。少ない人数でも先発を組める
   2. セーブを「その日時点の状態」を書き出す形にする（読込時に最初から計算し直さない。§6）
   3. 全国の試合を選手で行う（本番の既定を resolver contract `players_v1` にする。`game_core/live_members.py`）
4. 年度の重なり：秋の大会が終わった時点で翌年度の大会表をつくり、3月は前の年度の選抜と新しい年度の春季県大会を同じ日付で進める（済）
5. 秋の結果から選抜を選考する（済）
6. 前の年度のゲーム内の結果を、翌春の予選免除・シードに使う（済）
7. 3年分を止まらずに進められることを確かめる（済）

**試合経過の要点**（2026-10-21 決定）：1打席ごとの記録は残さず、得点が入った打席（誰が・何回に・どんな打撃結果で・何点）、本塁打、投手交代だけを残す。スコア・イニングごとの得点・個人成績は今までどおり残す。保存先は試合の履歴（`historical_match_archive.py`）で、セーブには入れない。目安は1年分で20MB以内（超える場合は甲子園・神宮・地区大会と県大会の準々決勝以降に絞る）。実装は `game_core/highlights.py`。2026年度1年分（13,517試合）で約7.6MBだったので、全試合で残す。

**開始配置と交代履歴**（2026-10-29）：両校の確定した先発9人・実守備位置・先発投手と、成功した変更の連番・学校・回・表裏・次の打席番号・退場／新出場者・継承打順・位置別差分をA方式履歴へ残す。各表裏の打席数だけを既存のイニング記録へ追加し、全打席を保存せず時点と守備出場を照合する。投手交代の要点は圧縮時に履歴への参照へ置き換え、読込時に元の表示形式へ戻す。守備のみの出場を区別するIDは公式戦経験・怪我の出場判定にも使う（§3.1・§3.2）。

**試合の履歴の容量**（2026-10-21 決定）：個人成績などの表は列名を1回だけ書いて詰めて保存する（中身は同じ。`historical_match_archive.py` の `compact_payload`／`expand_payload`）。2026年度1年分で約160MB → 約85MB。

**自動セーブ**（2026-10-21 決定）：1日ずつ進めるときは毎日、まとめて進めるとき（advance-to など）は1週間ごとと最後の1回。

## 9. 段階2（正式な画面）の方針（2026-10-22 決定）

### 方式（ADR-044）

- pywebview（WindowsのWebView2）で独立したウィンドウを開き、画面はHTML/CSS/JavaScriptで作る。PythonとSQLiteは今のまま
- Python側に「画面に出すデータをまとめて返す層」を作る。画面はそこからしかデータを読まない
- 画面は、遊んでいるセーブの内容を直接表示する（`season_cli` で作る別のSQLiteは使わない）
- 正式な画面ができたら、Tkの閲覧画面とそれ以外の試作の画面は削除する
- READMEの「追加パッケージ不要」を直す（pywebview が必要になる）。EXE化（PyInstaller）は段階2の最後に行う

- 上の帯：ゲーム内の日付、「1日進める」ボタン、まとめて進めるボタン

## 10. 段階3a（初期の勢力図）の方針（2026-10-25 決定）

学校の評判（ゲーム開始時点の初期値）を実際の甲子園の出場から作り、選手の入部品質の学校成分（`school_intake` の `program_quality_z`）を評判から決める。学校の強さは選手から計算する（ADR-001・006 のまま）。

**材料（実際のデータ。`historical_data/`、読むだけ）**
- `koshien_entrants.csv`：1915〜2025年の夏・1924〜2026年の選抜・2022〜2025年の明治神宮大会の出場校（1959年以前は2026-10-26に追加）（日本高野連の出場校一覧。参照ブランチ `reference/power-map-input-20261025` から取り込み）。2026年の夏はゲーム開始後の出来事なので入れない。学校IDは都道府県と校名で学校マスター・`koshien_records.csv` の旧校名（notes）・`koshien_team_aliases.csv`（主な旧校名の対応）と照合し、照合できない行（PL学園など今の学校マスターにない学校、継承が保留の学校）は空欄で残して使わない。2022年選抜の京都国際は辞退（`withdrawn`）、近江を繰り上げ出場として足した
- `autumn_regional_entrants_2025.csv`：2025年秋の地区大会の出場校（二次資料）
- `koshien_records.csv`（通算）、`data/initial_state/2026/prior_results.csv`（2025年秋の都道府県大会の上位）
- 検証（`python -m historical_results.koshien`）：学校の都道府県が合う、出場の数が通算を超えない、通算に出場年の一覧があればその年に含まれる、ゲーム開始後の大会がない

**評判の点**（`game_core/school_reputation.py`、重みは `config/abilities/school_reputation_v1.json`）
- 年ごとの出場：夏1・春0.8・神宮0.4 に、2026年からの年数で減る重み（6年で半分）を掛けて足す
- 通算：年ごとの出場にない分（1959年以前・照合できなかった出場）、勝ち数・優勝回数を、最後の出場年で減らして足す
- 直前の結果：2026年選抜・2025年夏・2025年秋の地区大会・2025年秋の都道府県大会の上位に点を足す
- 全校に小さな乱数（0〜0.4、ゲームの乱数の種で決まる）を足す。甲子園に出たことのない学校は乱数だけで順位が決まり、県の上位校が生まれる余地を残す

**入部品質への反映**：評判の順位（下からの割合）を、`school_intake_v1` の学校成分と同じ平均・広がりの z（正規分布）に変える。学校マスターにない学校（テストの架空の学校など）は今までどおり乱数。年度ごとの当たり外れ（cohort）は乱数のまま。ゲーム開始時の在校生（1〜3年）にも効く。評判の差が試合に出るよう、学校成分と cohort の重みを 0.8:0.6 から 40/41:9/41 に、品質 z 1あたりの能力の差を3倍にした（`school_intake_v1` revision 2）。2026-10-31 からは、この z を新入生全員に一律に足さず、選手ごとの素質（z × 重み ＋ 選手ごとの乱数 ＋ 有望な新入生の上乗せ）を通して効かせる（§3.1「入学時の能力と選手の素質」）。学校能力のランクの境目（`screen_v1.json` の `ability_ranks`）は、全校の中の割合が前と同じになるよう広げた

**画面**：学校の詳細に評判のランク（S〜E。全校の中の割合で決める）を出す

**確認の目安**：夏の甲子園の出場校のうち初出場は実際（2016〜2025年の夏で約1割。`koshien_entrants.csv` から数えた）に近い程度。強豪校が毎年のように出るが、毎年同じ顔ぶれにはならない

**夏の地方大会の結果を足す（2026-10-26）**

## 11. 段階3（試合の規定と調整）の方針（2026-10-26）

進め方：現状の確認 → タイブレーク・コールド → 球数制限 → 実際との比較と調整。調整値は `config/` の JSON。

**規定**（`config/match/game_rules_v1.json`。試合ごとの規定は `AbilityMatchResolver.rules_for` が決める）
- タイブレーク：延長10回から無死一・二塁（2023年春から。[高校野球ドットコム](https://www.hb-nippon.com/articles/7271)）。打順は前の回から続け、一塁は先頭打者の1人前、二塁は2人前の打者。置いた走者の得点は自責点にしない。すべての試合
- 得点差コールド：5回終了で10点差以上・7回終了で7点差以上（後攻が勝っているときは表が終わった時点）。都道府県大会・地区大会で使い、本大会の決勝は使わない。神奈川は準決勝から使わない。甲子園（選抜・選手権）と明治神宮大会は使わない（[J:COM 高校野球観戦ナビ](https://www2.myjcom.jp/special/tv/sports/baseball/highschool/column_hsbb/calledgame/)）。都道府県ごとの細かな違いは大会要項を確かめたら `prefecture_exclude_rounds_from_end` に足す
- 球数制限：1人の投手は、試合の日を含む7日間に500球まで。すべての公式戦で使い、年度をまたいでも数える（3月の選抜と4月の春季大会）。上限に届いた打者の打撃が終わるまでは投げられ、次の打者から交代する（[高校野球ドットコム](https://www.hb-nippon.com/articles/2629)、[センバツLIVE！](https://news.yahoo.co.jp/articles/0df36cffe66cbcf8e7fa7b297250d82b0d2cbd3b)）

**球数**（2026-10-26）
