# Stage43G-81：v2学校索引の健全性監査と安全な版別再構築

作成日：2026-10-12

## 背景
Stage43G-79の索引は、封印済み架空v2の完全A試合から作る**派生データ**であり、原本を上書きしない。Stage43G-80のTkinter試験GUIでは、利用者が明示的に索引を選択する場合だけ使用し、不整合は拒否する。

年月経過により年度が追加された、索引が壊れた、あるいは古い範囲で作られている状況を区別し、**原本にも既存の派生索引にも手を加えず**安全に新しい索引を用意する。

## 読み取り専用健全性監査

`audit_v2_school_index_health(v2_path, calendar_path, index_path)` は、原本・カレンダー・索引をmode=roで参照する。索引がない場合に自動生成はしない。保存済みの全年度ヘッダを独立取得し、索引metadataに保存された出典絶対パスと年度範囲を確認する。対象となる**全保存済み年度の原本JSON SHAと学校所属を全件検証し、派生索引のすべての会員行を原本と一致照合する**。

| 状態 | 意味 |
|---|---|
| `ready` | すべての保存済み年度が索引範囲内で、年度ヘッダ・calendar・ledger・全試合SHA・所属校索引一致まで証明 |
| `missing_index` | 派生索引がない。新規作成は別操作のみ |
| `extension_required` | 既存索引対象の全原本検証は成功したが、新しく保存された年度が索引外 |
| `unsealed_source_years` | 未封印年度が存在し、完成済み索引として扱えない |
| `integrity_conflict` | 原本・calendar・ledger・索引の不整合、出典違い、破損等 |
| `empty_source` | 保存済み年度が存在しない |

監査結果に`strict_original_payloads_verified`と`strict_derived_memberships_verified`を別々に記録する。原本・カレンダー・索引のSHA256前後比較も行う。検証範囲を省略して「現在の全履歴が索引済み」と表示しない。

## 安全な新しい索引版の作成

`prepare_versioned_v2_school_index(v2_path, calendar_path, existing_index_path, new_index_path)` は**明示的に呼び出す場合のみ**実行する。

1. 保存元と旧索引の健全性を読み取り専用で調査。未封印年度や空の原本を拒否。
2. 10000年以降の保存済み全年度が100年度以内に収まることを確認。期間を超える場合は本APIは拒否し、複数期間索引は後工程で設計する。
3. 新しいファイル名が既存ファイルと一致・重複しないことを保証。旧索引が破損していても変更せず保持する。
4. Stage43G-79の全原本SHA照合を使って**新しいパスにだけ**索引を作成。新索引を全件検証し、既存ファイル群のSHAが変わらないことを確認。
5. 新索引を既存のGUIへ**自動適用しない**。現在のTk試験GUIが参照する既定ファイル名を自動変更しない。後工程で明示的な版選択・切替を別途設計する。

不正な原本から新索引を復元して正しいことにすることはなく、原本の完全性が証明できないときは作成しない。保存済みの旧A方式と混合しない。

## テスト
合成完全A原本で以下を検査。

- 索引未作成の報告と原本のSHA不変
- 10000・10001年度の既存索引の厳密監査
- 10002年度が保存された場合の拡張必要判定と新しい索引作成
- 索引の学校所属改ざん、原本JSON改ざんを拒否
- 未封印年度を追加した場合の安全拒否
- 既存索引、新パスのファイル、原本・カレンダーへの上書き禁止
- Stage43G-79の元API回帰

## 制約・次工程
この工程は実際の全国3000校・100年以上の本番セーブでの性能や実大会進行を実証しない。また100年を超える年度範囲を1ファイルに押し込まない。今回作成した版別索引をGUIで選べるようにする場合には、出典パスをセーブ単位で独立管理する設計が必要。
