## 条件付き敗者復活ゲートの純粋な評価エンジン

`phase2_engine/hiroshima_conditional_retry_gates.py`に、**実ゲームruntimeへ接続しない試験用の単独コンポーネント**を追加した。年度固定校名も史実のカードも不要。

1. `entrant:任意ID`：まだ試合に登場していない参加学校（合同チームなら一参加単位）。
2. `winner:gateID`：上流ゲート勝者を参照。上流の`winner_to_gate`で**指定した同じ次ゲート**から参照された場合のみ入場可能。既に県大会出場権を与えた勝者は再参加を禁止。
3. `loser:gateID`：上流ゲート敗者を参照。上流の`loser_to_gate`が**指定した次ゲート**と一致する場合のみ再挑戦を許可。それ以外の敗戦は自動的に移動させない。
4. 試合の勝敗は外部から受け取り、評価器自体は予め記録した2026年の勝者を利用せず、任意のチームIDで動作する。
5. 各試合IDとチーム参加の重複を禁止。資格獲得済み校の再登場、対戦相手ではない学校の勝利、年度別出場枠の超過・不足、未消費の進出経路、未存在ゲートへの経路、先に存在しない結果の参照を拒否。
6. ゲート種は`zone_runner_up`、`cross_zone_decider`、`conditional_retry_decider`の3種に限定し、**資格確定後の任意順位戦を生成しない**。

### 純粋な動作例（史実から学校名を使わない）

```
G1: entrant:A 対 entrant:B  → 勝者Aが代表獲得
    敗者Bの移動先をG2と明示

G2: loser:G1（B）対 entrant:C → 勝者Bが代表獲得

結果: 代表2校（A・B）
```

G1で敗者の移動先を指定しなければ、G2で`loser:G1`を参照する操作は例外となる。G2でBではなくCが勝つ入力なら、代表はA・Cになる。**この試作の結果はゲーム本体の抽選・試合へは反映されない。**

## 互換性と今後のブロッカー

現行FMT025は一次予選と敗者復活の森林構造によって、地区ごとの出場枠数を返せるが、各ゾーンの敗戦→後続ゲートの個別経路は公式抽選図で確定していない。

試作のデータ契約は、公式抽選・大会要項などの別根拠で年度非依存ルート条件が整備され、初めて実行runtimeへ接続する想定。**現状でゲーム本体へ有効化することはしない**。出場枠64（春西選抜免除1、予選63）、過去のlegacy/lazy等価テスト、任意順位戦未実行を保護する。
