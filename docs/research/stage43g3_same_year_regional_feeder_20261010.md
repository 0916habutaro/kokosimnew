# Stage 43G-3：同一年の春季県大会結果から春季地区大会への進出資格を検証

作成日：2026-10-10  
依存：Stage43G-2（PR #143、mainマージ済み・マージ後CI成功）  
成果の範囲：**県大会で試合を終えた学校の資格を証拠付きで算出するread model**。地区大会そのものの年度別組合せ・実行・保存まで完了したわけではない。

## 1. 目的・対象

Stage43G-2で茨城・埼玉の2027年春県大会を同一ゲームスロット／年度に保存・再開できるようになった。次は2027年の試合勝敗から、後続の春季関東地区大会（`CMP000006`）への進出校を確定する。

既存の2026マスター `data/competitions/regional_feeder_rules.csv` は関東地区の8都県17校を定義している。

| 元大会 | 2026方式の進出枠 |
|---|---:|
| 茨城県春 `CMP000084` | 上位2校 |
| 栃木県春 `CMP000086` | 上位2校 |
| 群馬県春 `CMP000088` | 上位2校 |
| 埼玉県春 `CMP000090` | 上位2校 |
| 千葉県春 `CMP000092` | 上位3校 |
| 東京都春 `CMP000094` | 上位2校 |
| 神奈川県春 `CMP000095` | 上位2校 |
| 山梨県春 `CMP000105` | 上位2校 |
| **合計** | **17校** |

今回は2027ゲーム内試験大会として、**茨城県春・埼玉県春の上位2校ずつ、計4校**を確定したゲーム試合から照合する。残る6都県13校については、未プレイ・未登録として保留する。

なお、千葉の2026方式の上位3校枠は、3位決定戦なしの準決勝敗退2校が同順位となる場合がある。既存`CompetitionRun.outcome.final_ranking_school_ids`の見かけ上の並びだけで3位を確定したと誤認しないため、**3位の明確な決定ルールが確認されるまで、その枠は未解決**とする。

## 2. 実装したread model

`phase2_engine.same_year_regional_feeder_gate.project_same_year_regional_feeders(service,session,destination_competition_id)`

処理順：

1. 対象はゲーム内2027年以降で、登録済み`spring_regional`大会のMAINステージのみ。
2. `regional_feeder_rules.csv`の該当する全ルールを取得し、県大会`spring_prefectural`、`rank_range`、当年直接出場枠、指定件数とMAIN枠合計の一致を確認。
3. **処理済み日付・seed・出場校・初期計画の完全なidentity**がチェックポイントJSONと一致し、セーブ済みのセッションであることを確認。
4. `historical_matches.sqlite3`内の当年`career_years`のstatus・rng_seed・resolver_contract・plan_fingerprintを検証。前年のsealed台帳も変更されていないことを検証。
5. 完了した`CompetitionRun`のMAIN全試合、優勝・準優勝、順位表を検証し、履歴SQLiteに保存された同年度の全MAIN試合の対戦・勝敗・fingerprintと一致する場合にだけ県大会の上位2校を抽出。
6. 試合日が対象年度内にあり、2026マスターの関東地区日程を年だけ投影した**ゲーム内仮地区大会開始日**より前に県大会が終了していることを検証。
7. 重複校・異県所属を拒否して、各ルールに`verified_game_qualification`または`source_not_completed`／`source_not_in_preview`／`ranking_cutoff_requires_tiebreak_rule`の状態を設定。
8. 地区大会が全出場校を揃えていない限り`all_feeder_results_verified=false`。**今回のread modelは`regional_runtime_ready=false`・`automatic_qualification_committed=false`を維持**し、勝手に後続の大会を起動しない。

出力には、ルールID・元大会ID・出場枠・学校ID・試合manifestに由来するSHA-256証拠を含む。年次公式資料から未確認の2027大会の日程・出場校を作り出さない。

## 3. テスト

`tests/test_stage43g2_multi_competition_checkpoint.py`にStage43G-3用の5件を追加。

- 両県大会の未完了時：17枠はすべて未確定、8ルールそれぞれの未解決理由が得られる。
- 茨城の本戦が終了した時点：茨城の上位2校だけを試合・履歴から検証し、埼玉の結果は未解決。
- 茨城と埼玉の両大会が終了後：同じ2027ゲームスロットの履歴と照合した**4校**を認証し、残り6ルール13枠が未解決のままであることを確認。
- 当年の保存済みMAIN試合fingerprintを後から改変した場合：結果の信頼を取り消して資格の読み出しを拒否。
- 大会未登録・地域が異なる・古いセッションでread modelを参照する場合：安全に拒否。

## 4. 続きのStage43G-4で必要なこと

- 春季関東大会の残り6都県すべてをゲーム内で完了させ、全17校の資格を確定する。千葉の3位タイや同順位の処理を含む大会ごとの最終順位・代表枠の決定ルールを明示する。
- 学校の2027年地区所属・合同チーム・休廃部を年度別ゲーム用学校マスターで管理する。
- 関東地区大会`CMP000006`の2027仮日程・17校の組合せ・選手ロスターを実験用年度ランタイムに追加する。その際、シード権は資格と独立し、前大会順位を自動シードへ変換しない。
- 完了した同年の複数大会`CompetitionRun`を履歴に確定保存し、年末の全大会終了後に2027年度を封印する。
- 2026→2027の本編`LiveGameService`切替、全国162大会、甲子園・センバツを含む正式ゲーム進行とGUIへの反映は、引き続き未実装。

**今回の完成ラインは「同じ2027年のゲーム内春県大会の実結果が、春季関東地区大会の進出資格4校を検証可能にする」であり、地区大会の実行開始ではない。**
