# Stage 43F-7：岐阜FMT002・東京一次予選と前年秋出場資格の接続

作成日：2026-10-10。前工程：Stage 43F-6 PR #140（main反映済）。
適用範囲：**ゲーム内2027年度以降の明示入力sandbox大会**。2027年度の公式大会・出場校を認証する機能ではない。

## 1. 実装対象と出場資格

2026方式マスターの`competition_access_rules.csv`と`competition_stage_format_assignments.csv`には、次の前年秋の進出資格が収録されている。

| 翌春大会 | 規則 | 前年秋から直接MAIN | 翌春の予選方式 | 県・地区代表 |
|---|---|---:|---|---:|
| 岐阜 `CMP000109` | `ACR000010` | 4校 | `BRANCH_QUALIFIER/FMT002`・4地区 | 8＋4＋5＋3＝20校 |
| 東京 `CMP000094` | `ACR000020` | 64校 | `PRELIMINARY_QUALIFIER/FMT001`・47独立ブロック | 47校 |

Stage43F-5/6では`BRANCH_QUALIFIER/FMT001`に限定していたアダプタを、これら2方式に対して**大会ID・ステージコード・方式・出場枠を明示検証したうえで**使用可能とする。

- 岐阜は、各地区FMT002の第1次試合と敗者復活戦の内部進行を、既存`CompositeQualifierGroupRuntime`へ任せる。橋渡し側は代表や結果を先に決めない。
- 東京は、前年秋の64校を一次予選から除外し、明示入力された残校を47ブロックに分けてFMT001の試合を行う。決まった47代表と直接64校をMAINで合流させ、111校で進める。
- いずれも、前年秋順位を**翌春第1シードなどに変換しない**。`main_seed_school_ids=[]`のまま、リンクしたシードルールが未検証なら拒否する。
- 仮日程はStage43Fの`game_projection_v1`であり、出場校・ロスター・組合せもすべてゲーム内のsandbox入力として扱う。

## 2. 東京都の前年秋マスター欠落：追加の重要な制約

現行の`data/competitions/competitions.csv`には、東京の`CMP000094`春季大会行はあるものの、対応する**2026東京都秋季本大会`autumn_prefectural`行が存在しない**。2026年度の東京都秋の参加校64校を大会マスターから自動で取得したと表現することはできない。

このため、東京は`prior_source_competition_id`を**明示して呼び出すsandboxモード**に限り起動できる。指定IDのゲーム内大会について、Stage43F-4の`CareerCompetitionOutcomes`に次の全条件を満たす前年秋の結果が存在しなければ拒否する。

1. 対象年`year-1`が`HistoricalMatchArchive`でsealed済みかつ年次SHA-256台帳が一致。
2. 指定したゲーム内秋季大会で、優勝・準優勝と最終ランキング、**すべてのMAIN対戦結果**が履歴DBの同年度・同試合に一致。
3. 少なくとも64校の順位があり、上位64校が当該年の東京所属・硬式加盟校として入力され、予選対象と重複しない。
4. 東京の47ブロック代表と合わせてMAIN合計が111校となる。対象大会にない2026年度の地区予選・シードを勝手に加えない。

例：`prior_source_competition_id="GAME-TOKYO-AUTUMN-2026"`は、試験用として過去年に実際にゲームが完了し、試合と順位を保存・封印した場合だけ使える**ゲーム用ID**。実在の2026秋季東京都大会を登録・再現した識別子ではない。

正式な長期年度進行へ接続する際は、**東京秋大会を年度別大会マスターへ追加して大会ID・出場校・代表抽出ルールを構造化する工程が必要**であり、この明示指定を本番の自動認定処理に置き換えてはいけない。

## 3. 実装と互換性

`phase2_engine/future_prior_autumn_access_bridge.py`：

- `_check_rule`で既存のbranch bypassに加えて`grant_main_entry_bypass_preliminary_qualifier`を受け付け、アクションとステージの組合せを照合。
- `CMP000109`のFMT002、`CMP000094`のPRELIMINARY/FMT001だけを追加解禁。他県の未知FMT002、想定外のステージ・混合方式は明示的に拒否。
- 予選ステージ日付を動的な`qualifier_code`で指定し、予選→MAINの会期を分離。東京はMAIN111校と秋64校を件数照合。
- FMT002は一次トーナメントと敗者復活の日付が不足した場合に起動しない。各組の代表は既存コンポジットエンジンが決定。
- 前年の封印済み秋大会・年度別選手ロスター・出場校の県内登録を検証し、古い2026学校所属を流用しない。
- 茨城・埼玉・千葉・岡山の従来4県の`BRANCH_QUALIFIER/FMT001`は変更しない。

`tests/test_stage43f7_gifu_tokyo_access.py`：

- 岐阜のゲーム内44校（前秋4校＋地区参加40校）で、FMT002の予選内部試合を通して地区代表20校と直接4校でMAIN24校へ接続。
- 東京のゲーム内112校（前年秋の封印済み秋季大会64校＋一次予選48校）で、47ブロックから47代表、直接64校とMAIN111校へ接続。
- 2026秋季大会はすべて**自動生成した試験用結果**として実際のMAIN対戦を保存・照合し、年次封印済みSQLiteを使用。東京秋はゲーム用仮IDであり2026史実ではない。
- 同じseedで日程・組み合わせが再現し、A方式個人成績に2027年ロスターのplayer_idが利用されることを確認。
- 東京の前年秋結果の明示指定欠落、封印済み結果の学校数不足、岐阜への不適切な上書き、別県所属、継続ロスター欠損を拒否。
