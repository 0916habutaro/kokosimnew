# Stage 43G-57：長期履歴の年度検索最適化と正式GUI要件の整理

作成日：2026-10-11

## 前提・今回の成果

- #195/#196/#197：2027年架空ゲームの東海4県・東海地区大会をA方式で保存し、Tkinter試験GUIへ接続済み。
- #198（Stage43G-56）：保存済み年度の画面5経路の実測probe。全国3,000校・100年の大会実行を実証するものではない。
- 本Stageは**年度選択と大会概要の取得経路の小規模な最適化**。正式GUIを現時点で構築・切り替えない。既存保存SQLiteを変更しない。

### コード変更

1. CareerTokaiSeasonBrowseModel._year の年度存在確認を、全年度を取得してPython側でsetを作る方式から career_years のPRIMARY KEYの1件検索へ変更する。保存年数が増えても年度検証で全年度を展開しない。
2. 大会概要 overview の6大会別集計を、SHA照合済みの試合一覧を6回絞り込む方式から、一度走査して「保存試合数／参加が確認できる学校ID集合／最後の保存日」を集計する方式へ変更する。
3. _games のSHA-256・保存年度／大会／試合／対戦校ID照合は従来どおり必ず実行する。**一度検証しただけの結果を無期限キャッシュして改ざん検知を迂回しない**。
4. 既存Stage43G-54のfixtureで「年度全件列挙が呼ばれない」「SQLiteの主キー検索計画」「大会ごとの件数と日付が維持される」「元SQLite不変」をCI監査する。

## 正式ゲームGUI要件案（実装は後工程）

### 画面と機能区分

| 画面 | 必須項目 | 読み取りデータ |
|---|---|---|
| ホーム／保存枠 | セーブ枠、進行年度、進行日、保存／再開状態、閲覧導線 | ゲーム用セーブの明示的なID |
| 日付別試合 | 日付、地域、大会、カード、スコア、続きの試合、未実行・終了区別 | 年度カレンダーと保存試合 |
| 大会 | 春／夏／秋、県・地区・全国大会、ラウンド、トーナメント表、参加資格の由来 | マスターと進行runtime、保存済み結果 |
| 学校 | 実在名称と固定学校ID、地区、該当年度の出場大会・戦績、歴代結果 | 学校マスター、年度別A履歴 |
| 試合 | スコア、イニング別得点、打者・投手個人成績、対戦校へのリンク | 保存済みA方式のみ。打席単位ログは捏造しない |
| 選手 | 架空選手名、所属年度・所属学校、年度別・通算成績、在籍履歴 | 年度別保存ロスター、A方式個人成績 |
| 記録集 | 大会記録、学校別通算、選手別歴代ランキング、年度比較 | 封印済み履歴と明示的な集計規則 |
| 設定／診断 | 年度・表示件数、保存整合・読み取り診断、エラー説明 | 閲覧専用probe／健全性診断 |

- **ゲーム操作と記録閲覧を明確に分離**：ゲーム日付進行、試合生成、年度更新は明示的操作とし、閲覧／検索中に勝手に進めない。
- ゲーム内架空結果と、公式資料に基づく2026年大会方式・現実の加盟校資料は情報源ラベルを分ける。実際の2027年の大会結果を表示しているような表示は禁止。
- 画面遷移は学校ID・選手ID・年度・大会ID・試合IDで行い、学校改称・同名・過去所属に耐える設計とする。
- 大会方式固有の画面にはプラグイン／read modelのAPIを用意。県別・地区別の例外条件をGUIコードへハードコードしない。
- 試験用Tkinterを正式デザインと見なさない。GUIフレームワークの最終選択と見た目・操作系は別途レビューする。

### 長期運用・メモリ管理の契約

- ゲーム進行年数は無制限を設計上の目標とする。ただし年のISO日付表現、年数依存のデータ量、インデックス維持、セーブ移行等は検証・設計が必要。「100年完走確認済み」と誤表示しない。
- ユーザーが閲覧するのは必ず要求ページのみ（現状の試験GUIは30件単位）。全国の全試合・全選手を1画面に載せない。総件数とページ境界、未保存状態を区別。
- 再集計・キャッシュ導入時はソース保存SHA／封印年度ledgerを照合。古いキャッシュは無効化し、出所不明の数値を表示しない。
- 異なる年度の同名学校や複数セーブの選手IDを混同しない。未プレイ年度・未保存試合を埋める補完処理は導入しない。
- 書き込み対象はゲーム進行runtimeだけとする。閲覧モデルはmode=ro + query_onlyを維持し、既存SQLiteとsidecarに副作用を残さない。
