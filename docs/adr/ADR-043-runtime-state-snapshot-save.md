# ADR-043: セーブは進行中の状態をそのまま書き出し、読込で計算し直さない

- 状態: Accepted
- 日付: 2026-10-21
- 置き換え: ADR-026（読込時に最初から計算し直す方式）
- 関連: game_definition.md §6、§8（速さの目標）

## 背景

ADR-026 はセーブにseedと進行日だけを残し、読込のたびに最初の日から試合を計算し直していた。全国の試合を選手で行うと1年分の計算に十数分かかり、読込も同じだけかかる。複数年・成長・怪我が加わるとさらに重くなる。速さの目標は「セーブの読込は数秒以内」。

ADR-026 が避けたかった「内部構造が変わると読めなくなる」点は、開発中は旧セーブとの互換性を持たない方針（§5）になったので問題にならない。

## 決定

- セーブ（`live_season_save.py`、schema `live-season-save.v2`）は、進行中の年度の状態（`LiveSeasonDependencyRuntimeState`）を `phase2_engine/runtime_snapshot.py` で pickle・圧縮して、JSONの `runtime_state` に入れる
- データ（`DataRepository`）・試合の進め方（engine）・大会の入力をつくる部品は書き出さず、読込時に今のものをつなぎ直す
- 読込では計画（大会表）を作り直して `plan_fingerprint` を確かめ、状態を戻すだけにする。試合はやり直さない
- 形式が違うセーブは読み込まない。変換（migration）の仕組みは削除した
- pickle を使うので、読み込むのは自分のゲームが書いたセーブだけにする（個人用・Windows専用の前提）

## 帰結

- 2026年10月末まで進めた全国のゲームで、セーブ約1.3秒・読込約0.7秒・ファイル約2MB
- 内部のクラスを変えると古いセーブは読めなくなる。開発中は新規開始し直す
- 名簿は今のところseedから毎回同じものが作れるので、セーブに入れていない。成長・怪我など毎年変わる情報が入ったら、名簿もセーブに含める（2026-10-26 に入れた。下の追記）

## 追記（全国の試合を選手で行う、2026-10-21）

- 大会の進行が直接持っている試合の決め方（`main_match_resolver` / `pre_main_match_resolver`）も、engine と同じく書き出さず読込時につなぐ。名簿・能力のキャッシュをセーブに入れないため
- 選手で行った試合のスコア・個人成績は、大会の進行には持たせず状態の `pending_match_details` に置く。セーブのたびに履歴（`historical_match_archive.py`）へ保存して消し、試合に `archived` の印をつける。履歴へはまだ保存していない試合だけを送る（増分）
- 1打席ごとの記録は残さない（履歴にも保存していなかった）
- 測定（2026年度を1年分、選手で全国の試合）：進行 約133秒（準備 約22秒）、試合がいちばん多い日 約6.5秒、セーブ 約1秒、読込 約0.3秒（毎日の自動セーブで保存待ちの記録が少ないとき）

## 追記（名簿をセーブに入れる、2026-10-26）

成長（game_definition.md §3.1）で選手の能力が試合や月ごとに変わると、乱数の種から名簿を作り直せなくなる。その準備として名簿をセーブに入れた。

- 名簿（`game_core/roster_book.py` の `RosterBook`）は `CareerState.rosters` としてセーブに入る。年度・学校ごとに、選手の名前・出身・守備位置・投打と能力（1項目1バイト）を詰めて持つ。選手IDは乱数の種・学校・入学年度・番号から作り直す
- 乱数の種から作るのは新規開始の部員と新入生だけ。進級した選手は前の年度の名簿から引き継ぐ（成長ができるまでは、進級のときに学年の差 `grade_adjustment` を能力に足す）
- 試合と画面の能力は名簿から読む（`SchoolAwarePlayerAbilityGenerator.source`）。学校の編集の補正はその上に足す
- 前の年度の名簿は、その年度に始まった大会（3月に始まる春季県大会）がすべて終わったら、試合履歴の `closed_rosters` に書き出してセーブから手放す。閉じた年度の試合の選手名はそこから出す
- 測定（全国の試合を選手で3年分、2026年4月〜2029年4月1日、セーブの直前にもう一度セーブして試合の記録を履歴に書き出したあと）：セーブ 5.3〜8.2MB（名簿が約3.8MB。いちばん大きいのは2つの年度が重なる3月末）、セーブ 0.4〜1.5秒、読込 0.3〜2.0秒。新規開始 約26秒（最初の部員の能力をつくる）
