# ココシミュNew：閲覧画面と遷移の構想（Stage 42）

更新日：2026-10-10  
**位置づけ：機能構想と画面間の関係図。正式GUIの画面設計・Tkウィジェット配置の決定ではない。**

機能の正本：`docs/design/viewing_feature_catalog_stage42.csv`  
概要：`docs/design/viewing_features.md`

## 1. 閲覧機能の情報構造

```text
ホーム（年度・シーズン概要）
├─ 日付別試合一覧 ───────┬─ 試合詳細［候補］ ──┬─ 学校詳細/年度別戦績
│                        │                      └─ 選手詳細［試合ログは今後］
│                        └─ 大会結果 ──────────────┬─ トーナメント表
├─ 大会一覧 ─────────────┘                          ├─ 大会別ランキング ── 選手詳細
│                                                   └─ 予選進行［試験プレビュー限定］
├─ 学校検索 ── 学校詳細/年度別戦績 ──┬─ 学校試合履歴 ── 大会結果
│                                  └─ ロスター ── 選手詳細
├─ 選手検索 ── 選手詳細 ── 学校へ
├─ ランキング ── 大会別打撃/投手 ── 選手詳細
└─ 歴史・年度推移／比較・分析／データ出力 ［今後の候補］
```

**現在の簡易GUIは `Stage13D3BrowseApp` のホーム・日付別試合・大会結果・学校戦績・選手/ロスター・個人成績ランキングを基本タブとして持つ。** 広島の予選進行表示は専用の試験別窓であり、正式ゲームの大会結果と同等の機能ではない。

## 2. 想定ナビゲーションと対応ID

| 出発 | 操作 | 移動先 | 持ち越す条件 | 現在の判定 |
|---|---|---|---|---|
| ホーム | 試合日を選択 | 日付別試合 | `year,match_date` | 簡易GUIあり `VIEW-DATE-001` |
| 日付別 | 対象大会の結果を開く | 大会詳細 | `year,competition_id` | 簡易GUIに導線あり `VIEW-NAV-003` |
| 日付別 | 試合そのものを開く | 試合詳細 | `year,competition_id,match_id` | 今後 `VIEW-MATCH-002` |
| 大会一覧 | 大会を選ぶ | 大会詳細・ブラケット | `year,competition_id` | 簡易GUIあり `VIEW-TOUR-001`, `003` |
| 大会詳細 | この大会のランキングを表示 | 大会ランキング | `year,competition_id` | 簡易GUIあり `VIEW-NAV-002` |
| 大会ランキング | 選手を選ぶ | 選手詳細 | `year,player_id,competition_id` | 簡易GUIあり `VIEW-NAV-002` |
| 学校検索 | 学校を選ぶ | 学校年度別戦績 | `year,school_id` | 簡易GUIあり `VIEW-SCHOOL-001` |
| 学校戦績 | 試合履歴を選ぶ | 大会詳細 | `year,competition_id,match_id` | 簡易GUIあり `VIEW-SCHOOL-003` |
| 学校戦績 | ロスター・成績を開く | 学校ロスター | `year,school_id` | 簡易GUIあり `VIEW-NAV-001` |
| 学校ロスター | 選手を選ぶ | 選手詳細 | `year,player_id` | 簡易GUIあり `VIEW-NAV-001` |
| 選手詳細 | 学校名を選ぶ | 学校年度別戦績 | `year,school_id` | 正式な戻り導線はStage44検討 |
| 学校詳細 | 別の年度へ切替 | 同一学校の別年度 | `school_id`のみ保持、`year`を更新 | 候補 `VIEW-SCHOOL-008` |
| 広島秋西試験 | 学校を選ぶ | 2026既存SQLite学校戦績 | `school_id,year=2026,prefecture=34` | Stage40の限定・厳格な安全遷移 |
| SQLite学校戦績 | 試験プレビューへ戻る | 同じ既存試験別窓 | 生きている既存チェックポイントのみ | Stage41の限定戻り導線 |
| 試験プレビュー | 試合結果を段階公開 | 同じプレビュー | `checkpoint`、出典 | **事前登録結果の公開**。新規試合生成ではない |

ここで示す移動先の「試合詳細」は**完成済みとは限らない**。今後実装する候補の画面も、必要な連携を見落とさないように構想として掲載している。

## 3. 画面間で受け渡すID契約案

| キー | 意味 | 注意事項 |
|---|---|---|
| `year` | ゲームの年度 | OSの日付や史実資料の公開年に勝手に置換しない |
| `school_id` | 正式な学校マスターの恒久キー | 表示名、略称、自治体名の部分一致からIDを類推しない |
| `player_id` | 選手を区別するキー | 同名を区別できるが、年度跨ぎの継続性は別途確認 |
| `competition_id` | 大会を識別するキー | 春/夏/秋と年度、大会instanceの扱いを保つ |
| `match_id` | 大会内の試合キー | 単独では一意と仮定せず `year + competition_id + match_id` を使う |
| `match_date` | 結果の日付 | 公式未確定の場合は空欄・未定のまま |
| `source_kind` / `evidence_grade` | 史実二次/生成/公式確認状況 | provenanceを落として通常のゲーム結果に混ぜない |
| `checkpoint` | 試験プレビューの段階状態 | 生の勝敗情報をUI側で新規生成しない |

ゲーム本体と史実閲覧は**異なる名前空間**。例えば学校が同一でも、ゲーム内SQLiteの試合は生成・保存されたシーズン結果であり、広島2026二次史実プレビューの試合とは同一レコードとして合算しない。

## 4. 画面状態と戻り方の原則

- **年度は明示変更のみ**。学校検索や試合の遷移だけで2026へ黙って戻さない。
- **検索/絞り込みの復元**：不正なIDやDB未収録に当たった場合は元の検索条件を保持。戻る導線を統一するか、画面ごとの検索状態を保持するかはStage44で決定。
- **正本IDを検証**：スクリーンの表示名やTreeviewの見た目の行番号で学校・選手を確定しない。
- **実際に存在する対象だけ開く**：0件・対象外・別年度の場合は警告/未収録。別の学校へフォールバックしない。
- **準備中は準備中と明示**：予選で対戦校が確定するまで学校名を公開せず、任意順位戦や公式不明の矢印を県大会の出場権確定経路として描かない。
- **複数年度の選手ID**：卒業・進級・キャリアの仕様を検証するまでは年度を跨いだ同一選手として自動集計しない。
- **現在時点の能力**：能力snapshotは時点や起用で変化する。学校マスター固定値として表示しない。

## 5. 正式GUIへ移るときの検討事項（Stage44へ）

| 論点 | Stage42で決めること | Stage44で決めること |
|---|---|---|
| 上位画面 | ホーム・日付・大会・学校・選手・ランキング・歴史の機能領域 | タブ/サイドバー/パンくずの配置、戻り履歴 |
| 試合詳細 | スコア/イベント/試合個人成績を閲覧したい | 一画面にどこまで載せるか |
| 大会方式 | MAIN/ブロック/敗者復活/代表決定/順位戦の種別が必要 | 方式ごとの表現・ズーム・グループ分割 |
| 学校・選手 | 正式IDと年度の文脈が必要 | カード・表・比較のデザイン |
| ランキング | 指標、規定、ソート、対象大会が必要 | 指標切替・並べ替えUI |
| 検索 | 検索対象と保持すべきIDが必要 | 全体検索、ページング、絞込のレイアウト |
| 実機 | Windows Tk/DPI/日本語入力の手動確認が必要 | 正式GUIの目標表示サイズと受入基準 |

**正式GUIの採用技術、色、画像、画面配置は今回決定しない。** 閲覧データ契約を先に安定させ、試作UIは設計検証用として維持する。
