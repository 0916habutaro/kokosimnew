# Stage 13E-3G-5 調査・実装報告（2026-10-08）

## 概要

静岡春季西部地区の実試合参照には、4月4日と4月11日のように**同じ地区で複数日の順位決定戦**が含まれている。3G-4で地区ごとの学校ID・日付は特定済みだが、従来の保存契約では同じgroup_idを持つイベントが衝突した。

今回`RankingOnlyEventRuntime`に任意の`event_id`を付与し、明示されたイベントのみ日付＋地区で区別する。`ScheduledCompetitionRuntime`と`BrowseRepository`を同じ識別契約へ拡張し、試合の途中保存・再開・日別表示を実装した。

## 重要な仕様判断

- 旧snapshot・match_idは変更しない。`event_id`未指定は従来形式として読み込む。
- 同じ地区でも複数日イベントを独立し、先に保存した勝敗が消えることを回帰検査する。
- SQLiteの既存テーブルを破壊的変更しない。スナップショットだけ新テーブルを追加、試合テーブルは旧DBに追加列を移行。
- 順位戦の勝敗は代表・シード・MAIN進出に逆流しない。年間完了判定は通常の大会エンジンのみ。
- 2026の公式日付を使うFMT025実証アダプタは、対戦校の学校IDと代表確定済み集合の照合に成功した場合のみイベントを生成する。
