# Stage 43G-43：同年度センバツ後の北海道春季大会を共通年度セーブへ遅延追加

作成日：2026-10-11

## 背景と対応範囲
Stage43G-42は同じゲーム年度のセンバツ完了と、A方式の保存済み31試合を照合して北海道校を推薦対象にできる「資格ゲート」を実装した。ただし先行の `CareerMultiPreviewCheckpointService` は**年度開始時に全大会を確定**する設計で、同年度センバツの勝敗が決まる前に北海道春季の推薦校が確定できない。

今回、共通年度 `career_multi_previews/<year>.json` の既存仕様を壊さず、「センバツ終了後に `CMP000004` を一度だけ追加する」明示操作を追加する。

## 実装
- `CareerMultiPreviewCheckpointService.add_hokkaido_spring(session, group_entrant_school_ids=...)`
  - ベースの `CMP000001`（センバツ）が完了し、**同年度の元試合全31件がSQLiteに保存済み**でなければ追加不可。非北海道の出場校は推薦なし。
  - 2026年ルール `ACR000001` の適合、年度、参加32校、勝敗、打席／投手個人成績、試合日時、SHA、2027年度進級保存ロスターを `Stage43G-42` の証跡ゲートで再確認。
  - 北海道10支部の参加校を明示し、推薦校は支部の代表枠消費から除外。支部通過15＋センバツ北海道参加校数を将来年の動的なMAIN構成として使用する。
  - 既に進行済みの日付が北海道春季の2027年投影開始日（5月8日）に達している場合や、同大会の二重追加、古いチェックポイントからの操作を拒否。
- セーブ形式
  - 既存の `schema_version=2` を維持し、遅延追加した場合だけ `late_spring` を追加。
  - そのメタデータには **出典センバツ31試合のSHA、明示支部名簿、推薦校ID、最初のトーナメント状態のdigest、追加時の最終進行日**を保存。
  - **年度登録の `plan_fingerprint` は変更しない**。年度の基本2大会・初期スナップショット・前年度封印ledgerはそのまま維持。遅延追加イベントは追加メタデータのチェックサムで拘束。
  - `save` と `play_next_date` は新たな北海道春季大会を含めてA方式SQLiteに同期。既存の独立大会と同じ日付に試合があっても、同日付の各イベントを共通セーブ内で実行する。
  - `load` 時は登録当時の進行日時まで先行大会を決定論的に再実行し、同年センバツのSQLite実試合を検証してから春季大会を生成。保存した初期digest・出場権・全試合・各大会の進行日と結果を照合して不一致なら復元拒否。
  - 元の2026年度セーブ・元の大会記録・学校表示マスターを変更しない。

## 自動テスト
- 2026年度の空・封印済みサンドボックスからゲーム選手を2027年度へ進級。
- 同年度のセンバツ32校と四国8校の共通年度セーブで開始。センバツ31試合を完了させ、四国大会は未着手の状態から**北海道春季を後で追加**。
- 追加直後にロードし、四国と北海道春季の予定日が交互に進む状態を再ロードしながらテスト。全3大会を完了後、北海道春季のMAIN16校・15試合、A方式の打撃・投手成績、優勝校、学校別履歴から試合詳細の読み取りを照合。
- 旧年度封印ハッシュ、年度 `metadata_json`（固定 `plan_fingerprint`）、手動セーブ、閲覧前後のSQLite SHAを監査。
- 未完了センバツ、二重追加、異県学校混入、チェックサムを再計算した不正な推薦リスト、古いセッションからの重複追加は拒否。

## 位置付け
- 2027日付は2026年データの投影。実際の2027公式出場校・日程・結果ではない。学校IDは実在校マスター、能力・選手・試合はゲーム内で生成。
- 同一年度内のセンバツ→北海道春季について検証する専用サンドボックス。全国162大会を全自動で同年度に進める機能ではない。
- `plan_fingerprint` の不変性のため、遅延追加可能なのはホワイトリストの北海道春季 `CMP000004` だけ。他大会の無制限追加を許可しない。
- 多年運用性能・正式GUI・本番年度シーズンの自動大会進出は後続。
