# ココシミュNew ゲーム定義と実装計画

作成日: 2026-10-20 / 基準: main `6c13b74`（PR #302 マージ後）

この文書がゲームの目的・範囲・進め方の正本である。作業ルールは リポジトリ直下の `AGENTS.md` を参照。

## 1. ゲーム定義（ユーザー決定事項）

| 項目 | 内容 |
|---|---|
| 対象 | Windows専用、本人が遊ぶ個人用。配布・展開は考慮しない |
| 完成の基準 | ゲームとして遊べる状態 |
| 遊び方 | 日程を進めると、その日の全国の試合が処理される。結果・記録を眺める。監督としての指示や試合操作はない |
| 年度 | 4月開始。夏の予選 → 夏の甲子園 → 秋の予選（県・地区） → 神宮大会 → 選抜 → 春の予選 の循環 |
| 組み合わせ | 大会規則の範囲内で毎回ランダム |
| 選手の循環 | 新入生の入学と3年生の卒業を毎年行う |
| 成績 | 現在定めている範囲（個人成績・大会成績・学校戦績）を残す |
| 成長・怪我 | あり。練習の指示はないため、成長は仕組みで決める。強豪・常連だけが伸びすぎないようにする |
| 試合 | 実際の高校野球になるべく近づける |
| 初期状態 | 校名・能力・勢力図を実在に近づける |
| 履歴 | 大会結果・ベスト8一覧などを後から追える |
| 監督 | データを持つ。異動・退任があり、有名監督の学校は新入生の質がよくなる |
| 選手名 | 苗字は都道府県ごとのデータから選手の出身地に応じて選ぶ。名前はランダムだが、よくある名前ほど出やすい |

個人用・配布なしのため、**旧セーブとの互換性や旧形式の維持は不要**（§5で決定）。

## 3. 新しい仕組みの方針案

### 3.1 成長

練習の指示がないため、選手ごとに次の要素を持たせて自動で成長させる。

- **潜在能力（上限）**：入学時に決まる。分布は全校共通にし、無名校にも一定の確率で高い潜在の選手が現れる。
- **成長の型**：早熟・普通・晩成など。学年による伸び方の違い。
- **成長の時期**：毎月処理する。夏休みと冬（試合のない期間）を大きめにする。
- **試合経験**：公式戦の出場に応じて少し伸びる。

**強豪だけが伸びすぎない仕組み**：

1. 入部時の能力（入部品質）と、その後の成長量を分ける。強豪は入部時点の能力が高いが、成長量の学校差は小さくする。
2. 上限に近いほど伸びにくくする。差が開き続けない。
3. 出場機会を成長に反映する。強豪は控えが多く出場が少ない。弱い学校は1年生から出場して経験を積む。
4. 監督の育成力は小さめの補正にとどめる。

### 3.2 怪我

- 投球数・連投・年間の出場量から発生確率を決める。投手を重めにする。
- 程度（数日〜数か月）と、復帰までの能力低下を持たせる。重い怪我はまれにする。
- 球数制限（1週間500球以内）を大会規定として実装し、継投の判断にも使う。

### 3.3 勢力図の維持と変動

- 学校ごとに**評判**を持たせる。初期値は実績データから作り、毎年の成績で更新する（直近ほど重く）。
- 新入生の質 ＝ 学校の評判 ＋ 監督の評判 ＋ 年度ごとの当たり外れ。
- 評判が上がった学校には良い新入生が集まり、成績が落ちれば評判も下がる。これで「新しい強豪の誕生」と「名門の低迷」が起こる。
- 公立と私立で、県外からの入部の割合を変える。

### 3.4 監督

- 持つデータ：氏名、年齢、在任校と在任年数、評判（実績から更新）、育成力、継投や起用の傾向。
- 異動：公立は数年ごとに県内で異動。私立は長期在任が中心。
- 退任：年齢や在任年数に応じて退任し、後任が就く。
- 有名監督：評判が高いほど新入生の質が上がる。異動するとその効果も移る。
- 初期データ：実在の監督名を使うか、架空の名前にして評判だけ実在の勢力図に合わせるか（要決定、§5）。

### 3.5 選手名と出身地

- 苗字：都道府県ごとの頻度データから重み付きで選ぶ。
- 名前：年代別の人気の名前の頻度を重みにして選ぶ。よくある名前ほど出やすい。
- 出身地：基本は学校の所在県。私立強豪ほど県外出身の割合を上げる。苗字は出身地の都道府県のデータから選ぶ。
- データは出典付きで集める（苗字ランキング、名前ランキングの公開資料）。

### 3.6 試合の現実らしさ

1. 高校野球の規定を入れる：タイブレーク（10回から）、地方大会のコールド、球数制限。
2. 実際の試合結果（#302で収集）と比べる：得点の分布、点差、番狂わせの頻度、延長の頻度、甲子園と地方大会の違い。
3. 調整値は従来どおりJSONで管理し、経緯を `docs/tuning/` に残す。

## 6. 保存の現状（2026-10-20 時点）

ゲーム本体が実際に使っている保存は次の組み合わせ。

- セーブスロット（`save_slots.py` / `live_season_save.py`）：進行中の状態をそのまま書き出したJSON。読込で計算し直さない（ADR-043。2026-10-21 に ADR-026 の再計算方式から変更）
- 試合履歴（`historical_match_archive.py`、旧A方式）
- 選手名簿の履歴（`career_roster_archive.py`）
- 閲覧用SQLite（`browse_repository.py`）

v2（`career_v2_*`）は履歴閲覧の試作画面が使う実験系列で、段階2で置き換えて削除する。v3（架空大会用）は段階0で削除済み。

読込時に毎回最初から再計算する方式は、段階1で状態をそのまま書き出す方式に変えた（ADR-043）。

## 8. 段階1（年度循環）の方針（2026-10-21 決定）

### 年度の区切り

ゲームの1年度は **4月1日〜翌年3月31日**。新規ゲームは **2026年4月1日** に始まる。

| 時期 | 大会 |
|---|---|
| 4〜6月 | 春季県大会・地区大会 |
| 7〜8月 | 夏の地方大会・夏の甲子園 |
| 9〜11月 | 秋季県大会・地区大会・明治神宮大会 |
| 翌年3月 | 選抜（その年度の秋の結果から選考） |

**大会の所属年度**（2026-10-21 決定）：

- 3月の選抜は **前の年度** の大会（2027年3月の第99回選抜＝2026年度）
- 3月に始まる春季県大会は **新しい年度** の大会（2027年3月開始の春季県大会＝2027年度）
- 翌年度の大会表は、**その年度の秋の大会が終わった時点で作る**。3月は、前の年度の選抜と新しい年度の春季県大会が並んで進む

コードでは `phase2_engine/school_year.py` の `competition_school_year` で判定する。

実装（`phase2_engine/career_state.py`）：ゲームの日付は1つで、進行中の年度を同じ日付で進める。その年度の秋の大会の日程の最後の日が過ぎたら翌年度の大会表をつくって開き、3月31日を進めたら前の年度を閉じる（履歴を封印する）。3月に始まる大会は新チーム（夏が終わった3年生は出ない）。

**同じ学校が同じ日に2試合しない**（2026-10-21）：学校ごとの試合の日を全大会・全年度で共有し、両校とも空いている最初の日程の日に入れる。日程の日がふさがっていれば、次の日程の日より前の空き日（予備日）を使う。日程が地区ごとの日をまとめたものしかない大会（2026年データの青森春季の地区予選）は日が足りず、わずかに同じ日の2試合が残る。

### 選手の循環

- 4月1日に新入生が入部する
- 3年生は、自分の学校の夏の大会（地方大会または甲子園）が終わった時点で引退する。秋からは1・2年生の新チーム
- 3年生は3月に卒業する

**卒業・入学の日と大会の出場メンバー**（2026-10-21 決定）：

- 卒業は **3月31日**、入学は **4月1日**
- 各大会の出場メンバーは、**その大会が始まった時点の部員** から選ぶ。大会の途中で部員が変わっても入れ替えない
- 3月に始まる春季県大会は、秋と同じ新チーム（1・2年生）で戦う。4月1日に入学した新入生は、その大会の途中からは加えない
- 秋の大会は新チーム（1・2年生）で戦う。甲子園の途中で秋の県大会が始まる県でも、甲子園に出ている学校の3年生は秋の大会に出ない
- 同じ選手が同じ日に2試合出ないようにする（例：甲子園に出ている学校の秋の初戦は甲子園の後に回す）。年度の重なりか全国の試合を選手で行う作業で入れる

実装：`game_core/membership.py`（部員と出場メンバー）、少人数のときの先発・投手陣は `config/abilities/team_strength_v1.json` の `small_roster`。

### 最初の春（2026年春）に必要な過去の結果

**実際の結果を出典付きでデータに入れる。**（`data/initial_state/2026/prior_results.csv`）

第98回選抜（2026年3月）は2025年度の大会で、ゲーム開始前の実際の出来事として扱い、**シミュレーションしない**。出場校は試合をせず、春季大会の推薦・予選免除の入力としてだけ使う。前年秋の上位校も同じファイルから春季大会の予選免除・シードに使う。

- 2026年選抜（第98回）の出場32校：北海道・神奈川・愛知・三重・広島の春季大会で予選免除に使う
- 2025年秋の県大会・地区大会の上位校：茨城・埼玉・千葉・岐阜・兵庫・岡山・東京の春季大会の予選免除・シードに使う（`competition_access_rules.csv` の `source_year_offset=-1` の7件）

データが揃うまでは、該当する扱いをルールの範囲内でランダムに決めて動かしてよい。その場合も実在データと生成データを混ぜて保存しない。

### 2027年以降の大会と日程

- 大会の制度（出場枠・大会方式・シード・進出ルール）は **2026年と同じ** とする。現実で制度が変わったらデータを直す
- 大会の回数は毎年1つ進める（例：第99回選抜、第109回選手権）
- 日程は **2026年と同じ曜日になるようにずらす**（例：2026年の「7月の第3土曜」は翌年も第3土曜）。同じ月日のままにはしない
- 組み合わせは大会規則の範囲内で毎年ランダムに抽選する

実装（`phase2_engine/season_catalog.py`）：年度ごとに2026年の大会をひな形にして大会表をつくる。日程は年度全体を同じ日数（7の倍数、2026年の同じ月日から±3日以内）だけずらす。大会どうしの前後関係を崩さないため、大会ごとには合わせない。そのため「第3土曜」が年によって第2・第4土曜になることがある。ずらすと年度末（3月31日）を越える大会（3月の選抜）だけは1週早める。記念大会の冠（「〜記念」）は翌年以降の名前から外す。

### 選抜の選考

- 地区ごとの出場枠（`selection_rules.csv`）のとおり、**秋季地区大会の成績上位から選ぶ**
- 21世紀枠は最初は入れない。後から「秋に好成績だった公立校から抽選」で追加する

実装（`phase2_engine/senbatsu_selection.py`）：その年度の秋季地区大会（東京は東京都秋季大会）がすべて終わった日に選ぶ。地区ごとの枠は大会の順位の上から。関東・東京の比較枠は、関東の次の順位の学校と東京の次の順位の学校からくじで1校。神宮枠は神宮大会を試合で行うまではデータのとおりの地区（九州）。21世紀枠がないので出場は30校で、組み合わせの空きは不戦勝になる。

選抜の出場校を推薦で受け入れる春季地区大会（九州）は、出場校がその地区の枠より少なければ、その分だけ少ない校数で行う。

### 進め方（PRの分け方）

1. 年度の区切りを4月〜3月にし、新規ゲームを2026年4月1日から始める（済）
2. 2027年以降の大会表を自動生成する（回数、曜日合わせ、抽選）（済）
3. 全国で入学・引退・卒業を回す。全国の試合を選手で行う前提なので、次の順に分ける（2026-10-21 決定）（済）
   1. 名簿の作りを直す：部員を日付で決める（4/1入学、自分の学校の夏の大会が終わったら3年生引退、3/31卒業）。大会開始時点の部員で出場メンバーを固定する。少ない人数でも先発を組める
   2. セーブを「その日時点の状態」を書き出す形にする（読込時に最初から計算し直さない。§6）
   3. 全国の試合を選手で行う（本番の既定を resolver contract `players_v1` にする。`game_core/live_members.py`）
4. 年度の重なり：秋の大会が終わった時点で翌年度の大会表をつくり、3月は前の年度の選抜と新しい年度の春季県大会を同じ日付で進める（済）
5. 秋の結果から選抜を選考する（済）
6. 前の年度のゲーム内の結果を、翌春の予選免除・シードに使う
7. 3年分を止まらずに進められることを確かめる

**試合経過の要点**（2026-10-21 決定）：1打席ごとの記録は残さず、得点が入った打席（誰が・何回に・どんな打撃結果で・何点）、本塁打、投手交代だけを残す。スコア・イニングごとの得点・個人成績は今までどおり残す。保存先は試合の履歴（`historical_match_archive.py`）で、セーブには入れない。目安は1年分で20MB以内（超える場合は甲子園・神宮・地区大会と県大会の準々決勝以降に絞る）。実装は `game_core/highlights.py`。2026年度1年分（13,517試合）で約7.6MBだったので、全試合で残す。
