# Stage 43G-12：本編2026セーブ／キャリア年度の接続監査と学校・選手の歴代閲覧基盤

作成日：2026-10-10。前工程 Stage43G-11 PR #152 は main 反映済み。

## 1. 既存セーブの境界

2026年の本編 LiveSeason セーブは phase2_engine/live_season_save.py で定義され、手動・オートセーブの原本は slot/manual.json・slot/autosave.json。保存済みのゲーム日時、試合結果と大会プランSHAを保持する。

一方 Stage43G-1〜11 の 2027年以降は、別構造の「明示した参加校だけを試すゲーム内sandbox」。career_multi_previews/2027.json に共通年度プラン、historical_matches.sqlite3 に A方式試合、career_rosters.sqlite3 に固定選手IDと年度別所属のスナップショットを保持。

**2026年の本編手動セーブと、キャリア用に封印した2026試合台帳が同一の試合世界に属することは現時点では保証できない。** そのため旧セーブからの試合履歴や選手を無条件にインポートすると結果が二重化・改変される危険がある。今回実装するのは接続可否の監査と参照であり、史実（ゲーム内実試合）の自動移植は行わない。

## 2. 年度接続証明

新規 phase2_engine/career_year_continuity.py：CareerYearContinuityService。

- 明示した2027以降の年度共通セーブを実際にロードし、前年のA方式SQLiteが sealed、当年が active、前年の封印済み全試合台帳SHAと保存した年度プランSHAが一致することを確認。
- その年度に参加した全学校について前年度と当年度の roster を検証。継続者は不変ID、学年+1、入学年・背番号・氏名同一、前年度3年生は翌年度所属から外れる。新入生は当年度の1年生で、卒業者と同数。退部・転校等の未実装イベントは推定しない。
- 各学校の両年度ロスター本体からSHAを導出。接続証明は career_year_continuity/YYYY.json にチェックサム付きで記録し、再ロード時に照合する。以前の年次保存を改変しない。
- 手動・オートセーブの指定は opt-in（manual/autosave）。形式、2026年度表示、プランSHA、チェックサムを検査し、**参考資料のみ**として保存。2027以降のゲーム試合履歴と同一性が確認されたと扱わない。2027以外の年度に2026本編セーブを勝手に紐付けない。
- 異なる参照元・年度台帳・選手所属データで再登録する操作や整合しない証明のロードは拒否。
- Stage43G-11 CareerYearOperationService.audit() に、接続証明の有無・歴代選手閲覧準備状況・旧2026本編セーブの試合が未移行という状態を付加。全国年次進行、翌年自動進級は有効化しない。

## 3. 過去の学校戦績・歴代選手の閲覧

新規 phase2_engine/career_longitudinal_read.py：CareerLongitudinalReadModel。

| API | 用途 |
|---|---|
| school_results(school_id, start_year, end_year, limit, offset) | 保存済みスコアから年度×大会別の試合・勝敗・総得失点を集計 |
| school_player_index(school_id, limit, offset) | 固定選手IDごとの所属開始年度・氏名・直近年度での在籍状況 |
| player_years(player_id) | 選手の年度別在籍・学年・背番号を連続閲覧 |

- 既存 historical_matches の year／team1_id／team2_id 索引と、career_player_identities の school_id＋entry_year 索引を再利用。
- 試合は保存済みのスコアを使用し、順位・大会優勝や学校の格付けを推測で作らない。
- 試合レコードSHAおよび選手IDレコードSHAを検証し、改変時は拒否。
- 学校や個人名による曖昧な照合を禁止。卒業扱いは前年度3年生が翌年度に存在しないことを検証した接続証明で判断する。履歴一覧自体は「直近保存済み年度のロスターにいる／いない」を表示し、転校・退部等を断定しない。
- 1ページ最大200件（選手）、学校戦績は最大200の年度×大会グループ。3,000校×100年分を一度にJSON展開する方式ではない。
- 現行のA方式（スコア・イニング得点・個人成績）を引き続き保存し、打席ごとのイベントは保持しない。

## 4. テスト

tests/test_stage43g12_career_year_continuity.py で新規10件を登録。
- 16校×2年度の実ロスターを用い、320人の2027所属、192人の継続、128人の前年卒業、128人の新入生の整合を検証。
- 2026本編手動セーブの読み取り参照のみ、未検証の試合世界への統合はしないこと、破損した参照元・別年度を拒否。継続選手の全属性を学年以外不変として検証し、選手IDを残したまま左右打ち属性を書き換えてSHAを再計算しても拒否。
- 接続証明のチェックサム改変、封印済み前年SQLite台帳の改変、旧セーブの付け替えを拒否。
- 2026→2027の学校別試合閲覧、2年続く同一ID選手の学年+1、卒業相当者を含む歴代28人のページ分割一覧、改変拒否。
- 既存Stage43G-10の関東8都県E2Eを併せて回帰テスト。
