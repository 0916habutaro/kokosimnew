# Stage43G-78：封印済みv2学校別試合検索の長期保存性能監査

作成日：2026-10-12

## 目的と位置付け
Stage43G-76の学校検索は年度先頭索引の範囲でJSON1の `json_extract` を使い、学校IDを保存試合JSONから探す。旧A方式の学校先頭索引とは異なる。Stage43G-77の試験GUIの利用前後に、**実際のSQL検索計画・合成完全A原本の読み取り時間・原本不変更**を数字で確認する。

本監査は実際の全国3000校で50年・100年進行したセーブではない。得点・個人成績は `synthetic_ability_record` によって生成した合成fixtureであり、現実の高校野球の勝敗、連年大会構造、公式日程、進行の正確性を実証しない。

## 再現手順
```bash
python -m phase2_engine.career_v2_school_search_benchmark --years 4 --games-per-year 40 --repetitions 3
```

年10000から開始し、年度ごとに明示的な架空カレンダーを新規登録、完全A方式の合成試合を追加・封印する。学校IDは固定40校を20対に分け、そのうち `SCH000001` の試合を選択。監査専用の一時ディレクトリに新規SQLiteを作るため、利用中のセーブ・実行用ソースを読み書きしない。

測定値はCI実行環境とfixtureサイズに依存し、絶対時間の合格閾値を設けない。

出力JSONには、年度数・合成試合総数・対象校の保存試合数・完全Aと架空出典の明記、作成時間、保存されたSQLiteの実バイト数、`EXPLAIN QUERY PLAN`、下記の読み取りを繰り返したときの実測中央値／最大値／各サンプル、および読み取り前後の2ファイルSHA-256を記録する。

## 比較する検索
| 検索 | 実装する整合性確認 | 時間に含まれる処理 |
|---|---|---|
| `page` | 保存済み年度の封印／カレンダー／ledgerと表示中の原本SHA | 年度ごとの帳簿照合、学校JSON1フィルタの件数取得・ページ取得 |
| `selected_years` | 上記＋選択した保存済み年度に存在する全学校・全大会の原本SHA | 年度内の全原本検査、学校JSON1フィルタ・ページ取得 |
| `competition_page` | `page`と同じスコープで大会ID完全一致を指定 | 年度範囲内JSON1＋大会ID条件 |

「pageが30件だけの定数時間」とは主張しない。年度範囲が拡大すれば封印帳簿とJSON1検索コストも増える。厳密検証は同年度の他校試合まで検証するのでより重くなる場合がある。

## 検証・実施制約
- 通常最大1000試合の合成fixture。これを超える場合は明示的に `--allow-large`、最大10万試合をハード上限とする。
- 年度範囲は1〜100年。実際の検索対象は年10000以上の保存済み架空v2原本のみ。
- `--output-root` は専用の**空の検証用ディレクトリ**を指定。保存済みv2・架空カレンダーの存在を検知したら上書き拒否。
- CIは小規模な完全A fixtureを作成し、契約とSQLite SHAが不変であること、実測件数、実際のSQLプラン、異常入力拒否を検証する。
- 実測結果を基に、必要に応じて既存封印SQLiteに一切手を入れない**独立read-only索引/派生キャッシュ**を次工程で設計する。既存セーブの移行や学校IDの推定は行わない。

## 本ステージの完了条件
監査スクリプト、単体テスト、専用GitHub Actions、日本語監査方針をPRで作成。CI実測ログに計測数値を記録し、全Pythonテスト・関東17校E2Eを確認した後にmain反映する。CIでは全国長期セーブの性能を実証したとは記載しない。
