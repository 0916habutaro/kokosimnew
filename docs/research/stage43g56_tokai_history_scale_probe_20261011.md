# Stage 43G-56：東海の保存年度閲覧性能・ページング実測

作成日：2026-10-11

## 目的・適用範囲

Stage43G-55のTkinter試験画面が実行するheadless読み取り5経路（年度概要／大会1ページ目・次ページ／学校1ページ目・次ページ）を、**既存の架空ゲームA方式SQLite**で計測する。正式ゲームGUI・年次進行ロジック・大会ルールは変更しない。

既存のStage43G-13とStage43G-20で、合成SQLiteの学校別・選手別検索索引と長期間履歴の規模検証は導入済み。ただし、**その結果を今回の東海閲覧GUIの全国3,000校・100年処理能力と読み替えてはならない**。本Stageでは利用者が指定した既存保存年度のみを検証する。

## 実装

- career_tokai_history_scale_probe.py：存在する保存済み年度を1～100年度選び、既存read modelの5種類の経路を各1～5回実行して実測の中央値（ms）、ピークPython追跡メモリ、返却件数を報告する。年・大会・学校は実保存IDで指定。
- 大会・学校の前後ページは1～100件に制限。不要なイベント、架空の結果、欠落年は補完しない。
- 履歴SQLite、ロスターSQLite、派生キャッシュ、既存SQLite sidecarのバイトSHA-256を前後で比較し、作成・変更・削除を拒否する。SHAチェックは分割ストリーム読み取りで実施。
- **速度の合否閾値は設けない**。CI機種依存の瞬間的な数値で本番性能を断定しない。測定対象と未検証範囲をレポート内に明記する。
- 既存Stage43G-54テストfixtureで、ページ制限、未保存年度・不正ID拒否、非書込を専用unitで確認する。

## 実行例

    python -m phase2_engine.career_tokai_history_scale_probe \
      --data-root data --slot out/saves/<slot_id> \
      --school-id <保存学校ID> --years 2027 2028 \
      --competition-id CMP000008 --limit 30 --repeats 2

列挙した年度にアーカイブが存在しない場合は失敗する。全国規模テストを実施したという意味ではない。

## 次工程

次段階では実保存データによる各ページの最悪ケースを精査し、必要ならモデルのSQL検索・索引改善を**SHA改ざん検知を維持したまま**行う。あわせて「学校・年度・大会・選手」を横断する正式GUI要件を定義する。無制限年数は設計目標であり、100年到達や本番メモリ安全性の実証ではない。
