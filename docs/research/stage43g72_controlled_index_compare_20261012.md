# Stage 43G-72：新旧の重複主キー索引が占める容量と検索時間を同一データで比較

作成日：2026-10-12

## 背景

Stage43G-70ではv2試合原本の余分な主キー重複索引 `idx_v2_games_school_a` を、新規保存する場合のみ生成しないよう変更した。Stage43G-71では旧A方式の派生成績cacheにも同様に主キーと重複する `idx_cached_school_year` があり、新規生成から除外した。

これまでの監査はB-treeの割当や検索計画を確認していたが、**元データや試合数が違うDBを比較した数字では、重複索引1本の効果を切り分けられない**。

## 比較方法

`phase2_engine/career_paired_index_benchmark.py` を追加する。

1. 既に作成された**新スキーマの保存SQLite**をread-onlyで開く。完全A原本・派生キャッシュの内容は一切更新しない。
2. 使い捨てディレクトリへ、SQLite Backup APIで新旧比較用に**同一内容の2つのSQLite**を複製する。
3. 一方の一時DBは新スキーマのまま、もう片方の一時DBへ**旧スキーマで作られていた主キー完全重複インデックスだけ**を追加する。元セーブへは追加しない。
4. 同じ順序・同じ列の全保存行を読み、レコード数と行の全フィールド内容をSHA-256で照合する。内容が異なれば測定値を採用しない。
5. 各DBの**実際のSQLiteファイルサイズ、ページ数、SQLite dbstat利用時の追加索引の割当ページ量**を収集する。
6. 同じ保存済み試合IDまたは選手IDで、同じSQLによる索引検索を指定回数繰り返し、実測レイテンシを記録する。SQL実行計画がテーブル全走査になっていないことも確認する。
7. 元SQLiteのSHA-256が前後一致し、検証に利用した一時コピーが削除されたことを確認する。

比較対象は **v2完全A方式試合** と **旧A方式の派生成績キャッシュ**。2件の元ファイルそれぞれについて、同一元レコードを使った新旧一対比較を実施する。

## 実行例

```bash
python -m phase2_engine.career_paired_index_benchmark \
  --kind v2_matches \
  --saved-db out/saves/EXAMPLE/fictional_option_a_v2.sqlite3 \
  --repeats 10 --output-json build/reports/v2_paired.json

python -m phase2_engine.career_paired_index_benchmark \
  --kind legacy_cache \
  --saved-db out/saves/EXAMPLE/derived_player_stats.sqlite3 \
  --repeats 10 --output-json build/reports/legacy_cache_paired.json
```

**このCLIは新スキーマの元SQLiteを入力する。** 既存の旧スキーマ・重複インデックス付きのファイルは、比較元としてそのまま利用できない。旧ファイルの検査はStage43G-70/71のread-only B-tree監査で行う。

## 解釈の限界

- 「旧索引を追加した一時コピーのファイルサイズ」と「追加しなかった一時コピーのファイルサイズ」の**実測差**は示せる。ただし、既に保存されている本物の旧SQLiteから索引をDROPした場合に同じバイト数が戻る保証ではない。SQLiteファイルは空きページを内部再利用することがあるため。
- 同じSQLを少数回実行した時間の違いは、OSページキャッシュ、SQLiteのページ割当、CIの共有CPUなどに左右される。**速度が改善したと断定する合否条件にはしない**。
- SQLデータの真偽（試合原本・個人成績のSHAや出場学校ID）はこの索引性能比較ではなく、Stage43G-67/68等の元記録深度監査で確認する。
- 比較サンプルは使い捨ての少数架空試合・選手年度であり、全国3,000校×100年・50年の連続試合実行や正式ゲームGUIの速度を証明するものではない。
- 試合原本は従来の **A方式（スコア・イニング別得点・個人成績）** を保ち、原本の構造やイベント粒度は変更しない。

## テストとCI

- 新規7テスト：同一レコードの全列SHA一致、旧索引を付けた一時コピーの容量増分、両DBの索引検索維持、既存セーブは不変、旧スキーマ元ファイルへの誤適用を拒否、不正引数・リンク拒否・CLI入力上書き拒否。
- Stage43G-70/71の旧・新B-tree構造と派生cacheの再検証も回帰する。
- 新旧の実測結果をv2試合原本・旧A派生成績キャッシュそれぞれJSONでGitHub Actionsに保存する。
