# ココシミュNew：過去の試合記録の長期保存方針（A方式）

策定日：2026-10-10
区分：基本保存方針。現行のDH保存契約は§9を参照。
適用対象：ゲーム内で生成・確定した春夏秋の全公式戦（県・地区予選、地方、地区、全国を含む）
関連：game_event_stats_contract.md、match_simulation_contract.md

## 1. 決定事項

ユーザー選択の **A方式（最終スコア・イニング別得点・試合別個人成績）** を、過去の試合記録を振り返るための基本保存水準とする。

- 過去の確定試合は、何年経過しても閲覧できることを目標とする。古い年度だからという理由で自動削除しない。
- 進行可能年数に人為的な上限を設けない方針とする。保存容量は有限であり、実運用の性能・容量は別途検証する。
- **打席ごとのイベント列・投球ごとのイベント列を、歴史保存の必須データにはしない。**
- シミュレーション内部では打席イベントを用いて成績を計算してよいが、試合確定後の歴史閲覧はイベント列の保持に依存させない。
- 後からB/C方式に拡張する余地は残すが、将来拡張を理由にA方式へ隠れた必須保存を追加しない。
- 2026年の研究用史実・二次結果はゲーム生成記録とは厳格に分離する。本方針の適用により未確認の広島FMT025等を解禁しない。

**重要：本書は保存するべき内容の仕様であり、現在のすべての大会・年度で保存できているという達成宣言ではない。**

## 2. 保存対象の定義

| レベル | 歴史保存する情報 | 方針 | 既存実装との関係 |
|---|---|---|---|
| A-1 試合の基本結果 | 年度、正式な大会IDと試合ID、出場チーム、試合日と日付の出典、ラウンド・ステージ、スコア、勝敗、試合状態、結果の出典 | **全確定公式戦で必須・永久** | SQLite matches_by_date / ability_matches等を利用可能 |
| A-2 イニング別得点 | 表・裏ごとの実施状況と各校得点、延長の追加回、途中終了の状態 | **全確定公式戦で必須・永久** | 現行スキーマに専用の確定保存契約がなく新規実装要 |
| A-3 チーム成績 | 両チームの得点・安打・失策 | **生成できた試合で永久保存**。将来の完備を目標 | team_game_statsが存在 |
| A-4 試合別選手成績 | 実際に出場した打者の打数・安打・打点等と投手のアウト数・被安打・失点・奪三振等の整数計数 | **生成できた試合で永久保存**。将来の完備を目標 | batter_game_stats / pitcher_game_statsが存在 |
| A-5 集計・検索キー | 年度・大会・試合・チーム（必要に応じ学校）・選手を一意に結ぶID、記録の完全性、ロジックの出典 | **必須・永久** | 既存年度別キーを維持、将来の年度横断性は検証要 |
| 非対象 | すべての打席の順序・結果、投球ごとの球種・カウント、打席時の全走者位置 | **歴史保存の必須対象外** | match_events保存処理は現状存在。変更は後続工程 |
| 非対象 | 全スタメン、全交代・継投の時刻、決勝打や逆転場面の文章再生、打席ごとの打点内訳 | **A方式では閲覧保証しない** | 別途仕様と保存契約が必要 |

A-1・A-2は最終的な完成要件。既存の簡易モデルでは日付が推定や未定の場合があり、真の確定日付として表示しない。
A-3・A-4は生成エンジンが正確なGameStatsを提供した試合に限り値を保存する。未生成の項目を0として埋めない。将来の全試合対応はシミュレータ接続計画で進める。
大会方式によりbye・対戦未定・中止・結果待ちなどの状態がある。これらを「0対0の実施試合」として記録しない。

## 3. イニング別得点の保存契約案（未実装）

新たに match_inning_scores 相当の行モデルを定義する。

| 項目案 | 内容 |
|---|---|
| year, competition_id, match_id | 完了試合の一意キー |
| inning | 1以上の回番号。延長にも対応 |
| half | top / bottom（試合内チーム順に対応） |
| batting_team_id | この半イニングで攻撃した側 |
| was_played | 実施した半イニングと未実施を区別 |
| runs | 実施した場合の非負整数。未実施をゼロと偽装しない |
| completion_status | 表示に必要なら終了・途中打切り状態を持つ |

- 実施済み各半イニングの得点合計は最終スコアと一致させる。
- サヨナラ、コールド、延長、タイブレーク、9回裏未実施などを正しく扱う。未実施は0点実施と区別する。
- MatchSimulatorの試合確定時にイベント計算から導出して確定保存する。**後で last_inning や最終スコアだけからイニング別得点を推測・復元しない。**
- イニング得点はA方式の正本としてイベント保存とは独立して読み出せるようにする。
- 大会ID、参加チームID、学校IDが一致しない合同チームなどのケースに備え、試合参加チームを正確に保持する。

上記のテーブル・列名は設計案であり、既存SQLiteへの追加を本PRでは実施しない。

## 4. ランタイムと保存の責務

1. 試合中は必要に応じてメモリ内のMatchEvent等から試合を進める。
2. 試合が確定した時点で A-1、A-2、A-3、A-4 と来歴・完全性を整合確認し、一体として永続化する。
3. 保存済みのGameStats・イニング別得点を歴史閲覧の正本とする。打席イベントを保存していない年度でも閲覧・年度集計できる。
4. 既存 match_events テーブルやイベント読出しAPIは直ちに削除しない。互換性と既存データを保護しながら、**将来の新規確定試合でのイベント永続保存を任意化／省略する**別工程を設ける。
5. イベントから率指標を毎回再計算しない。打率・OPS・防御率等は保存した整数のGameStatsから計算する。
6. 旧年度や別方式由来の試合にイニング記録やGameStatsがない場合、欠損理由を明示する。史実二次結果や乱数再実行で補間しない。

## 5. 長期保存・年度移行・閲覧

- 結果・イニング得点・チーム成績・試合別選手成績は、年度ごとに確定して保持する。過去年分を通常の翌年度処理で上書き・削除しない。
- 保存済み過去年度の同一年再計算・置換は、既存 replace_season_views 等が同一年をDELETEして作り直す構造を持つため、**明示的な再構築操作・バックアップ・整合監査がある場合だけ許可**するよう後続実装でガードする。
- 検索は year + competition_id + match_id、および年度・学校・選手などの条件付き索引を利用し、全年度全試合の一括ロードを禁止する。歴代閲覧はページ分割・対象限定で実施する。
- 年度ごとの確定データは、可逆圧縮／古い年度の別ファイル化等を検討できる。ただしアーカイブからA方式の全情報を再閲覧できることが必須。アーカイブしたことで試合結果が不可視になってはならない。
- 100年・500年・1000年相当の件数で検索・DB成長・バックアップ／復旧・年度移行を性能試験する。これらの年数は**上限ではなく検証点**。
- 無制限の年数を実現するには、現在の2026年限定実行と Python datetime.date の西暦9999年上限を解消する年度・暦管理が別途必要。**本書だけで無制限進行が実装されたとはしない。**

## 6. 表示すべきデータの完全性

| 記録状態（概念） | 表示可能なもの | 表示ルール |
|---|---|---|
| FULL_A | A-1～A-4が揃った試合 | スコア・イニング別得点・チーム成績・試合別個人成績 |
| A_PARTIAL_STATS | スコアとイニング別得点があり、一部成績なし | 成績の欠損は「記録なし」。0扱いしない |
| SCORE_ONLY_LEGACY | 最終結果だけある旧形式等 | イニング別得点・個人成績を作り話で補完しない |
| NOT_PLAYED | 未実施・bye等 | 完了試合と区別し、得点／個人成績を表示しない |

これらは画面表示上の**概念的な状態名**。実DB列としての採用は後続のスキーマ設計で決定する。
生成結果・入力override・2026史実二次結果等は出典を明示し、混合しない。

## 7. Stage 43以降の対応と受入条件

**Stage 43（本方針の仕様確定・依存監査）**
- 既存結果モデル・GameStats・MatchEventとA-1～A-4のフィールドを対応づけ、不足と保有済みを一覧化する。
- 全公式戦（pre-MAINを含む）での正確なイニング得点とGameStatsの可用性を確認する。
- A方式のみで年度・大会・学校・選手の歴史閲覧に必要な値が取得できることを要件にする。
- これまでの「全打席イベントを永久保存する」未決案をA方式へ置換し、永続イベント保存は任意の拡張扱いとする。

**後続の実装工程（別PR）**
- MatchSimulatorでイニング別スコアを確定生成 → SQLite永続化 → 閲覧read model接続。
- 試合の基本結果とGameStatsの保存を一括整合・不可分に行う。中断／保存／復元の監査も追加。
- 現在のイベント永続保存処理を互換性を保って任意化する。既存の過去データを一律削除しない。
- 完全記録、部分記録、旧年度、試合未実施を分ける回帰テスト。
- 100・500・1000年相当の件数で、特定大会・学校・選手を素早く検索できるか試験する。

**受入の最低条件（実装後）**
1. 全確定試合について「出場チーム・スコア・年度／大会／試合ID」が失われない。
2. 新規A対応試合について半イニング別得点と合計スコアが一致し、未実施半イニングが区別できる。
3. 保存可能だったチーム・選手GameStatsが保持され、歴代集計がイベント列の有無に依存しない。
4. 翌年の開始・進行・保存で過去年の記録が不変であり、再開／バックアップ復元でも確認できる。
5. 打席イベントの保存を無効化しても、A方式の画面が機能する。
6. 未収録データは「記録なし」として表示し、0や架空の試合経過を表示しない。

## 9. DH試合の現行保存契約（2026-10-30）

既存A方式の同じテーブル・大会単位の圧縮・年度封印を使用する。全国の試合前DH選択にも
同じ保存経路を使う。DHなしの通常保存形は変更しない。

### 保存する事実と圧縮

スコア・イニング別得点/打席数・個人成績・要点に加え、既存の参加履歴に開始DH申告、
独立した開始守備9位置、DHの打順変更・引継ぎ・消滅、兼任の片役終了、規則通知を残す。
投手専任者も投手成績・開始守備・履歴から既知IDへ含め、打者成績に架空の行を作らない。
兼任者の投打成績は同じIDを参照し、異なる2選手として数えない。

- 開始守備は既存の列名1回の表形式。DH試合の変更時点は、打席前を
  `["B", 回, 表裏, 次打席番号, order]`、打席完了後を `["A", 回, 表裏, 完了打席番号]` に詰める。
- DH規則入力は打順変更の`[枠, ID]`列、通知対象ID、医療例外、球審承認を短い配列で保存する。
  展開時には既存の `LineupChange` / `DHAction` / 時点型の辞書へ戻す。
- 投手交代の要点は従来の `["P", チーム添字, 変更連番]`。攻撃中の交代申告は、
  イニング別打席数から次の実守備時点を求め、元の要点表示へ復元する。
- 全打席・全走者位置・全投球の永久保存は追加しない。

### 保存前の厳密検証

`validated_match_history()` はイベントを破棄する前に `validate_match_simulation_result()` を呼ぶ。
実打者・投手・打順・守備、初回DH打撃義務と相手先発交代通知、役割終了、選手別PA/BF・
安打内訳・打点・球数を照合する。DHイベントだけが持つ一時的な得点走者IDと塁の情報から、
既存の責任投手・無失策イニング再構成を再生し、選手別得点・失点・自責点も照合する。
この計算には現行打席モデルの自責点再構成の限界がある（`match_simulator_v1.md`）。

検証済みのA対象事実（年度・試合ID・両校・スコア・成績・参加履歴・要点）のSHA-256を
`dh_verification = {"version": 1, "facts_sha256": ...}` に持たせる。
これはイベント照合から保存までの受渡しで事実が変わっていないことを確認するもので、
全イベントの代替や電子署名ではない。追加はDH試合に限り、照合値オブジェクトが95バイト、
キー等を含む増分は未圧縮で114バイト/試合。

`AbilityMatchResolver` はこの検証後にだけ球数・出場経験・詳細へ反映する。
直接詳細・詳細sinkのどちらでもDHの全打席を渡さず、照合値付きA詳細だけを渡す。

### 保存後の検証と限界

読込ではレコード全体の既存 `record_sha256` を照合し、個別取得・一覧取得・大会圧縮後も
同じ読込処理を使う。DHの受渡し照合値も確認し、欠損・変更・非正規の履歴を拒否する。

`validate_recorded_match_participation()` は保存された半イニング別打席数を時間軸とし、
厳密検証と同じ状態遷移・通知処理を再生する。ここで推定する打者・投手は**保存履歴から
期待される配置**であり、失われた打席イベントを実測したものではない。
この時間軸で9枠の打順・守備、DHの引継ぎ/消滅、片役終了・完全退場・復帰禁止、通知時点、
守備出場ID、選手別PA/BFと保存成績の一致を確認する。打撃/投手の役を持つ選手の成績行も照合し、
チーム得点・安打・相手投手失点の合計と整数計数の妥当性を検証する。

当時の大会登録・起用可能性は保存前の試合入力に対して確認する。全登録名簿を試合ごとに
重複保存せず、読込では保存された参加ID・開始配置・履歴・役割別成績の整合を確認する。
当時の全登録名簿や、打球・走者進塁・打点・各打席の球数・責任投手/自責点を、
イベントなしに独立して再証明したとは扱わない。これらは保存前検証と照合値で受け渡す。
照合値と全記録を意図的に作り替えた場合の真正性を保証する署名方式は導入しない。

### 閲覧

既存の先発・交代・個人成績タブを使う。通常DHは打順9人と打順外の投手1人、
投手兼DHは同じIDの「投・DH」1行として表示する。片役終了と完全退場を区別し、
内部の初回打席完了・相手先発交代通知を選手交代として表示しない。
打撃専任DHは守備出場へ含めず、守備専任投手を打撃表へ混入させない。
守備・役割は当時の実配置と履歴から復元し、現在の本職や能力から再選考しない。
