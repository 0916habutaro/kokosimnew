# Stage 43G-36：新旧年度の試合詳細・表形式表示と大規模閲覧最適化

作成日：2026-10-11

## 目的・前提
Stage43G-35／PR #177（main にマージ済み）を起点とする。対象は閲覧試験用 Tk GUI と新旧年度read modelのみ。正式版ゲーム画面、統計の生成・集計、連続年度進行は対象外。

## 表示
- 回別得点、チーム記録、選手打撃、選手投手の保存済み行を1行ずつ表形式で表示する。各行に区分／選手名（保存済みIDつき）、学校名、成績の独立列を設ける。
- 打撃の主な列：打数、得点、安打、打点、四球、三振、本塁打。投手の主な列：投球回、失点、被安打、自責点、四球、三振、被本塁打。共通列見出しには「打数／投球回」のように両方の意味を併記する。
- 投球回は保存済みアウト数（outs_recorded）から 3アウト＝1回として「6.2」などの野球表記に変換する（6回2アウト）。これは表示上の換算だけであり、原本成績の再計算・補完ではない。
- 存在しない個人成績キーや None を「未収録」と明示し、0として埋めない。旧得点のみレコードの不足状況も保持する。raw JSON は表セルに展開せず、選択された成績行の保存済み全項目を下部ペインで表示する。
- 成績の表示行のみ 80件単位で切り替える。「戻る」／「学校へ戻る」／「対戦校へ」はページに関係なく維持。横スクロールで列が画面幅を超える場合も閲覧できる。
- 旧ISO年度と架空v2年度の原本を統合せず、保存年月日・学籍ID・大会ID・試合IDを変更しない。ゲーム年10000以上は合成fixtureで実在進行を意味しない。

## 性能・安全性
- 旧v2実装は `year_matches()` が全年度原本を読み込んで検証することを前提としていたため、N試合を100件ずつページ参照すると全年度検証を繰り返していた。年度確認を1回の全件検証に変更し、ページごとの再検証を除去する。
- v2試合詳細は封印台帳・カレンダー・（verify_source=True では年度全件）の検証後、`year, competition_id, match_id` の複合主キーで対象1件を直接取得する。対象行もSHA・日付・学校・点数整合性を改めて確認する。
- v2学校試合一覧も全年度検証を1回にまとめる。全件整合性を検証する際に必要なO(N)の読込みは引き続き行う（無条件に定数時間になったわけではない）。読み取り時のキャッシュファイル、DB更新、再計算された成績を作らない。
- Tkの行生成はイテレータと `islice` で現在ページ分だけをTreeviewへ追加する。元の原本・キャッシュを変更しない。

## テスト／CI
`tests/test_stage43g36_match_tables_and_scale.py` で、v2全年度検証1回（ページ再走査なし）、複合キー参照、対象レコード改ざん拒否、欠損項目のゼロ埋め禁止、実Tkの列と行選択、80件ページング、すべてのSQLite原本SHA不変を確認。旧Stage43G-33/34/35実Tk回帰とPython全unittestを継続監視する。

## 残課題
本番GUIデザイン、ソート・学校別フィルタ、超大規模年度を全量デコードせず厳密に検証するストリーミング監査、インデックス付き年度試合ページング、Windows実機での幅・スクロール検証は別工程として扱う。
