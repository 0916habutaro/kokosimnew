# Stage 43G-14：A方式個人成績から選手の年度別・通算成績と学校歴代記録

作成：2026-10-10。前段：Stage43G-13 PR #154 main。

## 対応した閲覧モデル

新規 `phase2_engine/career_player_records.py` の `CareerPlayerRecordView`。既存 `historical_matches.sqlite3` と `career_rosters.sqlite3` を**読み取り専用**で参照する。対象学校→年度範囲はStage43G-13の学校先頭索引・カーソルで限定し、全年・全校一括JSONロードを避ける。

| API | 応答 |
|---|---|
| `player_seasons(player_id,start_year,end_year)` | 年ごとの打撃・投球集計、対象期間の通算成績 |
| `school_leaders(school_id,start_year,end_year,category,limit)` | 学校の歴代安打・本塁打・打点・盗塁・投手奪三振・投球アウト数を固定player_idでランキング |

打者は打席・打数・安打・二三塁打・本塁打・打点・得点・四球・三振・死球・犠飛・犠打・盗塁・盗塁死を合算。打率=H/AB、出塁率=(H+BB+HBP)/(AB+BB+HBP+SF)、長打率=塁打/AB、OPS=出塁率＋長打率を算出。分母0は`null`で扱い、0割を避ける。

投手はアウト数・打者数・失点・自責点・被安打・被本塁打・与四球・奪三振・与死球を合算。防御率=27×自責点/アウト数、WHIP=3×(被安打＋与四球)/アウト数。イニングの端数はアウト数として保ち、投手勝敗・セーブ等は保存済みデータに直接ないため推測しない。

## 信頼性・記録欠損

- player_idと所属学校・年度ロスターの照合を必須とし、表示名の一致で同一選手を推測しない
- 試合ペイロードのSHA256・対戦・スコアと勝者の整合性、個人成績の数値と安打内訳、打者・投手重複を検証
- すべての対象試合はSHAを確認し、ページ外・対象選手の無出場試合でも改変を見逃さない
- 旧試合にスコアしかない場合、選手の打撃・投球を0として数えず、**学校の対象期間で個人成績が存在しない試合数**として返却する。したがって「通算成績」は保存済みA方式試合に限るという注意を付す
- 2026本編の別形式セーブから選手成績を無断移植しない
- 学校ランキングは有効なA方式個人成績を集計した範囲でのみ表示し、公式記録や全国ランキングと誤認しない

## 試験

`tests/test_stage43g14_player_records.py` で、継続選手の2026/27成績の合算、打率・OPS・防御率・WHIP、学校歴代記録、スコアのみ試合の欠損扱い、SHA改変・不正年／指標の拒否を検証する。

## 未実装と次工程

今の読取モデルは、対象校の試合を要求のたびに再検証して集計する。100年の閲覧を頻繁に繰り返したときのSQL負荷は残るため、**Stage43G-15では試合SHAに紐付く集計キャッシュの更新・破棄を検証**する。正本は必ずA方式SQLite、キャッシュは再生成可能な派生情報とし、古いスナップショットで新年度成績を上書きしない。

年度一括進行、3,000校×100年実測、年数無制限、投手勝敗等の未保持データ算定は引き続き対象外。
