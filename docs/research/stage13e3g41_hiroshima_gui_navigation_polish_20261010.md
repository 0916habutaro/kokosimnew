# Stage 13E-3G-41：簡易GUIの学校戦績遷移とプレビューへの戻りを改善

作業日：2026年10月10日

## 目的・対象範囲

Stage40までに、2026秋季広島西部の18校を公式学校マスター`school_id`に一意に照合でき、同ID・2026年・県コード34の学校が既存SQLiteに存在するときだけ通常の「学校戦績」へ移動できるようになった。ただし、**学校戦績画面へ移動後、プレビューへ戻る分かりやすい操作がなく、探索時の学校フィルタが残る場合があった**。年度を2025などに切り替えたときの操作案内も不十分だった。

Stage41ではこの往復操作を改善する。正式ゲームGUIの新規作成、予選シミュレーションの実行、SQLiteへの2026史実結果の合算は今回の対象外。

## 実装内容

`phase2_engine/browse_gui_stage13d3.py` を改修した。

- **「予選進行プレビューへ戻る」** ボタンを通常GUIの「学校戦績」タブと「大会結果」タブの双方に配置。初期状態は無効。Stage39照合済みの同一学校IDが、既存SQLiteの2026年学校戦績に存在し、画面上の学校検索結果にも一致して**実際に遷移成功した場合のみ**有効にする。
- 戻る操作では、既に開いているTkinterプレビュー別窓を前面に戻す（`deiconify/lift/focus_set`）。**新しい別窓は作成しない**。進行中のread-onlyチェックポイントや絞込も作り直さない。
- 別窓が閉じられている場合は「閉じられています」と案内し戻りボタンを無効にする。大会結果側から通常操作で別窓を開き直すことはできる。
- 既に開いているプレビューを大会画面の起動ボタンから再度開こうとしても**既存の窓を前面に出すだけ**とし、別窓の二重起動を防ぐ。
- 通常GUIの年度切り替えイベントが発生した場合、過去のプレビュー往復対象学校IDを破棄し、双方の戻りボタンを無効化。**2025年など他年度に勝手に2026年の画面を表示したり、年度を自動で変更したりしない**。
- Stage40のSQLite事前審査で許可されたにもかかわらず、通常GUIの学校検索結果に対象`school_id`が存在しなかった場合は**学校検索テキストと県フィルタを元に戻す**。例外発生時もそれらの文字列を戻す。誤った学校を選択して成功扱いにしない。
- 遷移が成功した場合は、親ウィンドウを`deiconify/lift/focus_set`して学校戦績を見せる。史実とシミュレーションの別データである注意書きは引き続き表示する。

## データの真正性と副作用の範囲

Stage40の`preflight_2026_west_school_browse_handoff`は`sqlite3`の`mode=ro`でチェックするため、その**事前確認は**ファイルの新規作成・レコード更新を行わない。GUIへ移動した後は従来の`BrowseRepository`を使うが、既存実装は`_initialize_schema_conn`でSQLiteスキーマの存在確認・必要に応じた初期化を行う実装である。このため、**ブラウザ全体について「SQLiteのファイルバイトがどんな環境でも絶対に不変」とは主張しない**。今回の段階では史実の予選25試合の得点や勝敗をゲーム用の`matches_by_date`などへ追加する機能を実装していない。

データ表示を混在させない境界を維持：
- 広島西部史実：2026年の二次資料から段階的に25試合・18校・県大会代表7校の閲覧。
- 通常の学校戦績：SQLiteに既に保存されたゲーム内シミュレーションの学校戦績・得点・個人成績。学校IDが一致しても、史実の成績と混ぜない。
- 公式の2026予選ルール：試合番号25件、敗者矢印32件は未確認。春秋8季節地区48要件は未解明、本番FMT025・任意順位戦は非解禁。

## 検証とWindows実機受入

`tests/test_stage13e3g41_hiroshima_gui_return_navigation.py` ではTkinterウィンドウなしで、本物の`Stage13D3BrowseApp`のUIコールバックを模擬している。成功時の戻りボタン・元窓の再表示・閉じた窓の無効化・年度切り替え・検索0件と例外での条件復元・親ウィンドウのフォーカス・SQLite欠損・偽の学校ID拒否・新規窓二重作成禁止を検査する。

`data/research/2026/hiroshima_gui_stage13e3g41_acceptance_checklist.csv`は次を区別する：
- 自動確認（headless）：13項目。GUIコールバックおよび存在する実装に対する自動検査。
- **Windows実機受入未実施：10項目**。Stage36の6項目を保持し、学校戦績への移動、プレビューへの戻り、年度変更、SQLite欠損案内の4項目を追加。

Windows実機での実操作手順：
1. SQLiteに2026年の学校戦績がある状態で既存簡易GUIを起動し、年度が2026であることを確認。大会結果→試験プレビューを開く。
2. 史実2026秋季広島西部へ切り替え、学校別戦績から対象校を選び「既存SQLiteの学校戦績へ移動（2026年のみ）」を押す。正しい学校ID・戦績のみ表示されるか目視。
3. 通常GUI学校戦績タブの「予選進行プレビューへ戻る」を押す。**同じ別窓**が前面に戻り、表示済み試合数と検索条件が変化していないか確認。
4. 通常GUIの年度を2025へ変更し戻りボタン無効化を確認。再び2026に戻して、プレビューから改めて正常に遷移できることを確認。
5. SQLiteに対象校がないケースでプレビューから遷移すると、理由が提示され、別校へ移動せず、通常GUIの元の学校検索条件が維持されるか確認。
6. Tkの文字表示・WindowsのDPI、キーボードフォーカス、複数ウィンドウの前後関係、閉じたあと再表示、既存の成績タブの変化を点検する。

**上記の目視はこの段階のCIでは未実施**。手動確認が可能となるまでチェックリストの`windows_visual_status=not_run`を保持する。
