# Stage 43G-74：学校の保存試合を年度・大会別に索引検索するページAPI

作成日：2026-10-12

## 目的

Stage43G-73では、完全A方式の学校数、年数、試合数を増やしたときのSQLite物理容量・原本JSON・読み取り時間を実測した。

既存の `CareerLongitudinalReadModel.school_results` は学校の試合を「年度×大会」で集計して返す方式で、**指定年度範囲の該当するすべての試合JSONを読み、改ざん検査も実施**する。ページの途中・末尾であっても全件検証するという安全性がある反面、数十年分の全試合原本を毎回読むため、軽量な「過去試合を30件だけ見る」画面には過剰な処理となる。

そこで、**元の厳密な集計APIは変更せず**、ゲーム1試合単位で保存済みの試合一覧を読む専用APIを新設する。

## 新しい公開API

`CareerLongitudinalReadModel.school_game_page(school_id, start_year=..., end_year=..., competition_id=None, limit=30, offset=0, verify_scope="page")`

実装本体は `phase2_engine/career_indexed_school_game_page.py`。

- 既存の `historical_matches` から、`team1_id`と`team2_id`の**学校先頭・年度先頭インデックス**を使う2本の検索を `UNION ALL` して取り出す。試合の正規化契約で同一学校どうしの対戦は登録できないため、両方向検索で二重計数されない。
- 年度は昇順の閉区間で指定する。大会フィルタは保存された正式な `competition_id` と完全一致し、**ゲーム結果を大会順位に推定しない**。年10000以降の独立v2は対象外で、旧A方式の年度1〜9999のみを受け付ける。
- 件数の取得には保存JSON本文を読まないSQL `COUNT(*)` を各方向に使う。ページ取得は `ORDER BY year,competition_id,match_id LIMIT ? OFFSET ?` をSQLに押し込み、要求されたページにある試合のJSONだけを読む。
- 返すのは確定済みID、年月日、対戦相手、スコア、勝敗であり、存在しない打席イベントや大会順位・結果は生成しない。試合詳細のA方式原本は別の既存読取処理から取得する。
- `mode=ro`＋`query_only=ON`でSQLiteを開き、元セーブを作成・変更しない。ページの値はすべて保存済みSHA-256とSQL列・スコアの整合性を照合する。

## 重要：改ざん検証の範囲

- `verify_scope="page"`（規定値）：**表示ページの試合だけ**保存SHA・学校ID・年月日・大会ID・勝敗を検証する。表示していない昔の試合の改ざんを検出したとは言わない。
- `verify_scope="filtered_window"`：指定した学校・年度範囲・大会IDに一致する**すべての試合**をページ外も含めて検証。画面の内容に加え範囲全体の正しさを求める場合はこちらを指定する。この場合は原本JSON全件の走査コストが発生する。
- 他大会や指定範囲外の年度は `filtered_window` でも検証しない。過去の全記録が改ざんされていない証拠が必要なら、引き続き原本の年次SHA・ledgerと旧 `school_results` などの深度監査を使う。

従来の `school_results` から、改ざん検出のために全件読んでいた機能を**削除・緩和しない**。ページ専用APIでは検証範囲の違いを `all_filtered_window_checksums_verified` などの出力に明記する。

## テスト

- 実在校から生成した完全A形式の原本と、別途作成した**架空スコアのみ**のインデックス負荷fixtureの両方を使用。
- 同じ学校の2027〜2028年、同じ大会を2試合ずつページ取得し、合計試合数・offset・相手・スコア・勝敗を照合。
- 逆側の対戦校（`team2_id`）からの検索も確認。
- `EXPLAIN QUERY PLAN`で学校先頭索引がホーム側・アウェー側の両方に選ばれることを確認。
- 範囲外の改ざんはページ表示モードでは未検出として明示し、範囲全件検証と既存集計APIでは改ざん拒否が維持されることを確認。
- 大会フィルタの範囲外の改ざんは該当大会の厳密監査を壊さず、全大会監査では検出されることを確認。
- CIで**4校×100年度×4架空試合/校/年＝1,600試合のスコアのみ保存fixture**を作り、選択学校の大会200試合からoffset 170で30試合だけを表示、範囲全件のSHA照合とSQLite非書込を検証。
- Python全unittest、関東8都県17校E2E、およびStage43G-13/14の旧方式完全回帰の全成功を確認してからmainへ反映する。

## 対象外と次工程

このAPIは**旧A方式専用のheadless/read model**であり、まだTkinter試験画面にも正式なゲームGUIにも直接接続しない。v2のゲーム内日付や封印済み年度の横断閲覧には既存の別系統の検証を維持する。

年度・大会フィルタの正式GUI連携を進めるには、v2原本側に同等のページ限定読み取り契約を用意し、旧方式とv2の厳密な出典分離を維持した画面統合が必要。

このStageだけでは全国3,000校×100年を実際に大会進行させたわけではない。元A方式（試合スコア・イニング別得点・個人成績）を削らない。
