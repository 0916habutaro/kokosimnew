# Stage 43G-75：旧A方式の学校別試合検索をTkinter試験GUIに接続

作成日：2026-10-12

## 前提
- Stage43G-73（PR #215）：完全A方式の容量・索引性能の一軸拡大監査。
- Stage43G-74（PR #216）：学校ID、年度範囲（1〜9999）、大会ID、30件ページの旧A方式索引読取API。標準の `verify_scope=page` は表示ページのみのSHA整合性を検査し、`filtered_window` は指定範囲全体を検査する。
- 旧A方式は `historical_matches.sqlite3`、年10000以降の架空v2は `fictional_option_a_v2.sqlite3` に別々に保持する。

## 今回の実装
`career_history_tk_pilot.py` の保存年度→学校画面で、厳密に検証済みの旧A方式の学校画面を開いた場合のみ「旧A方式：学校の過去試合を検索」を有効化する。学校IDと初期年度は原本で検証済みの `bridge.page` から取得する。任意入力の校名をIDへ推定変換しない。

別ウィンドウ `CareerLegacySchoolGamesTkPilot` から以下の操作を行う。

1. 開始・終了年度（閉区間、1〜9999）を指定する。初期値は選択した保存済み学校の年度。
2. 大会IDの完全一致で絞り込む（空欄＝すべて）。大会順位・公式試合結果を推定しない。
3. 1ページ30件の試合を取得し「年度・日付・大会ID・試合ID・相手校ID・得点・勝敗」を表示する。前の30件／次の30件を切り替える。総件数はSQL COUNTを使用する。
4. `page`（表示ページだけSHA）と `filtered_window`（絞込対象全件SHA）を明示的に選べる。全件検査の範囲も選択した学校・年度・大会だけであり、**セーブ全体の検証済みを意味しない**。
5. 不正年度、範囲逆転、不正スコープ、SHA不一致時は、ページ・条件・ページ位置を更新しない。GUIにもエラーを表示し、最後に成功した表示だけを残す。

GUIに付随する `CareerLegacySchoolGamePager` はheadlessで試験できる。元の歴史閲覧の遷移に成功したとき、またはセーブを切り替えたとき、検索子ウィンドウを閉じ、別セーブに以前の選択が残らないようにする。

## 非変更・出典分離条件
- Stage43G-74をそのまま呼び出し、`mode=ro`＋`query_only=ON`、表示ページの保存SHA照合を継承する。
- 試合原本・イニング別得点・個人成績を削除・圧縮・書き換えない。
- `source=historical_matches_legacy_iso` ではない学校画面では検索ボタンを無効化する。年10000以上のv2試合を表示したり、ISO日付に変換したりしない。
- 本画面は試験Tkinterであり、正式なゲームGUIではない。50年・100年の全国大会実行を新規検証したものでもない。

## 検証計画
- 合成スコア保存fixture（4校×20年度×4試合/校/年）で、大会絞込、40件の30＋10ページ、境界と逆方向の索引検索を確認。
- ページ外のSHA改ざんは `page` で全件検証を主張しない。`filtered_window` で拒否する。
- 次ページ改ざん／不正フィルタでUIとheadlessページの条件が変わらないことを確認する。
- 既存セーブ由来のStage43G-65 fixtureで実Tk操作、v2画面でのボタン無効化、セーブ切替時の子ウィンドウ破棄、全SQLite SHA非変更を確認する。
- 専用CI `career-legacy-school-game-tk.yml`（Xvfb）と、Stage43G-63/65/74回帰、全Python unittest、関東17校E2EをPRのマージ条件とする。
