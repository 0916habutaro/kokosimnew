# Stage 13E-3G-33：FMT025明示試合グラフの逐次結果閲覧・途中状態JSON保存

調査・実装日：2026年10月10日

## 前提と目的

Stage31で一次・敗者復活・横断決定・明示的な再挑戦を含む試合DAGの**全試合一括リプレイ**を実装し、Stage32で入力JSON契約`fmt025-explicit-input-v1`を導入した。Stage33では、試合結果を一括で表示するのではなく、**各試合の結果を一つずつ確認する進行状態**を読み取り専用Sandboxとして実装する。

結果を新規シミュレーションする機能ではない。Stage32契約には、架空試験用であっても**全試合の勝者が入力済み**である。Stage33の「結果記録」は、その入力済み・検証済み結果を順に**公開する**処理である。2026広島秋西の史実も二次結果に基づくものなので、公式試合番号や個別矢印が確認できたことにはならない。

## 状態と公開ルール

`phase2_engine/hiroshima_fmt025_incremental_preview.py` の主要API：

- `start_read_only_preview(payload, data_dir=None)`：Stage32入力を必ず再審査し、未実施（進行待ち）で開始する。
- `inspect_read_only_preview(payload, checkpoint, data_dir=None)`：保存された結果を元入力・元グラフ・勝者一覧と再突合したうえで状態を返す。
- `record_preapproved_match_result(payload, checkpoint, match_id, recorded_winner_id, data_dir=None)`：当該試合の入力元すべてが既に確定したときだけ、**もともと入力済みだった勝者**を公開できる。新しい勝者・架空の進出先は作れない。
- `export_read_only_checkpoint(checkpoint)`：進行途中の試合ID・公開済み勝者と内容識別をJSON出力する。
- `restore_read_only_checkpoint(payload, json, data_dir=None)`：全履歴を先頭から検証し、試合の飛ばし記録、重複、勝者改ざん、ソース変更、余分なフィールド、偽の公式承認を拒否して復元する。

進行状態は次の3種類：

| 状態 | 意味 | 出場校と結果の扱い |
|---|---|---|
| `waiting` | 前の試合が未確定 | 後続試合の学校名・勝者を未公開 |
| `ready` | 必要な前試合が確定し、二校が決定 | 二校を表示するが勝者は非公開 |
| `completed` | 既存の結果を公開済み | 出場校・勝者・敗者を表示、代表権があれば確定済みへ加える |

同時進行可能な別々の一次試合は、依存関係を守る限り記録順を入れ替えられる。これによって、全大会の日付順の固定進行に限定されない。しかし対象試合より後の敗者復活戦を先に確定することはできない。

## 途中保存の信頼性

`PreviewCheckpoint` は、契約バージョン、Stage32入力のSHA-256、**内部の試合構造・既登録結果・依存関係を含む別のSHA-256**、結果記録の順番を持つ。この二重識別は、原本が変更されたあとに過去の途中状態を誤って引き継がないためのものであり、公式組み合わせの真正性を証明する電子署名ではない。

復元に際しては、JSONが適切な形式であるかだけでなく、元データから結果の正しさを**毎回再構築・検証**する。必要に応じて、外部の永続化機構（今後のSQLite等）がこのJSONを保存できる。Stage33自体はSQLiteレコードを作成せず、GUI・本番スケジューラには組み込まない。

## 実データと試験データ

`data/research/2026/hiroshima_fmt025_preview_expected_events_stage13e3g33.json` に架空4校の4段階を登録した。

1. 開始：一次P1・P2は`ready`、敗者戦R1は`waiting`。代表枠0/3。
2. P1の結果(A勝利)を公開：P2が`ready`、R1が`waiting`。代表A確定。
3. P2の結果(C勝利)を公開：R1は二校(B/D)が揃って`ready`。代表A/C確定。
4. R1の結果(B勝利)を公開：全試合`completed`、代表A/C/Bの3枠が確定。

実大会由来の監査は**2026秋季広島西部のみ**、初期18校・史実25試合・学校別32接続・予選通過7校を一試合ずつ公開し、途中保存→復帰と枠数保存をチェックする。これは既登録の二次結果の段階再生であって、公式2026の試合番号25件・進行矢印32件の個別証明ではない。
