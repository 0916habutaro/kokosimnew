## 実装範囲

新しい独立labの登録・8/32team plan・match入力・独立bracket oracle・隔離SQLite・readonly履歴Tkを追加。旧Stage100–107 API・338catalog・106CSV・製品save/writer/schemaを変更していない。33校660永久ID、32team640登録、合同10＋10選抜と未選抜20人保持、5ラウンド31枠のGate AはLinux補助4 tests/skip0で成功した。

ゲーム内ブラケットseed430108と固有試合seedによる架空大会。2026公式大会の組合せ・シード・個別日程・実選手・結果を再現したとは主張しない。20人登録と10＋10比率はゲーム用仮定。旧確率の部分利用・確定進塁・犠打/失策/盗塁等未対応、疲労/怪我未接続のStage105 labモデルを継続する。

## 実際のGate B/Cと完全A

Gate Bは合同を含む8team7試合を3ラウンド完走。親が同じTemporaryDirectoryを保持し、spawn子を0→1、1→4（初round終了）、4→7で終了させ、次の別プロセスが全旧内容を再検証して継続した。Gate BのSQL／全660人履歴照合成功をGate Cの前提として明示し、失敗時はGate Cを計算しない。

Gate Cは別の新規隔離DBで32team31試合、5ラウンドを完走。workerを0→1、1→16、16→31でそれぞれ終了し、親と異なるPID・exit code・各commit件数を確認。全試合で独立event再集計と同seed全内容再実行、独立bracket oracle、SQL/JSON/SHAと元学校・永久IDを照合した。完全Aのスコア／全イニング／team・投打成績を保持し、結果や勝者の書換えはない。

架空優勝は甲府第一（公式一覧の略称「甲府一」）5勝0敗、準優勝は日本航空4勝1敗。決勝は日本航空1–8甲府一。準決勝敗者は同3位、以下同5/9/17位で、未実行の順位決定戦による厳密1–32位を作らない。合同はGate C初roundに実出場し、元学校を維持した個人投打行を記録。合同のチーム勝敗を農林・塩山それぞれの単独勝敗へ加算しない。

全33校の参加teamと実試合、全660永久IDの各試合実出場行と全計数累計を照合。合同未登録20人とベンチへ架空出場を与えない。学校参加indexのSQL membership joinは63行。team表32行・membership33行・registered_players640行、結果31行・進出台帳31行・順位32行を保持した。

## 実測と受入

Linux 3.12.14補助測定。最終実装の専用gateは**19 tests / skip0、460.745秒、成功**。この時間は旧10版の独立checkout/exportと故障試験を含み、全unittest・関東E2Eとの並行負荷がある。全件検証を省くDBキャッシュは導入せず、同一request内の能力snapshotと結果SHA計算だけを共有した。最適化前後の7入力全内容もbit同値で照合した。

|項目|Gate B（8team）|Gate C（32team）|
|---|---:|---:|
|計算・commitした試合|7|31|
|spawn phase到達試合数|1 / 4 / 7|1 / 16 / 31|
|各phaseの秒（再開・検証・計算・保存・終了を含む）|2.926607 / 6.779222 / 7.462003|12.570198 / 95.624403 / 114.890271|
|完了DB bytes|2,056,192|5,115,904|
|完了検証read秒|—|1.166386|
|開始登録・初期検証秒|—|2.047123|

RO読取前後のDB bytes不変、保持したnative connection全件の実close、rename/reopenを確認。保存原子性は試合単位のみ。試合前・insert途中・commit直前・commit後応答前・round境界・exclusive lock・WAL/DELETE・同時同一追記・旧checkpoint・改ざん／未知indexを検証した。dirty spill後の強制終了ではhot journalをRO readerが修復せずbytes不変で拒否し、自己所有fixtureだけ明示recovery後に旧prefixを保持して再試行成功。

初期試験には、空のteam_ranks表へのDELETEがrow triggerを起動しないことを無視した試験前提と、plan tupleをlistと誤認した改ざんfixtureの2不備があった。全表に行のある完了fixtureでtriggerを試験し、改ざんfixtureを修正して19件を再実行・成功した。validatorやreaderの拒否条件は維持した。

真のStage94/99/100/101/102/103/104/105/106/107 mainの**10版**から独立プロセスで自己生成候補をexportし、現readerでRO内容verify・原本bytes不変を確認。338互換catalog入力と106CSVを含むdata集合bytes不変。真正性、現コードreplay、本番restore認可とは区別し、実ユーザーsaveは利用していない。

先行head `30471393382662c2127971df5859069de331bace`のWindows Python3.12 headlessも19 tests / skip0、481.273秒で成功（[run](https://github.com/0916habutaro/kokosimnew/actions/runs/38732382763)）。最終headでは再度Windows headlessとnative mapped Tk（32team scroll・履歴・未完了/破損/読取失敗時消去・未登録選手・close/rename/reopen）、全Python unittest、関東8都県17校E2E、Stage91–107を受入する。結果とWindowsのphase秒・DBサイズ・保存行数は最終headのCIログ／集計artifactとPR本文に記録する。前Stageの全unittest CIが約42分のため、件数を削らずtimeoutを45→60分とした。ローカル関東8都県17校E2Eは2 tests / skip0、867.199秒で成功。全unittestの最終結果もPR本文に記録する。個人Windows PCで人が触った目視手操作は未検証。

## 保護境界と残課題

原子性は単一SQLite内の試合transactionのみ。31試合全体やJSON/複数製品DBの同時原子性は保証しない。SHAは整合性確認で真正性署名ではない。親所有TemporaryDirectory終了後の製品長期保存は未対応。合同の勝敗/優勝を構成校の単独成績に複製しない。

既存save利用/変更、本番restore/import/activation、履歴削除/GC、製品writer/schema採用、2027実開始、全国一般化、正式全国GUI一括実装、EXE配布を行わない。ADR-037–041はProposed・製品未採用。旧候補生成の重複整理は別Stageでfixture独立性を確認してからとし、今回は既存保障を維持する。

最終head全必須CI成功後も未マージ・auto-merge無効でレビュー待ち。
