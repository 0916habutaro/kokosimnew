# Stage43G-109 個人Windowsでの手動確認手順

この手順はWindows runnerの自動Tk試験とは別の、人による個人PC確認用。**本資料の作成時点で個人Windowsのマウス操作・OSログインセッション跨ぎは未実施**。実施した人が日時・Windows/Python/Tk版・各項目の成否だけを記録する。実ユーザーsave・既存backup、原本SHA、秘密の絶対パスをGitHubへ添付しない。

## 準備・起動

1. WindowsでPython 3.12（公式installerのtcl/tkを含む）を用意し、PowerShellで `py -3.12 -m tkinter` を実行する。Tk画面が開くことを確認して閉じる。
2. このPRのcheckoutへ移動し、`py -3.12 -m phase2_engine.yamanashi_demo_tk` を実行する。EXE作成・依存パッケージの追加は不要。
3. 上端に「ゲーム内試験用山梨県夏季大会」「架空選手／架空組合せ／架空結果」が常時見えること、固定2026 seed・疲労等未実装の説明を確認する。

## 新規開始・保存・完全終了

4. 「専用保存先を新規作成」を押す。Git checkout・data・save・backupの外側の個人用フォルダーを親として選択し、**未存在**の新規名（例 `KokosimYamanashiDemo109`）を入力する。既存フォルダーは採用されない。同じ名で再作成すると安全エラーになることを別の新規試験先で確認する。
5. 「新規32チームデモ」を押し、永続保存の確認を承認する。demo IDを手元へ記録する。選択は32チーム、31試合の予定、33校660人を保持し、合同「山梨農林・塩山」の学校選択が2校あることを確認する。
6. チーム選択と学校・選手選択を操作する。合同の全40永久IDと登録枠、未登録20人が選べ、未登録者に「未登録」「実出場なし」と出ることを確認する。公式表示名は学校マスターとの対応表示であり、勝敗は架空である。
7. 「次の1試合」を押す。処理中表示・二重操作防止、完了後「1/31試合 自動保存済み」と次の対戦を確認する。該当チームの保存済み試合を選び、スコア・全イニング（Xを含む）・実出場の打撃/投手行と通算を見る。横・縦scrollも操作する。
8. 「このラウンドの残り」を押し、16試合まで進むことを確認する。保存は1試合ずつで、ラウンド一括ではない。
9. 「終了」または画面右上×を押す。未commit結果は未保存・commit済みのみ再開対象との確認文を見る。ウィンドウが消え、PowerShellのプロンプトが戻るまで待つ。タスクマネージャーでこのアプリのPythonプロセスが終了していることを確認する。他のPythonプロセスは終了させない。

## 翌日・別OSセッションの再開

10. 一度Windowsからサインアウト、または再起動する。後日でもよい。再ログイン後、同じcheckoutから手順2のコマンドを新しく実行する。
11. 「専用保存先を開く」で手順4の専用ルートを明示選択する（各demo子ディレクトリやSQLiteそのものは選ばない）。手順5のdemo IDを選び「続きから」を押す。全prefix再検証の処理中表示後、16試合の同じ記録と次のroundになることを確認する。
12. ラウンドを進め31試合完了を確認する。同1/2/3/5/9/17位であり、順位決定戦なしの厳密1～32位を作らない。合同チーム勝敗を構成校それぞれの学校単独成績へ複製していないこと、全660人の元学校ID・試合別/通算成績を再閲覧できることを確認する。
13. 再び終了・Python完全終了・再起動・明示再開し、31試合と同順位が変わらないことを確認する。「新規32チームデモ」は別IDを追加し、完了済みデモを初期化しないことを確認する。

## 中断・拒否（捨ててもよい自作の試験用デモだけ）

14. 別の新規デモで「次の1試合」の処理中に「終了」を押す。未commit結果の未保存表示、処理終了を待った画面終了を確認する。再開時にcommit済みの0または1件だけがあり、半端な結果がないことを確認する。応答直前にcommitした場合は1件残るのが正しい。
15. 同じ専用デモを2つのアプリで明示再開し、後から開いた側が使用中として拒否され、以前の成績画面を残さないことを確認する。先のアプリを通常終了すると新しいプロセスで再開できる。
16. アプリを閉じた後、捨ててもよい新規試験用demoの`demo.json`へ空白を追加する等、意図的にmarkerを壊す。同demoを選ぶと拒否され、スコア・選択欄・履歴が消え、自動修復しないことを確認する。**通常デモ・製品save・backupに行わない。**このStageに修復/削除/GCの操作はない。
17. プロセス強制終了・停電等でjournalが残ったデモは再開拒否される場合がある。journalを削除して再開する手順は提供しない。専用保存先に別IDの新規デモを作成する。実体コピー/移動は再開対象外である。

確認記録例: 実施日、Windows版、Python/Tk版、Gate A/B/C、完全プロセス終了、OSログイン跨ぎ、再開後件数、scroll/個人成績、拒否/画面消去、未確認項目。スクリーンショットを共有する場合は保存先絶対パス・ユーザー名等を除く。
