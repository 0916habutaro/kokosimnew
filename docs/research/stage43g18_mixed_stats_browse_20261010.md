# Stage 43G-18：封印キャッシュ＋進行年度A方式の安全な混合集計

作成日：2026-10-10。前提：Stage43G-17の読み取り専用キャッシュアダプタ。

## 目的
50年・100年単位の閲覧時に、ある1年が進行中またはキャッシュ未生成という理由だけで、全期間のA方式元試合を読み直す無駄を避ける。学校×年度について派生キャッシュが使える年度は検証済みキャッシュを使い、その他年度は元試合のSHAとロスターの正当性を検証して合算する。

## 実装構成
- `CareerStatsReadOnlyAdapter.coverage_plan`：学校・年度範囲を**一括2接続**で調べ、年度ごとに`cached=True/False`を返す。キャッシュ行があるのに原本がactiveまたは台帳SHA・件数が異なる場合、年範囲に未生成年度が混じってもエラーにする。
- `CareerStatsReadOnlyAdapter.verified_school_rows`：Stage43G-15の学校年度fact SHA・全行カバレッジ・各行SHAを検証した上で、校年度の選手全候補を返す。ランキングは途中のtop 20だけで集計しない。
- `CareerMixedStatReader`：連続した同一取得経路の年度をまとめ、個人成績は各年度の加算値から正しい通算打率・出塁率・長打率・OPS・防御率・WHIPを再算出。学校歴代記録は全候補の加算値から順位を算定。A方式に個人成績が保存されていない試合は欠損数として合算する。
- `CareerHistoryBrowseModel`：全年度cachedならStage43G-17の高速パス、全年度rawなら従来の検証パス、両方が混在するときだけ新しい混合集計へ。画面は`cached_year_count`/`raw_year_count`と`source_validation`を表示。
- `CareerHistoryGuiPilot`：試験画面のJSON詳細欄に、キャッシュ利用年度数と元試合からの集計年度数を表示。

## 不変条件
- GUIは元の`historical_matches.sqlite3`、`career_rosters.sqlite3`、`derived_player_stats.sqlite3`を一切更新しない。
- キャッシュ生成は別フロー。ゲーム画面から`materialize`しない。
- キャッシュ破損や台帳不一致はfail closed。特定年度のキャッシュ未生成自体は破損ではないため原本を使う。
- 高速化は**原本照合を省略してよいという意味ではない**。キャッシュ年度はStage43G-15の封印台帳・派生行SHA・校年度網羅性を毎回確認。ただし元試合payloadを逐次再検証するのはraw年度のみ。すべての試合SHA監査は別工程で実施。
- 個人成績はA方式に保存された数値だけを採用。投手勝敗、規定到達、卒業、トーナメント勝者を推測しない。
- 年度別キャッシュ欠損の診断機能はまだ未実装。年数無制限を保証する実機性能試験も未実施。

## テスト
`tests/test_stage43g18_mixed_history_reader.py`：
- 封印2026＋active2027の個人成績・歴代ランキングが全原本集計と一致する
- DB3ファイルを閲覧が変更しない
- 原本側のスコアのみ試合について未記録個人成績をゼロで埋めない
- 混在時にもキャッシュ行破損・台帳改変を拒否し画面位置を変えない
- 全年度キャッシュ生成済みなら高速経路へ戻る
- active年度の偽キャッシュ行を拒否する

GitHub ActionsのPython3.12 unittestと関東8都県17校E2Eを両方成功させてからmain反映。
