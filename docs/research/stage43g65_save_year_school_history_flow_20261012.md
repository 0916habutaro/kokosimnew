# Stage 43G-65：セーブ選択→年度→保存校→試合・選手履歴の閲覧経路

作成日：2026-10-12

## 目的

Stage43G-62〜64の読取専用履歴GUIでは、学校IDを入力すれば保存年度の試合・選手記録を閲覧できた。今回追加するのは、**保存済みセーブ→保存済み年度→その年度に実際に保存された学校ロスター候補→学校の試合・選手記録**という連続した閲覧経路。

正式ゲームGUIの技術仕様、試合進行エンジン、実在の大会結果や将来の架空年度の推定には接続しない。

## 技術設計

### 保存年度に対応する学校候補

新しい `CareerSavedSchoolCatalog.page(year, after_school_id=None, limit=30)` を追加する。

- 旧A方式、v2架空方式の保存年度は既存のread gateで検証する。封印ledger、原本ゲームSHA、年10000以降のv2カレンダー等の検証が済むまで学校名の画面表示は行わない。
- 候補校は **`career_school_rosters` に当該年度の保存ロスターが存在する学校に限定**。全国の全加盟校、試合だけがある学校、当該大会への実出場校をすべて網羅するとは主張しない。
- SQL `WHERE year=? AND school_id>? ORDER BY school_id LIMIT 31` で最大30校ずつ検索し、保存された `school_id` とロスターのSHA検証済み `school_name` を返す。
- 学校表示名の変更は、保存年度・固定学校IDの検証と独立させる。名前の一致から選手・学校を再識別しない。
- 最新の学校マスターにのみ存在する学校を、保存年度に試合をした学校だと推定しない。

### ヘッドレスな画面遷移

`CareerHistoryGuiBridge.open_year(year)` で、現在の保存年度一覧に表示された年度を選び、当該年度の学校候補画面へ進む。新しい画面種別は `history_school_catalog`。

`older_schools()` で学校IDをキーとする次の30校を表示し、`open_school(year, school_id)` は現在の学校候補ページに表示される年度・学校IDのみを許可する。

表示名ではなく固定IDで学校・試合・選手へ移動する。各画面への移動時は、現在の保存原本を再検証する。状態は、移動先を検証できてから確定し、失敗時はルートと戻り履歴を変更しない。

以前の **年度候補から学校IDを直接指定して開く操作**は引き続き有効とする。保存ロスターがないが試合結果だけがある学校は、この直接指定による閲覧の対象になりうる。学校候補一覧には出さない。

### Tkinter試験画面

- 年度一覧から学校ID入力なしで選択すると保存学校候補に移動する。
- 学校ID入力がある場合は以前どおり学校履歴へ直接移動する。
- 年度一覧で「選択年度の学校候補」ボタンを押すと、学校ID入力の有無にかかわらず保存校一覧へ進む。
- 学校候補一覧では「次の学校候補」ボタンで30校ずつ読み込み、学校名と保存学校IDを選択して学校履歴へ進む。
- 試合・選手・戻る・別セーブ選択にはStage43G-63/64の既存ロジックを再利用する。セーブが変われば候補年・候補校・戻り履歴は引き継がない。

## テスト

- 使い捨ての架空2026旧A方式、独立した年10000のv2試合、2つのセーブスロットを使用する。2026→10000まで試合を進めたという意味ではない。
- セーブ→年度→学校→試合→戻る→選手→戻るまで、ヘッドレスと本物のTkinter widgetsで確認する。
- 未表示学校ID／未表示年度／別のセーブのリンクを拒否し、失敗時の画面と戻り先が不変であることを検証する。
- 保存ロスターのハッシュ改ざん、v2の試合ハッシュ改ざんでは保存校候補の表示を拒否する。
- 37校の合成保存ロスターを用い、30校と残り7校の二ページに正しく分かれることを確認する。全国大会の37校出場や年次進行は実行しない。
- 各閲覧の前後でセーブSQLiteファイルのSHA-256が変化しないことを監査する。
- Stage43G-62～64回帰、Python全unittest、関東8都県17校E2Eをmain反映条件とする。

## 未解決・次工程

- 大会参加校のみが記録され、保存ロスターのない学校の候補検索は今回の一覧対象外。試合記録だけから学校IDを安全に索引化する場合は、封印済みレコードのIDおよび出典を保全する別索引を設ける。
- 実際の全国3000校規模で、50年・100年分のロスター・個人成績を持つセーブでの検索速度・保存容量の計測は、メタデータだけの負荷試験とは分けて実施する。
- 正式ゲームGUIのセーブ作成、学校能力表示、選手の生成・年度進行、本大会実行は別工程。履歴閲覧は常に読取専用とする。
