## 位置づけ

既存`phase2_engine/career_history_gui_pilot.py`は旧A方式の2026以降の試合とキャリアデータ用Tk閲覧試験画面である。この画面を大幅変更したり、2026 BrowseDBなどの史実プレビューを本編成績へ混入させないため、新旧年度は**別の試験ウィンドウ**として接続する。正式なゲームGUIの完成・全国年度進行を意味しない。

## 今回の実装

- `phase2_engine/career_cross_era_gui_pilot.py`
  - `CareerCrossEraScreenController`：Tkなしで画面状態・戻り履歴・選択年度・ページ番号を保持。すべての遷移先についてG-30/G-31/G-32のソース・保存済みIDを検証し、失敗時は移動前の画面を保持。
  - `CareerCrossEraGuiPilot`：封印済み年度の選択、学校の保存済み試合のページ送り、対戦相手校へのダブルクリック移動、保存済み年度ロスター選手への移動、選手の年度変更と元の学校へ戻るリンク。学校・選手IDを表示し、名称や行番号でIDを推測しない。
  - `available_sealed_years(slot_root)`：旧・v2双方の年度原本ヘッダーをSQLite読取専用で列挙し、実際に封印済みの年度だけ選択候補とする。空白の年度は作成しない。
- `phase2_engine/career_history_gui_pilot.py`
  - 既存の年度・学校・大会・試合・選手閲覧、キャッシュ診断は維持したまま、ツールバーに「新旧年度履歴」ボタンを設置。
  - 旧試験GUIで表示している学校IDか、入力欄の正式学校IDを採用。学校IDが未指定・学校マスターに存在しない・封印済み年度がない場合はGUIで明示して停止。
  - 新旧側は`tk.Toplevel`の別ウィンドウとして起動し、旧GUIのHistoryRouteと戻り履歴は変更しない。
  - 一回に選択する年度はG-32の制約どおり最大24年度。旧GUIから開く場合は直近の封印済み24年度を提示し、上限以前の履歴や欠損を補完したことにはしない。

## 独立起動（テスト専用）

```bash
python -m phase2_engine.career_cross_era_gui_pilot \
  --slot /path/to/SAVE_SLOT \
  --school-id SCH000001 \
  --years 2026,10000
```

- `--school-id`：保存済みの正式学校ID。実在学校の氏名表示名を入力するものではない。
- `--years`：封印済みで明示的に選択する年度を昇順・重複なしで最大24件。旧年度と10000年度v2の両方が実際にそのセーブに保存済みである必要がある。
- `--slot`：当該セーブの`historical_matches.sqlite3`、`fictional_option_a_v2.sqlite3`、`career_rosters.sqlite3`、必要な`fictional_v2_player_stat_cache.sqlite3`などが所在するディレクトリ。
- スタンドアロン画面はv2年度のみのセーブでも起動できる。旧年度がない場合、旧GUIを新規作成せず、この新画面から開く。

## データ保護・画面契約
- 戻る・年度変更・ダブルクリック・ページ移動は必ず検証を通ってから状態を更新。変更元データのSHAが不一致なら警告し、表示中の画面を維持する。
- 学校試合ページは最大30件。原本別の保存済みスコアと学校勝敗だけを表示。全試合の打席イベントは存在しない。
- 年度ロスターが保存されていない場合、選手へのリンクは作らない。選手IDは恒久IDのみ。
- 旧とv2は`YYYY-MM-DD`と`G10000:04-01`などの日付型を分離し、画面の詳細に参照元を明示。
- 年度2026と10000の間の記録が存在すると推定しない。選択年度間の未検証期間を詳細に表示。
- 旧・v2の個人成績をまたぐ通算成績は`combined_career_totals=None`。10000年度は合成試合であり、実ゲームが10000年まで進行した事実はない。
- GUI操作により、元試合SQLite、年間ロスター、架空カレンダー、個人成績キャッシュを作成・変更しない。

## テストと実画面の範囲

`tests/test_stage43g33_cross_era_gui_pilot.py`：
- 旧2026・架空v2 10000の合成保存データを使用し、学校→対戦校→戻る、学校→選手→年度切替→学校、日付形式維持を検証。
- 未登録年度・不正リンクを拒否してナビゲーション履歴を保持する。
- すべてのSQLiteについて閲覧前後のファイルSHAが同一であることを確認。
- v2のみのセーブで旧DBを生成しない。
- `DISPLAY`環境のあるTkでは`ttk.Treeview`で選手行選択→詳細→年度切替→戻るを実際のwidgetに対して実行し、既存Tk履歴pilotのボタンで新しい`Toplevel`を起動できることを確認。
- CIはUbuntuの`xvfb-run`を使い、表示サーバのないLinuxでも本物のTkウィンドウを生成してwidgetを検証する。Python全unittest・関東17校E2Eもマージ条件とする。
