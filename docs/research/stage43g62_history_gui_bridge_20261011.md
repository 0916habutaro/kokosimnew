# Stage 43G-62：正式ゲームGUIへ引き継ぐ履歴閲覧契約

作成日：2026-10-11

## 方針

正式ゲームGUIの画面全体をこの段階で決め打ちしない。保存済みのA方式履歴を、ゲーム進行エンジンから独立した**読取専用の画面遷移契約**として定義し、後続GUIでTkinter以外の実装に交換できるようにする。

Stage43G-60/61の旧A方式（西暦年1～9999／ISO）と独立v2方式（年10000以降／ゲーム日トークン）を利用するが、両方式の結果・年度・通算成績を合算したことにはしない。

## 新規API `CareerHistoryGuiBridge`

初期化：`CareerHistoryGuiBridge(slot_root, year_page_size=24)`

- `page`：現在の安全な画面契約。`screen`、元の読み取りモデル `data`、実行可能な閲覧操作 `actions`、`source_verified`、`history_read_only` とゲーム進行可否フラグを返す。
- `older_years()`：保存済みの年度ヘッダを主キーseekで古い方へ最大24年分表示。年度カタログは**候補ヘッダだけ**なので試合原本の検証済みを意味しない。
- `open_school(year, school_id)`：表示中の年度候補にある年度・固定学校IDを選択。既存 `CareerCrossEraYearCatalog.select_school()` が封印ledger・試合SHA・年月日形式を検証した上で学校画面へ進む。試合も学校年度ロスターも無い学校IDは拒否。
- `open_link(target)`：現在の検証済み画面から払い出された、試合・選手・相手校などのリンクのみ受付。別年度のリンクや改変されたIDは拒否。再検証できた場合だけ画面を切替える。
- `back()`：直前のルートの原本を再検証してから戻り、読み取りに失敗すれば現在画面を変更しない。遷移履歴は最大100件。
- `refresh()`：現在画面を原本から再読込し、失敗した場合の画面・ルートは不変。
- `advance_year()`：履歴画面からの年度進行は必ず拒否。年度進行の正式操作は未接続で、後日ゲームエンジン側の保存処理、進行準備条件、成功／失敗状態、トランザクション境界を明示して接続する。

## 画面構成

| 画面契約 | 取得元 | 必須表示要素 |
|---|---|---|
| `history_year_catalog` | 保存年度ヘッダ（候補のみ） | 年度、旧A／v2、候補未検証の注意、古い年度への移動 |
| `history_school` | 検証済み学校・年度 | 年度、学校ID、保存試合、戦績、選手リンク、出典 |
| `history_match` | 検証済みの年度＋大会ID＋試合ID | 点数、回別得点、保存済み個人成績、未記録の明示 |
| `history_player` | 保存年度の選手ID | 所属確認、当該年度個人成績、記録なしの区別 |
| 年度進行 | **未接続** | 履歴画面からの実行禁止。ゲーム進行本体の別契約が必要 |

- すべての画面は固定の学校ID／大会ID／試合ID／選手IDを保持する。表示名だけから学校・試合・選手を同一視しない。
- **年度一覧は未検証、学校以下は検証済み**を画面契約で区別。原本を改ざんした場合は不適切な値を表示せず、状態を維持してエラーにする。
- 元の保存データ・キャッシュは更新せず、試合への進出・優勝、公式結果を自動補完しない。
- 記録の長期保存は原則A方式（スコア、イニング別得点、個人成績）。打席別イベントは保存必須としない。

## 専用テスト

- 合成旧A方式2026年と独立v2方式年10000の2つの**封印済み原本**を使う。実際に7,974年を進行したセーブではない。
- 年度一覧→学校→試合→戻る→選手→戻る、年度カーソル境界、新旧日付形式、安定IDリンク、UIアクション制限、SQLite SHA不変を確認。
- 改変リンク、選択年度外の年、改ざんされたv2試合SHAを拒否し、失敗時に画面・戻り先が変わらないことを確認。
- 閲覧機能が勝手にSQLiteを作成せず、年度進行操作を受け付けないことを確認。
- Stage43G-60/61、31/32を回帰。Python全unittest・関東E2Eをマージ条件とする。
