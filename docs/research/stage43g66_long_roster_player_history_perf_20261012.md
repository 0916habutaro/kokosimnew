# Stage 43G-66：100年ロスターと全国規模インデックスを想定した選手履歴の読み取り最適化

作成日：2026-10-12

## 背景と対象

既存の `CareerRosterArchive.player_history(player_id)` は、1人の永久選手IDを検索する際、その選手の所属校の**全保存年度の学校ロスターを取得・JSONデコード**していた。100年、1000年と学校の保存年数が伸びると、卒業した選手の閲覧にも無関係な年のロスターを全件処理する。

一方、現在のゲームの高校選手は1～3学年に限定され、`entry_year = reference_year - academic_year + 1` の検証があり、同じ永久選手IDの在籍は最大3年度に限られる。

## 実装方針

### 選手履歴問い合わせの上限

`CareerRosterArchive.player_history` を次のように変更。

1. `career_player_identities` から永久選手IDで唯一の `school_id` と `entry_year` を取得し、元のidentity JSONとSHA-256が一致するか検証。
2. `career_school_rosters` の複合インデックス `(school_id, year)` を用い、`year BETWEEN entry_year AND entry_year + 2` の**最大3年度**に範囲を限定。
3. 取得した学校年度ロスターは従来の `_get` でSHA照合・学校ID・年度整合性・選手構造をチェック。固定選手IDと `entry_year` を再確認して本人の年度情報だけを返す。
4. 読み取りをSQLiteの `mode=ro` と `PRAGMA query_only=ON` に固定する。履歴閲覧で保存スロット内の書込・DB作成・補助キャッシュ生成をしない。

これにより**所属校が何年進行したかに対し、対象選手1人の学校ロスターJSON処理件数は原則3年分**に抑える。試合個人成績の長期集計と年度進行・大会実行はこの問い合わせには含まない。

### 読み取り専用の実測CLI

```bash
python -m phase2_engine.career_long_roster_player_probe \
  --rosters out/saves/EXAMPLE/career_rosters.sqlite3 \
  --player-id PLYxxxxxxxxxxxxxxxxxxxx --repeats 3
```

- 保存された学校年度ロスター件数、学校ID種類数、対象選手の所属年度、ルックアップ実測時間中央値、Python追跡メモリピークをJSON出力。
- `EXPLAIN QUERY PLAN` で `idx_career_rosters_school_year` 利用を確認する。
- 実行前後のSQLiteのSHA-256の不変を監査する。
- このCLIは任意の実セーブを開いて測定できるが、**ゲームの100年連続実行や全国3,000校の完全な試合再現を示すものではない**。

## 自動テスト

1. 実際の `PlayerRosterGenerator` と `CareerRosterArchive.advance_and_save` により、**1校について2026～2125年の100年度分の20人ロスター**を使い捨てDBへ生成する。最初の1年生選手IDが2026・2027・2028だけ返ることを確認する。試合シミュレーション・大会の進出は行わない。
2. 同じ実生成2026～2028ロスターに、**3,000個の合成学校ID×50年度＝150,000件のインデックス構造検証専用のメタデータ行**を追加する。これらの行は本物のロスターではなく、試合・選手データとして表示・集計・出力しない。SQLの範囲検索プランと、無関係な行の大量追加後も3年間の本人ロスターだけを閲覧することを検証する。
3. 1年・2年・3年生別の卒業までの所属年度、破損した永久選手identity SHA／対象年度のロスターSHAの拒否、無関係な卒業後の年度ロスターを参照しないことを監査する。
4. 閲覧前後の元SQLite SHA-256が不変、存在しない選手・保存ファイルを勝手に作成しないことを確認する。
5. Stage43Eの進級・卒業テスト、クロス年度閲覧・GUIブリッジの回帰、Python全unittest、関東E2Eをマージ条件とする。

## 注意事項・今後

- **実ロスター100年度は1校限定**。全国3000校×100年を実際に進行した結果ではない。150,000件の構造テストは合成インデックス専用であり、校名・試合・個人成績の完全性を確認したものではない。
- 個人成績の大規模な試合原本、学校通算集計、全校100年の実ゲームセーブ容量などは引き続き別の監査が必要。
- 全画面の履歴ナビゲーションに無条件で全校・全年度データを読み込ませない方針を継続する。ゲーム進行を行う正式GUIとは別契約で処理する。
