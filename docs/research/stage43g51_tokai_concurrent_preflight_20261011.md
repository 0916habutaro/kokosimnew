# Stage 43G-51：センバツと愛知・三重春季地区予選の同時進行に向けた事前凍結

作成日：2026-10-11

## 背景
Stage43G-50では同年センバツ32校・31試合の保存済みA方式記録から、愛知 `CMP000113`・三重 `CMP000115` の春季地区予選免除対象を特定できる。しかし2026基準のゲーム用投影日程は選抜3/19開始、両県の地区予選3/20開始で重なる。選抜全試合の完了を待ってから、3/20開始の地区予選に免除校を後から登録すると、既存の試合・セーブ・プレイヤー成績を遡及変更する危険がある。

## 採用した二段階契約

### 第1段階：年度最初の試合前に32校と地区参加校を凍結
`CareerTokaiConcurrentPreflight.freeze`：
- `CareerMultiPreviewCheckpointService` の2027年共通年度セーブに、32校完全な選抜エントリーと前年度封印ledgerがあることを要求。
- `CareerInvitationalManifestService` の既存の32校マニフェストを記録し、その内容・前年度ledger・同年度ゲームプランfingerprintと紐付ける。
- 愛知5地区はFMT010～FMT014の混成方式、三重3地区はFMT016。2026マスターの地域所属を参照し、出場校IDが正しい地区に存在し、地区別代表枠16/6/11/5/10＝48、8/10/7＝25を満たすことを照合。
- 凍結する地区予選入力から当年選抜の各県代表校を除外し、校の二重登録・他県混入を拒否。選抜に0校の県は**選抜32校全体が凍結済みのときだけ**地区予選免除0校として候補化。
- 凍結は年度のいかなる試合よりも前に限り、保存後に再作成・差し替えを拒否。
- 記録は `career_tokai_preflights/2027_aichi_mie.json`。元の手動セーブや主セーブ、過年度Aレジャーは変更しない。

### 第2段階：選抜が完了したら全31試合を保存DBと再照合
`CareerTokaiConcurrentPreflight.audit`：
- 凍結済みプランを再読込し、選抜32校マニフェスト、同年度・前年度セーブ識別情報、全地区所属を検証。
- 選抜未完了なら **`frozen_waiting_for_31_saved_senbatsu_games`** とし、暫定免除権を県大会の確定結果に昇格させない。
- 選抜全31試合がA方式SQLiteに保存され、全件SHA・対戦・勝敗・保存日で整合したとき、選抜参加校リストと初期凍結内容の一致を確認し **`source_games_confirm_frozen_preseason_selection`** と報告。
- 参照2026地区予選の開始日は3月20日であり、選抜の2027ゲーム用最終実試合日と重なる可能性がある。開始日後に当初の地区組み合わせを作り直すことは許可しない。

## 本Stageで未実装の事項
- 愛知FMT010～FMT014、三重FMT016の地区予選・県MAINを実際に生成し、同年センバツと同じ日付から並行に保存・進行すること。
- 地区予選の初期日程と当年選抜参加校の同日二重試合を割り当てないスケジューラ。
- 全4県8校を認証した後の春季東海地区MAIN7試合。

これらは**Stage43G-52以降**の実行エンジン接続で対応する。今の段階では、凍結証跡の作成・再読込・選抜結果の事後整合の監査までが可能。誤って `auto_prefectural_activation_enabled=True` とする処理は導入しない。

2026学校マスターは地区所属の参照資料であり、2027年の実在の参加校や正式大会結果を示すものではない。2027年の対戦・選手能力・日時はゲーム内仮想データ。

## テスト

```bash
python -m unittest discover -s tests -p 'test_stage43g51_tokai_concurrent_preflight.py' -v
```
