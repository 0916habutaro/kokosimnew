# Match Simulator v1 設計

作成日: 2026-10-07

## 目的

Stage 13C-1で固定したMatchSimulation contractを実際に完走する最小能力ベース試合エンジンを実装する。

Stage 13C-2の対象は「試合結果だけ」ではない。

```
PlayerAbility / TeamStrength
  -> plate appearance event
  -> base / out state
  -> inning progression
  -> MatchEvent
  -> Batter / Pitcher / TeamGameStats
  -> score / winner
```

を一貫して生成する。

## 正本

- 実装: `game_core/match_simulator.py`
- 調整値: `config/match/match_simulation_v1.json`
- event定義: `config/match/event_catalog_v1.json`
- stats契約: `config/match/game_stats_contract_v1.json`

アルゴリズムはPythonへ、確率・閾値・進塁係数はJSONへ置く。

## MatchSimulator

入力:

`MatchSimulationInput`

出力:

`MatchSimulationResult`

出力前に必ずStage 13C-1の `validate_match_simulation_result()` を通す。

したがって、得点だけ生成できても

- event runs
- batter runs / hits
- pitcher runs / hits allowed
- PA / BF

が一致しない試合は完成扱いにしない。

## 打順

`StartingLineup.batting_order` の1〜9番を出発点とし、試合中は
`TeamMatchState.player_at_order()` で現在の打者を取得する。進行番号だけを
イニングを跨いで引き継ぐ。控え投手への交代では前任投手の打順枠を継承し、
退場選手を後の打席に戻さない。代打・代走・守備交代のAI判断は行わない。

## 出場状態と本番試合の接続

この節の全国進行・A方式保存はDHなしの既存経路。DHの直接試合計算は次節を参照する。

`game_core/match_state.py` の `TeamMatchState` を、DHなしの打順・実配置・
出場状態の正本として `MatchSimulator.simulate()` で使用する。
本職の `primary_position` を実配置の代用にしない。

- `_game_staff()` の球数制限後の先発を確定してから開始配置を作る。
  控え投手が先発する場合は予定投手の打順枠へ入り、予定投手は未出場の控えへ戻す。
  すでに野手として先発する選手が投げる場合は、その選手と予定投手の守備位置を交換する。
  開始前の調整は交代・退場履歴に記録しない
- 大会登録は `TeamMatchInput.registered_player_ids`、当日の起用候補は
  `player_abilities` で区別する。登録集合の省略時は当日の候補を登録集合とする。
  大会側は負傷者を除く前の登録集合を渡す。従来の「健康な選手が9人に足りない場合は
  負傷者も使う」救済は維持するが、除外済みの選手を新たな登板経路から使わない
- 現在の投手は `current_pitcher_id`（Pの担当者）、守備は `defensive_alignment`、
  打者とタイブレークの自動配置走者は現在の打順枠から取得する。
  投手起用順のインデックスは交代判断の進行情報に限り、実際の選手IDの正本にはしない
- 投手起用順、スタミナ・対戦打者数・登板中の失点・球数による交代判断は維持する。
  交代決定後に `change_pitcher()` で配置と打順を一括更新する。
  控え投手は現投手を退場させてその枠を継承する。出場中の野手が登板する場合は
  現投手と位置を交換し、元投手は退場させず打順を保つ。
  既存の順序にない候補の追加や再登板判断はしない。投手能力のない野手には既存の暫定能力を使う
- DHなしでは9打順・9守備位置に異なる同じ9人を配置し、Pと登板投手を一致させる。
  登録外・当日起用不可・退場済みの選手を拒否する。変更は候補全体の検証後に
  一括確定し、失敗時に不完全な状態を残さない。投球可能者がいなければ試合を明確に拒否する
- 新出場者の打撃成績行を追加し、交代前の行も保持する。塁上走者のIDは打順枠と
  独立して維持する。責任投手・無失策イニング再構成は既存処理を通す。
  投球数と投手成績は現在の投手へ記録し、大会側はPA>0/BF>0/実守備出場の和集合を
  選手IDごとに重複なく出場経験・怪我処理へ渡す。未出場の控えや開始前に外れて
  実出場のない選手を除き、交代で退場した選手の出場も残す。成長の係数・上限は変更しない
- 守備値は既存の `TeamStrengthGenerator.defense_for_alignment()` の重み・適性・
  丸めを再利用する。開始配置が変わったときと、試合中の交代時だけ再計算する。
  交代しない打席で全選手の走査や状態の再構築を行わない

状態モデルは不変の公開コレクションを持つ。`change_positions()` / `swap_positions()` は
出場中の選手の位置を交換・循環し、打順を維持する。`substitute()` は控えを指定した
退場者の枠へ入れる。`change_pitcher(outgoing_player_id=...)` には別の野手を交代対象とし、
元投手を野手として残す操作もあるが、本番の判断では新しい戦術として使わない。
成功した変更だけを `LineupChange` に連番・種類・交代選手・打順枠・位置別の前後IDで保持する。

### 開始配置・交代履歴の保存

`MatchSimulationResult.team_participation` は両校の学校ID、開始配置、実際の先発ID、
成功した変更履歴、実際に守備へ出た選手IDを持つ。開始配置は打順順の9行
（`batting_order`・`player_id`・`defensive_position`）で、選考点や全登録名簿を重複保存しない。
球数制限後の配置を保存し、開始前の調整を途中交代へ混ぜない。

`LineupChange.sequence` はチーム内で1から連続する。学校ID・変更の種類・退場者・
新出場者・継承打順・位置ごとの変更前後IDに加え、`moment` に回・表裏・
`next_plate_appearance_no` を持つ。打席番号は**試合全体で1から数え、その打席の開始前に
変更を確定する**。守備位置だけの交換や出場中の野手登板は退場者・新出場者・継承枠を
nullとし、新しいPは位置別差分から確認する。失敗・無変更の操作は履歴を増やさない。
独立した状態操作では時点を省略できるが、試合結果として保存する履歴には必須。

開始配置と差分から既存の `TeamMatchState` 操作で最終打順・配置・退場者を復元する
（`replay_team_participation`）。最終9人のコピーを別途保存しない。本番では復元結果と
実行中の最終状態を照合し、打席の打者・投手も履歴を適用した状態と一致させる。
`state_sink` は同じ確定状態を返し、別の交代履歴を作らない。

既存の `inning_scores` へ各表裏の `plate_appearances` を加える。これにより、全打席を
保存せずに変更時点の打席番号と表裏の対応を保存・読込時に検証できる。
守備出場も、各表裏の開始と交代時点だけを再生して照合する。打順・9守備位置の一意性、
Pとの一致、再出場禁止、差分の連続性、連番・時点の順序を検証する。

`AbilityMatchResolver` は結果の同じ記録を詳細へ渡し、A方式の
`HistoricalMatchArchive._history_payload()` が明示的に保存する。圧縮・読込・年度封印も
既存経路を利用し、開始配置・交代履歴・位置別差分も列名を共有する既存の表形式で詰める。
読込は保存されたIDと配置差分だけで可能であり、現在の能力・本職・
現在名簿から再選考しない。50年・100年後の年度登録を経た読込も確認するが、
全国100年間の成長・試合シミュレーションを実施したことを意味しない。

投手交代の事実は配置履歴を正本にする。`game_highlights()` の要点の順序は保ち、
A方式の圧縮時だけ投手交代を `["P", チームの添字, チーム内変更連番]` の参照へ置き換える。
回・表裏・学校・新投手を二重保存せず、読込時に従来の5要素の要点へ復元する。
得点の要点と投手交代の並び・表示形式は維持する。

`fielding_player_ids` は実際の守備開始時・交代時に記録する。PA/BFが0でも守備に出た
選手を保存記録から区別できる。大会側の`_record_games()`はこれをPA/BFの出場IDへ加え、
月次成長用`games`と練習中の怪我用`season_games`を同じ1試合として加算する。
試合直後の怪我判定では両校の従来対象の後へ守備のみの選手を追加し、従来対象の乱数順を
維持する。守備のみの選手は投球数0の既存確率を使い、成長・怪我の係数は変更しない。

正式な試合詳細画面は保存済みの配置・差分を既存の復元操作で読み、先発9人・交代時点・
守備位置の変化を表示する。個人成績は交代前後の全行を残し、守備欄を実際に守備へ出た
位置の順（投→遊など）で示す。同じ打順枠や位置を交代選手が引き継ぐことを重複エラーに
しない。配置記録のない試合は「配置記録なし」とし、本職から補完しない。
画面表示のために現在の能力で再選考したり、保存結果を修復したりしない。
全打席の状態コピー・詳細イベントの追加保存・旧セーブ互換処理は追加しない。

## DHの直接試合計算

`TeamStrengthGenerator.generate()` / `select_starting_lineup()` の `dh_mode` は
`none`（既定）・`normal`・`pitcher`。DH方式では `starting_pitcher_id` で利用可能な先発を明示できる。
DHなしは従来の投手陣から選考し、球数制限後の開始配置へ接続する。
通常DHは守備9人に選ばれなかった選手の打撃合成を比較してDHを追加する。
投手兼DHの明示モードは本職投手の打撃合成・投手合成の低い側を比べて高い選手を優先する。
同点なら投手合成・打撃合成・ID順とし、打撃だけ・投球だけの選手へ偏らせない。
これは3方式を確実に再現する選考で、最終的な監督戦略や使用率を決定するものではない。
投手陣は能力順のまま保持し、DH申告の予定先発を試合の起用順の先頭へ置く。
打撃の学校値は打順9人、守備値は独立した守備9人から計算する。

球数制限で先発が変わった場合、確定した投手を固定して同じDH方式で開始配置を再選考する。
通常DHの実先発は打順から外れ、投手兼DHのDH IDは実先発IDと一致する。
登録・当日の起用可能者だけを使い、開始前の再選考を途中交代や退場として記録しない。

通常DHの継投は打順を保つ。投手兼DHは投手を退いても打撃を続ける。
緊急の野手登板でDHが残っている場合は、DHが空いた野手の位置へ入り、旧投手を退場させる。
DHが投手本人なら既存の位置交換を使う。いずれも `change_pitcher()` / `transition()` が
DH消滅・打順と守備の9人一致・役割再取得禁止を検証する。DH消滅後の控え投手は
現在の投手の打順を引き継ぐ。登板済み・完全退場・投手役を退いた兼任者を後の候補から除く。

`LineupAdjustment` は直接計算用の明示的な交代指示で、試合全体の次打席番号・学校ID・
打順変更・守備変更・医療例外を持つ。指定順に状態操作へ渡し、その後に通常の継投を判断する。
成功した交代だけを既存履歴へ記録し、未実施の打席への指示はエラーにする。
代打・代走・DH戦略のAIは追加しない。打順変更に伴う新打者の成績行だけを追加し、
守備専用投手のために架空の打者行を作らない。タイブレーク走者も交代後の実打順から取る。

### 規則通知の時点と照合

- `ChangeMoment` は従来どおり次打席開始前。DH試合では `order`（同じ打席境界で1から連続）も
  持ち、両校をまたぐ交代・相手先発交代通知の順序を保存する。DHなしの通常出力には追加しない。
- `CompletedPlateAppearanceMoment` は回・表裏・**完了した打席番号**を持つ。
  打席結果・得点・個人成績・イベントが確定した後、初回DH打撃の通知を出す。
  サヨナラ・コールド・最終打席でも実在する完了打席を指し、次打席へ繰り越さない。
- 自チームの先発を交代したとき、未完了義務のある相手チームだけに通知する。
  自チームの投手兼DHの打撃義務は解除しない（日本高野連2026年2月訂正）。
- `validate_match_participation()` はDH試合では全打席イベントを必要とし、打席前変更→実打者・
  実投手・守備出場→結果確定後通知の順で同じ状態操作を再生する。
  根拠のない/欠けた通知、通知先・時点の不一致、最終状態の不一致を拒否する。
  `validate_match_simulation_result()` は開始DH方式と入力を照合し、選手別PA/BF・安打内訳・
  打点・四死球・三振・犠打・投球数も実イベントと照合する。DH試合のイベントには実球数を含める。

### 本番保存との境界

結果と状態履歴はメモリ上および状態モデルのJSONで往復できるが、A方式へは接続しない。
`AbilityMatchResolver` はDH入力を試合実行前、DH結果を球数・経験・詳細の反映前に拒否する。
A方式の既存検証にもDH記録の拒否を置く。全国進行の生成引数は既定のDHなしのままで、
保存形式・圧縮・試合詳細画面は変更しない。次工程で保存・読込・画面・全国起用を接続する。

根拠：[日本高野連・公認野球規則5.11（2026年2月訂正後）](https://www.jhbf.or.jp/memberschool/regulation/dh/)。

## 投手運用

PitchingStaffのorderを使用する。

- ace
- second
- third
- depth...

の順で使用する。

交代判定は

- batters faced
- stamina
- runs allowed
- 次投手の有無

で行う。

v1では一度降板した投手の再登板はない。

## 打席eventモデル

通常のevent候補:

- strikeout
- walk
- hit_by_pitch
- single
- double
- triple
- home_run
- reached_on_error
- fielder_choice
- field_out

situational event:

- sacrifice_bunt
- sacrifice_fly

### 基本方針

base probabilityだけで抽選しない。

打者側:

- contact
- power
- plate_discipline
- strikeout_resistance
- speed
- baserunning
- bunt

投手側:

- stuff
- control
- strikeout
- groundball
- pitch repertoire quality

守備側:

- defense_strength

を使ってevent weightを変化させる。

TeamStrengthの総合値を「+n点」のように直接scoreへ加算しない。

## pitch repertoire

投手のpitch qualityは各球種qualityをusageで加重した値を使う。

球種ごとの打者相性はv1では扱わない。

## base state

塁は

`[first, second, third]`

としてrunnerのplayer_idを保持する。

runner identityを保持するため、得点時にBatterGameStats.runsへ正しいplayer_idを加算できる。

## 進塁

single / double / errorの追加進塁は

- runner baserunning
- runner speed
- opponent defense_strength

で確率変化させる。

triple / home runは決定的進塁。

walk / HBPはforceのみ。

fielder choiceはv1では1out＋lead runner除去の簡略モデル。

## sacrifice

### bunt

以下の場合のみ候補。

- 0または1out
- 一塁または二塁に走者
- 三塁走者なし
- 点差が設定範囲内
- batter.buntが最低値以上

### sacrifice fly

field_out候補から

- 三塁走者あり
- 2out未満

の場合に一定確率で変換する。

## inning / game end

通常9回。

- team1 = 表
- team2 = 裏
- 裏側リード時の9回裏省略
- 9回裏以降の勝ち越しでwalk-off
- 同点なら延長継続

大会固有の

- コールド
- タイブレーク
- 特別延長規則

はStage 13C-2 v1の共通モデルへ固定しない。

安全上 `hard_max_innings` を設け、そこまで同点ならエラーとして監査で検出する。

## RNG

1打席ごとに独立namespaceを使う。

event type抽選:

`plate_appearance_v1:{match_id}:{plate_appearance_no}`

進塁等:

`event_v1:{match_id}:{event_no}`

同じseed / match_idなら完全再現。

match_idが変われば同じチームでも別試合になる。

## pitcher earned runs

`_RunnerResponsibilityTracker` の走者責任情報から `runs_allowed` を責任投手へ
加算する。投手交代そのものでは責任を変えない。野手選択では9.16(g)に従い、
前任投手の走者をアウトにしても責任枠を残す。代替打者より前の走者が先に
得点する場合も前任投手の残した数を優先する。同時得点時は可能な限り現在の
対応を保ち、失策・タイブレーク由来の非自責情報も引き継ぐ。

`_EarnedRunTracker` は半イニングについて、チーム用と投手ごとの無失策の塁・
アウト・得点を別に再構成する。救援投手の再構成は登板時の実際の塁とアウト数
から始め、登板前の失策によるアウト機会を引き継がない（9.16(i)）。退いた投手の
再構成も回の終わりまで続け、交代後の失策によるアウト機会を反映する。
失策で押し出された走者などは、後続の安打で無失策でも得点できれば自責点へ
戻るため、`earned_runs` は半イニング終了時（サヨナラ・コールドを含む）に確定する。
打順が一巡しても走者を取り違えないよう、再構成では選手IDと出塁打席を合わせて使う。

タイブレーク配置走者・失策出塁走者とその非自責の代替走者は自責点に含めない。
各投手で `0 <= earned_runs <= runs_allowed`、投手別失点合計と相手得点を検証する。
チーム自責点と投手個人自責点合計の一致は要求しない。チーム自責点は内部検証用で、
現在の試合結果スキーマには追加しない。保存済みの試合結果は再計算しない。

交代判断の「失点」は従来どおり登板中に入った得点数を別に保持して参照する。
公式記録の責任帰属を直しても打席抽選・進塁乱数・打順・投手起用・試合イベント・
打撃成績・勝敗・得点板を変えない。保存形式と試合確率の設定も変更しない。

**現行イベントでの再構成の限界**：`reached_on_error` は打者のアウト機会を1つ
逃したものとして扱い、そのプレイによる進塁を無失策の塁へ加えない。安打では
無失策の走者が実際と同じ塁にいる場合に観測された進塁を使い、塁が異なる場合は
安打の種類による最小進塁を使う（疑いは投手に有利に扱う）。犠打時に仮想三塁に
残る走者は保留し、実際にないスクイズを仮定しない。
打者のアウト機会と走者のアウト逸失の区別、安打に付随する失策、捕逸、
ファウルフライ落球、併殺逸失、打席途中の継投などは現在のイベントに情報がない。
厳密に扱うには失策の対象・失策なしのアウトと進塁・ボールカウント等を追加する必要がある。
本処理がすべての実際の公式記録と一致するとは扱わない。
