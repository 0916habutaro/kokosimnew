# Stage 43G-80：独立v2学校索引をTkinter試験GUIで任意使用

作成日：2026-10-12

## 狙い
Stage43G-77で導入した旧A方式／架空v2の閲覧専用Tk画面を維持しながら、Stage43G-79で導入した**独立保存の派生学校索引**を任意で使用できるようにする。

## 画面と動作
- 従来の学校・年度履歴画面から検証済みv2学校を選択し、専用の学校別試合検索子画面を開く。
- v2検索に限り「検索方式（手動切替）」を表示。選択肢は`original_json1`（原本JSON走査）と`separate_index`（別SQLite学校索引）。初期値は常に**原本JSON1**。
- 独立索引のパスは、当該セーブ内の`fictional_v2_school_read_index.sqlite3`。指定パスに既存ファイルがない場合も自動作成しない。原本検索へ黙って切り替えることもしない。索引は別途明示的なStage43G-79 APIで検証・作成する。
- 検索方式の変更後、現在の学校・年度範囲・大会ID・`page`/`selected_years`検証スコープ・オフセットで保存された試合を再検索し、整合性を確認して初めて変更確定。
- 不正な索引（他セーブを参照、年度範囲外、破損、未封印、原本不一致）は拒否し、以前の検索方式・試合一覧・検索条件を残す。
- 旧A方式の画面には検索方式切替UIを置かない。旧Aと架空v2の保存出典を合算・日付変換・移行しない。
- 親画面の履歴遷移・セーブ切替が成功すると子画面を破棄。セーブBへセーブAの索引設定が持ち越されない。

## 出典とSHA検証
- `original_json1`: Stage43G-76 APIを直接呼び、指定期間の封印・カレンダー・ledgerを確認し、表示中の試合原本SHAを確認。
- `separate_index`: Stage43G-79 APIを呼び、索引の元の原本パス／年度／封印・ledgerを確認し、**表示中の各試合は原本の主キーを再取得し原本SHA・学校IDを検証**。
- `page`モードでは、表示外の索引行・原本が未改変と断定しない。`selected_years`モードでは指定範囲の保存済み全原本SHA・独立索引全行を検査する。この方式では厳密監査処理が重くなることがある。
- 検索結果の出典表示は「原本JSON1」／「独立SQLite学校索引」を常に区別する。v2論理日付`G{year}:MM-DD`を維持。元SQLiteは`mode=ro`+`query_only=ON`で読み取り、索引の作成・書換は画面操作から行わない。

## テストと対象範囲
- 新規単体テスト：索引なしでの切替拒否、明示的作成後の原本との表示一致、SHA不変、別原本参照索引・年度範囲外索引の拒否と操作の原子性。
- 新規実Tkテスト：切替UI表示／エラーからの復帰、事前生成した索引の選択と原本検索への復帰、厳密SHA、セーブ切替での破棄、旧A画面に索引切替がないこと。
- Stage43G-77のTk回帰、Stage43G-79の索引検証を専用CIで実行。
- 本工程は**Tkinter試験GUI**のみ。正式なゲーム用GUI・実大会進行・全国3000校／100年度の性能保証を含まない。
