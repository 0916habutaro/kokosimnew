# Stage 43G-63：保存履歴の日本語表示投影・Tkinter試験GUI接続

作成日：2026-10-12

## 目的

Stage43G-62で策定した「年度候補 → 学校年度 → 試合／選手 → 戻る」という読み取り専用ナビゲーション契約を、表示データ整形レイヤとTkinterの実イベントへ接続する。最終的な正式ゲームGUIはまだ作成しない。**保存記録を眺める**というゲーム目的を優先し、進行エンジンや選手生成等の書き込み側と分離する。

## 構成

| 層 | 実装 | 責務 |
|---|---|---|
| 保存データ | legacy `historical_matches.sqlite3` ／独立v2 `fictional_option_a_v2.sqlite3` | 元のゲーム記録とSHA・封印ledger |
| 検証モデル | `CareerCrossEraYearCatalog`、`CareerCrossEraNavigator` | 年度候補・年度ごとの試合／選手IDの原本検証 |
| ナビゲーション | `CareerHistoryGuiBridge` | IDによる画面遷移、戻る、エラー時の非破壊、進行操作の拒否 |
| 表示投影 | `project_history_screen` | 安全な画面応答を日本語の行・見出し・詳細に変換 |
| 試験GUI | `CareerHistoryTkPilot` | TkのTreeview、ダブルクリック・Enter・戻るボタン・詳細ペイン |

## 閲覧画面

- **年度一覧**：旧A方式／v2形式を日本語で区別し、「封印済み年度ヘッダ候補・試合未検証」と表示。年10000以降を実際の公式大会が開催されたとみなさない。
- **学校年度**：保存された年度、学校ID、試合ID・大会ID、保存スコア、日付、選手IDを一覧化。学校IDの指定は明示入力のみで、名前から推測しない。
- **試合詳細**：大会／試合ID、得点、イニング別得点、チーム成績、打撃成績、投手成績を、**保存済み全フィールドのJSON**として下段の読取専用テキストへ展開可能。欠落項目は「保存記録なし」と明示し、打席イベントは補完しない。
- **選手記録**：当該年度の保存選手IDと原本個人成績を表示。未記録・未所属・長期間の成績合算を推測しない。
- **操作**：年度の古い候補へ、学校記録を開く、ダブルクリック／Enter、戻る、再読込。表示済み画面で払い出されていないリンク、ID改変、選択年度外の暗黙遷移は下層で拒否。
- **エラー**：原本SHA破損・不明な学校IDのとき、Tkの現在の表示とナビゲーション状態を保持したままエラーを表示する。
- **禁止**：履歴閲覧画面には「年度を進める」「試合を実行する」「記録を変更する」操作を設けない。

## 単独起動

```bash
python -m phase2_engine.career_history_tk_pilot \
  --slot out/saves/EXAMPLE --school-id SCH000001
```

これはGUI動作確認用。正式なゲーム画面・セーブ選択機能・全国大会進行機能は未搭載。画面に表示されるのは選択セーブの原本から検証できる架空ゲームの履歴だけ。

## 検証

- 旧A方式2026年とv2架空10000年を**別々に作成した使い捨ての原本**で、年度選択→学校→試合詳細→戻る→選手→戻るを確認。
- Xvfb上で実際のTk widgetsを作り、Treeview選択・ボタンのコールバック・表示・詳細ペインをテストする。
- v2の保存試合SHAをテストデータ上で変更した場合、新しい画面へ遷移できず現在画面が維持され、SQLite自体は閲覧により変更されない。
- 旧AのISO日付とv2ゲーム内トークンの形式を明示的に区別する。
- 専用CI、Stage43G-60〜62回帰、Python全unittestと関東E2Eをマージ条件とする。

## 次工程

正式画面を固定する前に、複数セーブの選択からこの読取専用GUIへ接続するルート、学校表示名の保存年度スナップショット優先、長期大量個人成績の読み取りスケールをさらに整備する。これらは進行エンジンの成熟と独立して改善可能。
