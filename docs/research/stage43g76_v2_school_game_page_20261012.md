# Stage43G-76：封印済みv2学校試合の検索ページread model

作成日：2026-10-12

## 前段・対象
- Stage43G-74：旧A方式の学校ID先頭索引を使う30件ページ検索（1〜9999年度）。
- Stage43G-75：旧A方式のTkinter試験GUIの年度・大会絞り込み。
- 本Stageでは**年10000以降の独立架空v2保存原本**を対象にする。v2は実際の全国大会を10000年度まで進めた実測ではなく、明示的な架空カレンダーで封印した試合原本。
- 既存の旧A方式 `historical_matches.sqlite3` と独立v2 `fictional_option_a_v2.sqlite3`、架空カレンダー `sandbox_calendar_v2.sqlite3` はマージ・移行・書換しない。

## 重要：旧方式とv2の構造差
旧A方式のSQLiteは`team1_id`/`team2_id`列と学校先頭索引がある。一方、v2の`v2_option_a_matches`は**学校IDをJSON原本内にだけ保存**する。既存の封印済み原本の表構造・索引を遡及変更しないため、学校フィルタはSQLite JSON1の `json_extract` による**年度範囲内のJSON走査**を行う。

従ってSQL `LIMIT/OFFSET` によりPythonで復号・SHA検証する試合はページ分に限定できるが、**旧A方式と同等の学校先頭索引性能ではない**。SQLの `COUNT(*)` も対象年度範囲のJSON照会コストを要する。大規模実セーブへの性能保証を主張しない。ゲーム年の指定範囲は最大100年度（10000〜10099など）とし、それ以上は別区間を検索する。

## 公開API
`CareerV2OptionAArchive.school_game_page(school_id, start_year=..., end_year=..., competition_id=None, limit=30, offset=0, verify_scope="page")`

- 有効年度：10000以上で昇順の閉区間、最大100年度。
- 学校IDは保存済みの正確な識別子、大会IDは完全一致（空文字は不正）。
- 並び順は「年度→論理日付→大会ID→試合ID」。
- 返却値は保存済み年度、ゲーム内日付 `G{year}:MM-DD`、大会・試合・相手校ID、スコア、学校側勝敗。ISO日付・公式大会順位へ推測変換しない。
- 日付を含む元のイニング別得点・個人成績等A方式原本は維持。
- 読み取りはSQLite `mode=ro`＋`query_only=ON`。指定範囲内の保存年度について封印状態、架空カレンダー内容SHA、試合数・ledger SHAを検証。既存セーブには書き込まない。

## 整合性検証スコープ
`verify_scope="page"`（規定値）：
- SQL範囲の候補JSONを調べて件数を数えるが、SHA・日付・得点・勝敗の厳密な原本検証は**表示中の試合のみ**実施。
- 保存されている指定年度の封印ヘッダ、カレンダーとledger（保存行の記録SHAによる帳簿）は検証する。
- 表示されない試合のJSON改ざん、試合所属校を書き換えて検索条件から脱落させた改ざんまでは検出済みと主張しない。

`verify_scope="selected_years"`：
- 学校IDが独立した索引列にないため、**指定した期間に保存済みの全学校・全大会のv2試合原本**について内容SHA・カレンダー・勝敗整合を検証したあと、指定学校・大会でページ取得する。
- 条件外の学校へすり替わって絞り込み結果から消える改ざんも検出できる。処理負荷は期間内の全原本に比例する。
- 選択期間外や未保存年度は検証していない。未保存年度に試合があったと推測しない。
